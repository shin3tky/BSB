# 5. 配列、文字列、JSON

この章では、複数の値をまとめて扱う配列、文字列、外部から受け取る JSON の基本を学びます。

## 不変の配列

```text
色は 定数 【「赤」、「青」、「緑」】。
```

配列の要素は同じ型でなければなりません。添字は0から始まり、範囲指定は開始を含み終了を含まない
半開区間です。

```text
色 と 0 を 配列から取り出す          # 「赤」
色 と 0 と 2 を 配列の一部を取り出す # 【「赤」、「青」】
色 を 配列の長さ                    # 3
```

配列は不変で、作成後に中身を変更できません。`配列の要素を置き換える` や `配列の末尾へ追加する` は元の配列を変更せず、新しい配列を
返します。空の配列は要素から型を決められないため、`空の整数配列` のような型ごとの組み込み単語で作ります。

## Unicode 文字列

```text
「  BSBで日本語プログラミング  」 を 前後の空白を除く
「赤,青,緑」 と 「,」 を 文字列を分割する
「Hello, World!」 と 「World」 と 「BSB」 を 文字列を置き換える
```

`文字列の長さ` や、文字列の一部を取り出す単語は、人が1文字と感じる単位（拡張書記素クラスタ）で数えます。Unicode の
コードポイント単位で処理したい場合は、名前に `コードポイント` を含む単語を明示的に使います。

正規表現は `正規表現「…」` と書き、完全一致、部分一致、名前付きグループの取出し、置換、分割に使えます。

## JSON は文字列から解析する

BSB のソースへ JSON リテラルを直接書く構文はありません。文字列を解析します。

```text
注文は 変数 JSONヌル。

メインとは （--）
    「{"orderId":"A-100","quantity":2}」 を JSONを解析する
    を 注文 に 入れる
    注文 と 「orderId」 を JSONオブジェクトから必須値を取り出す
    JSONから文字列を取り出す
    一行表示する
こと。
```

`JSONを解析する` は、入力が不正な JSON だと診断を出して実行を終了します。内容が正しいと分かっている入力に使います。
外部から受け取った JSON のように、不正な場合も処理を続けたいときは、`JSONを解析して結果を返す`（後述の `結果` を返す単語）を使います。

## JSON の構造をまとめて検証する

外部から受け取った JSON の必須キーや値の種類をまとめて確かめるには、`JSON形状` を組み立てます。次の例では、
`orderId` を必須の文字列、`note` を省略可能で null も許す文字列として検証します。

```text
注文
空のJSONオブジェクト形状
「orderId」 と JSON文字列の形状
JSON形状に必須キーを設定する
「note」 と JSON文字列の形状
JSON形状をヌル許容にする
JSON形状に任意キーを設定する
JSONの形状を検証する
```

`JSONの形状を検証する` の戻り値は `結果<JSON,配列<JSON形状失敗>>` です。失敗側の配列は、形状にキーを設定した順に
並びます。各要素からは、専用の取出し単語で失敗の種類、JSON Pointer 形式のパス、期待した種類、実際の種類を
取得できます。形状に設定していないキーが入力にあっても、失敗にはなりません。

## 入れ子の JSON を参照し、オブジェクトをまとめて作る

決まった位置にある入れ子の値を取り出すときは、RFC 6901 の JSON Pointer（`/response/items/0/id` のような
経路文字列）を使えます。指定した位置に値がなくても実行は終了せず、結果は `任意<JSON>` の値なしになります。
値が JSON の null の場合は、値なしではなく、null を持つ値ありになります。

```text
応答 と 「/response/items/0/id」 を JSONをポインターで任意参照する
```

キーの配列と値の配列がすでにある場合は、`JSONオブジェクトを構築する` で JSON オブジェクトを一度に作れます。
2つの配列の要素は、同じ位置どうしがキーと値として対応します。

```text
【「model」、「stream」】 と
【「gpt-example」 を 文字列をJSONに変換する、いいえ を 真偽をJSONに変換する】 を
JSONオブジェクトを構築する
```

この例は `{"model":"gpt-example","stream":false}` という JSON オブジェクトを作ります。

## 値がない可能性は `任意`

オブジェクトのキーがないことを許したい場合は `JSONオブジェクトから任意値を取り出す` を使います。
結果は `任意<JSON>` です。

```text
設定 と 「mode」 を JSONオブジェクトから任意値を取り出す
任意に値がある ならば
    任意から値を取り出す
    JSONを文字列に変換する
    一行表示する
さもなければ
    任意を捨てる
    「未設定」 を 一行表示する
つぎに
```

`任意に値がある` は、分岐の後でも元の値を使えるように、`任意` をスタックに残したまま `真偽` を積みます。
そのため、値なし側でも `任意を捨てる` で `任意` を取り除く必要があります。

## 失敗する可能性は `結果`

`結果<T,E>` は成功値 `T` または失敗値 `E` のどちらかを持ちます。`結果が成功である` で判定し
（`任意に値がある` と同様に `結果` はスタックに残ります）、成功側は `結果から成功値を取り出す`、失敗側は `結果から失敗値を取り出す` で中身を得ます。

`JSONを解析して結果を返す` のほか、UTF-8・Base64 の復号、HTTPS 通信、ファイル操作、CSV/TSV の解析を行う単語は
`結果` を返します。CSV/TSV への変換は失敗値を返さず、文字列を直接返します。入力の誤りなどは分岐で処理できますが、
資源の上限超過や、必要な機能を実行環境が提供していない場合は、診断を出して実行を終了します。

## 試してみよう

文字列の配列を作り、`各要素について` で1行ずつ表示してみましょう。次に、空の JSON オブジェクトへ
`name` キーを設定し、JSON 文字列として表示してみましょう。

<summary>回答例</summary>

```text
メインとは （--）
    【「赤」、「青」、「緑」】 を 各要素について
        一行表示する
    繰り返す

    空のJSONオブジェクト
    と 「name」
    と 「BSB」 を 文字列をJSONに変換する
    JSONオブジェクトに設定する
    JSONを文字列に変換する
    一行表示する
こと。
```

実行結果は次のとおりです。

```text
赤
青
緑
{"name":"BSB"}
```

配列ループでは、各反復の入口に現在の文字列が1個積まれ、`一行表示する` がそれを消費します。
JSON の設定操作は元の空オブジェクトを変更せず、`name` を持つ新しい JSON オブジェクトを返します。
