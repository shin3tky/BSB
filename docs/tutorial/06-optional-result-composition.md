# 6. 任意・結果を合成する

前章では、`任意<T>`と`結果<T,E>`を判定してから中身を取り出しました。利用者定義単語が同じ種類の
ラッパーを返す場合は、値なし・失敗の分岐を局所伝播で短く書けます。この章では局所伝播と、ラッパーを
要素に持つ配列を使います。

## 値なしなら現在の単語から戻る

次の単語はJSONオブジェクトから任意の`id`を読みます。

```text
IDを読むとは （JSON -- 任意<整数>）
    「id」 を JSONオブジェクトから任意値を取り出す
    任意から値を取り出すか戻る
    JSONから整数を取り出す
    任意にする
こと。
```

`任意から値を取り出すか戻る`は、値があれば中身の`JSON`を積んで次へ進みます。値がなければ、残りの
処理を実行せず、現在の`IDを読む`から値なしの`任意<整数>`を返します。この構文は例外を捕捉するものではなく、
`任意`の値なしだけを明示的に伝播します。

通常経路では最後に`任意にする`が必要です。取り出した`整数`をそのまま残すと、宣言した出力
`任意<整数>`と一致しません。

## 失敗なら現在の単語から戻る

`結果`にも対応する局所伝播があります。

```text
数を増やすとは （文字列 結果<整数,文字列> -- 文字列 結果<整数,文字列>）
    結果から成功値を取り出すか戻る
    1 足す
    成功にする<整数,文字列>
こと。
```

成功時は`整数`を取り出して処理を続け、失敗時は元の失敗ペイロードを変えずに現在の単語から戻ります。
この例では、ラッパーより下にある`文字列`もそのまま保持します。この保持部分をprefixと呼びます。

局所伝播には次の制約があります。

- 利用者定義単語の本体だけで使える。`メイン`、宣言の初期値、配列要素式では使えない
- `任意`の伝播先は、宣言出力の末尾が`任意<U>`でなければならない
- `結果`の伝播先は、宣言出力の末尾が`結果<U,E>`で、失敗型`E`が同じでなければならない
- ラッパーより下のprefixは、個数、順序、型が宣言出力と完全に一致しなければならない

つまり、局所伝播は現在の単語のスタック効果で明示された範囲だけに作用します。別の失敗型への変換や
ログ出力が必要なら、従来どおり判定語と条件分岐を使います。

## 任意・結果を配列へ入れる

同じ具体型の`任意`または`結果`は配列要素にできます。

```text
【1 を 任意にする、2 を 任意にする】
【41 を 成功にする<整数,文字列>、「失敗」を 失敗にする<整数,文字列>】
```

それぞれの型は`配列<任意<整数>>`と`配列<結果<整数,文字列>>`です。成功と失敗が混在しても、両方が
同じ`結果<整数,文字列>`なら1つの配列にできます。型引数が違う要素は混在できません。

配列の入れ子上限は、`任意`・`結果`の内側も含め、型全体に現れる`配列`型構築子を数えます。

- `配列<任意<配列<整数>>>`は配列型構築子が2個なので利用できる
- `配列<任意<配列<配列<整数>>>>`は3個なので利用できない

表示と`等しい`も型引数へ推移します。中身を表示・比較できる`任意`・`結果`の配列は表示・比較できますが、
直接表示できない型を包んでも制限は消えません。

## 試してみよう

`JSONを解析して結果を返す`を使い、成功したJSONをもう一度文字列にする単語を作ってみましょう。失敗は
`結果から成功値を取り出すか戻る`で伝播し、単語の出力を`結果<文字列,JSON解析失敗>`にします。

<details>
<summary>回答例</summary>

```text
JSONを正規化するとは （文字列 -- 結果<文字列,JSON解析失敗>）
    JSONを解析して結果を返す
    結果から成功値を取り出すか戻る
    JSONを文字列に変換する
    成功にする<文字列,JSON解析失敗>
こと。

メインとは （--）
    「{\"answer\":42}」 を JSONを正規化する
    結果が成功である 一行表示する 結果を捨てる
    「{」 を JSONを正規化する
    結果が成功である 一行表示する 結果を捨てる
こと。
```

1回目は`はい`、2回目は`いいえ`を表示します。`JSON解析失敗`は直接表示できないため、結果値は判定後に
捨てています。詳細を扱う場合は、失敗側で`JSON解析失敗`の専用取出し語を使います。

</details>
