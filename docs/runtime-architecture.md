# 実行基盤の構成

## 実行方式

BSB の処理系は JVM 上で動作する Java 製インタープリタです。`.bsb` ソースを JVM バイトコードへ
直接変換するのではなく、静的検査を終えた構文木から処理系内部の IR を生成し、その IR を解釈します。

実装言語は Java、最小実行環境は JDK 25 です。IR は永続化形式や互換性を公開しない内部表現です。
ビルド、テスト、配布、資源制限、CLI の詳細は[実装・配布ガイド](implementation-guide.md)に定めます。

## 処理の流れ

```text
UTF-8 ソース
  ↓
Unicode 検査と字句の正規化
  ↓
字句解析
  ↓
構文解析（助詞とソース位置を保持）
  ↓
名前・型・スタック効果・助詞配置の検査
  ↓
実行用 IR
  ↓
JVM 上のインタープリタ
```

検査に失敗したプログラムから IR は生成しません。構文木と実行の間に境界を置くことで、静的検査、
通常実行、トレース、説明生成が同じ解析結果を共有します。

助詞はトークンと構文木に保持し、配置検査、整形、診断、ソース説明に使います。実行用 IR には助詞の
空操作命令を生成せず、ソース位置と関連する呼び出しを非実行メタデータとして残します。

## 主な構成要素

- `frontend`: Unicode 検査、正規化、字句解析、構文解析
- `analyzer`: 名前解決、型検査、スタック効果検査、能力と副作用の解析
- `binding`: 単語・定数・変数の名前空間、字句スコープ、束縛 ID
- `format`: 構文に基づく標準形への整形
- `explain`: 呼び出し関係、到達性、能力、副作用、束縛の説明モデル
- `ir`: 処理系内部の命令とソースマップ
- `runtime`: 値、スタック、実行ループ、資源予算、ホスト能力
- `stdlib`: 組み込み単語の辞書、型、公開メタデータ
- `numeric`: 正確な整数・小数値と表示
- `regex`: 正規表現の検査、コンパイル、実行制限
- `json`: JSON の不変値、非再帰解析、決定的直列化
- `diagnostics`: 人間向け診断と JSON 診断の共通モデル
- `cli`: コマンド解析、公開 DTO、決定的な出力

論理接続、バイト列、HTTPS、作業領域、ファイル、CSV/TSV は、解析器、実行環境、組み込み辞書を横断する
機能として構成します。公開上の分類は[機能グループ](conformance.md)に従います。

## 値と実行

整数は `BigInteger`、小数は `BigDecimal` を基礎として正確に保持します。BSB の数値を `double` へ
暗黙変換しません。丸め方法は BSB の値として明示し、Java の `RoundingMode` へ対応付けます。

配列、JSON、任意値、結果値、バイト列、HTTP 要求・応答、日時は不変値です。更新操作は元の値を
変更せず、新しい値を返します。配列は一次元と二次元で同じ値モデルを共有し、二次元値では論理葉数も
資源予算として検査します。

再帰実行に Java メソッドの再帰は使いません。インタープリタ自身が呼出スタックと命令位置を管理し、
BSB の資源上限として検査します。

## ホスト能力の境界

実行器は Java の `System`、既定ロケール、既定タイムゾーン、OS ファイル、ネットワークへ直接依存せず、
差し替え可能な実行環境から能力を受け取ります。この境界により、実 I/O や実時間を使わず適合性テストを
再現できます。

- stdin、stdout、stderr、終了、起動引数、時計、待機は独立した能力
- HTTPS は論理接続名からホスト側の接続定義と認証を解決
- 資格情報は BSB 値、変数、結果、診断、トレースへ載せない
- ファイルは `(作業領域名, 論理名)` の有限登録を権限境界とする
- 書き込みは同じ親ディレクトリの一時ファイルから原子的に全置換する

詳細は [IO](spec/host-io-console.md)、[論理接続](spec/logical-connections.md)、
[HTTPS](spec/https.md)、[作業領域とファイル](spec/workspace-files.md)の各仕様に従います。

## 外部ライブラリとの境界

Unicode の規範データには ICU4J 76.1、正規表現の照合核には RE2/J 1.8 を使います。ライブラリ固有の
型、例外、Unicode 表を BSB の言語仕様へ公開せず、BSB 側の構文、診断、資源制限、適合層を通します。

JSON は外部 JSON ライブラリへ依存せず、非再帰コーデックと不変値モデルで扱います。CLI の JSON DTO と
言語の `JSON` 値は別の型であり、自動変換しません。

## AI・ツール向けの公開面

- `format`: ソースを一意な標準形へ変換
- `check --json`: 診断、位置、修正候補、資源上限を版管理された JSON で返す
- `explain --json`: 単語、型、スタック効果、到達性、能力、副作用、束縛を返す

公開 JSON は内部の構文木、IR、トレース、Java 列挙型から分離した DTO で生成します。内部表現を変更しても、
公開版の必須フィールドと識別値を不用意に変えないためです。詳細は
[CLI JSON 診断](spec/cli-json.md)と[CLI JSON 説明](spec/explain-json.md)に従います。

診断の `stage` は開発順ではなく、`utf8`、`lexical`、`syntax`、`name`、`typeAndStack`、`runtime` などの
処理フェーズを示します。
