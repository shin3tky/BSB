# WST-TABLE機能グループ: 厳密CSV/TSVと二次元文字列配列

> 本文は現行実装の規範契約です。
>
> WST-FILE機能グループの[名前付き作業領域と複数ファイル](workspace-files.md)および
> NARRAY機能グループの[二次元配列](nested-arrays.md)を前提とします。統合草案
> [名前付き作業領域、ファイル、CSV/TSV](workspace-tables.md)と異なる場合、
> CSV/TSVについては本仕様を優先します。

## 1. 目的と範囲

厳密UTF-8として復号済みのBSB`文字列`と、不変`配列<配列<文字列>>`の間を、決定的なCSVまたはTSVとして
変換します。ファイルI/Oとは合成可能ですが、変換語自体は純粋であり、OS path、作業領域、論理ファイル名を
受け取りません。

初版に含むものは次です。

- comma固定CSVとtab固定TSV
- 同一の引用符、改行、BOM入力規則
- 全セル`文字列`の矩形な二次元配列
- 文法不正を返す閉じた解析失敗値
- 0セル行、ragged、NULセルを拒否する直列化診断
- BOMなし、CRLF終端、最小引用の決定的出力
- 入力・出力・配列・区切りテキスト作業の有限上限

専用`表`型、header、列名、型推論、null、方言指定、文字コード自動判定、streamingは追加しません。

## 2. 公開型と組み込み語

新しい閉じた組み込み型は`区切りテキスト解析失敗`です。型は通常の文字列や配列と比較・表示できず、内容は
専用取出し語だけで観測します。成功表は既存の`配列<配列<文字列>>`です。二次元配列自体のragged・0セル行許可は
変更せず、CSV/TSV変換境界だけで矩形性を要求します。

WST-FILE機能グループの159語の末尾へ、次の順で8語を追加します。別名はありません。すべて
`featureGroup="WST"`、`typeRule = fixed`、`returnsNormally = true`です。

```text
CSVを表として解析する
TSVを表として解析する
表をCSVに変換する
表をTSVに変換する
区切りテキスト解析失敗の種類を取り出す
区切りテキスト解析失敗のバイト位置を取り出す
区切りテキスト解析失敗の行を取り出す
区切りテキスト解析失敗の列を取り出す
```

スタック効果は次です。

```text
CSVを表として解析する
    (文字列 -- 結果<配列<配列<文字列>>,区切りテキスト解析失敗>)
TSVを表として解析する
    (文字列 -- 結果<配列<配列<文字列>>,区切りテキスト解析失敗>)
表をCSVに変換する
    (配列<配列<文字列>> -- 文字列)
表をTSVに変換する
    (配列<配列<文字列>> -- 文字列)
区切りテキスト解析失敗の種類を取り出す
    (区切りテキスト解析失敗 -- 文字列)
区切りテキスト解析失敗のバイト位置を取り出す
    (区切りテキスト解析失敗 -- 整数)
区切りテキスト解析失敗の行を取り出す
    (区切りテキスト解析失敗 -- 整数)
区切りテキスト解析失敗の列を取り出す
    (区切りテキスト解析失敗 -- 整数)
```

8語は能力も副作用も要求しません。型名と語名を予約名へ追加します。

## 3. 共通方言

CSVの区切りはU+002C comma、TSVはU+0009 tabです。それ以外の規則は共通です。RFC 4180は参考にしますが、
本節の規則だけをBSBの規範とします。RFC 4180がrecord区切りをCRLFと定義する一方、実在するCSV/TSVとの
相互運用のため、入力ではLF単独とCR単独もrecord区切りとして受理します。直列化出力はCRLFに統一します。

```text
document       := bom? (record lineBreak)* record? lineBreak?
record         := field (delimiter field)*
field          := unquoted | quoted
quoted         := DQUOTE quotedContent* DQUOTE
quotedContent  := nonQuoteScalar | delimiter | CR | LF | DQUOTE DQUOTE
lineBreak      := CRLF | LF | CR
bom            := U+FEFF at document start only
```

- 文書先頭のU+FEFFを最大1個だけBOMとして除去する。それ以外のU+FEFFは通常データである
- CRLFは1改行として原子的に消費し、CRとLFも単独改行として受理する
- quoted field内の区切り、CR、LFはデータであり、`""`だけを1個の引用符へ戻す
- unquoted field内の引用符は不正である
- closing quote後は、区切り、改行、入力末尾だけを許す
- 空白をtrimせず、comment、backslash escape、区切り自動判定を行わない
- NUL U+0000はquoted/unquotedのどちらでも拒否する
- 最初のrecordをheaderとして特別扱いしない

空入力は0行0列です。区切りだけの入力は1行2空セル、1改行だけの入力は1行1空セルです。改行直後に入力が
終わっても次の空recordを開始しません。したがって`LF LF`は空セル1個のrecordを2行として扱います。

解析成功値は、空文書を除き、全行が同じ1個以上のセル数を持つ矩形です。2行目以後のセル数が異なる場合は
文法失敗値になります。

## 4. 解析失敗値

外部入力の文法不正は`失敗(区切りテキスト解析失敗)`として返し、次の閉じたASCII種類だけを持ちます。

| 種類 | 失敗位置 |
|---|---|
| `unexpectedQuote` | unquoted field内の引用符 |
| `unexpectedCharacterAfterQuote` | closing quote直後の許可されない文字 |
| `unterminatedQuotedField` | 入力末尾 |
| `nulCharacter` | NUL自身 |
| `columnCountMismatch` | 最初の余分なfieldの開始、または不足recordの改行開始・入力末尾 |

失敗値が保持するのは、種類、0始まりUTF-8バイト位置、1始まり物理行、1始まりUnicodeスカラー列だけです。
元入力、セル、期待・実際のセル数、区切り、例外を保持しません。

位置はBOMを含む元入力で数えます。文書先頭BOMの直後はbyte位置3、行1、列2です。CRLFは両scalarを消費して
次の行の列1へ移り、quoted field内でも物理行を進めます。補助平面文字は列を1、UTF-8バイト位置を4進めます。
入力末尾の失敗はUTF-8全長と、その位置の行・列を返します。

同じ位置で複数候補が成立する場合は、`nulCharacter`、`unexpectedQuote`、
`unexpectedCharacterAfterQuote`、`unterminatedQuotedField`、`columnCountMismatch`の順で分類します。

## 5. 決定的直列化

直列化が受理するのは、空の外側配列、または全行が同じ1個以上のセルを持つ
`配列<配列<文字列>>`です。0セル行、ragged、NULを含むセルは捕捉不能診断で拒否します。

出力は次の一意な形式です。

- BOMを付けない
- 空の外側配列は空文字列にする
- 非空表はrecord間と最終record後にCRLFを1個置く
- 対象delimiter、引用符、CR、LFを含むセルだけを通常はquoted fieldにする
- quoted field内の引用符を`""`へ二重化する
- 先頭recordの先頭セルがU+FEFFで始まる場合は、入力BOMとの誤認を防ぐため必ずquoted fieldにする
- それ以外の文字を正規化、trim、型変換しない

この特別引用により、受理した任意の表`T`について`parse(serialize(T)) = T`を保ちます。CSVでtabを、TSVでcommaを
含むだけのセルは引用しません。先頭の`=`、`+`、`-`、`@`等を表計算式対策として変更しません。

## 6. 資源上限と課金

| 資源 | 上限 |
|---|---:|
| CSV/TSV入力・出力 | 16,777,216 UTF-8 bytes（既存文字列上限） |
| 1行・外側配列の直接要素 | 65,536（既存配列上限） |
| 1二次元値の論理セル | 1,000,000（既存二次元配列上限） |
| 1実行の配列構築単位 | 1,000,000（既存） |
| 1実行の区切りテキスト作業 | 134,217,728 |

解析1回の区切りテキスト作業は、入力の`UTF-8 byte数 + Unicodeスカラー数`です。入力文字列の既存上限を検査し、
この作業を有限幅で一括予約してから走査します。文法失敗でも予約を戻しません。成功時だけ、各行のセル参照と
外側の行参照、すなわち`セル数 + 行数`を既存配列構築単位へ一括予約します。

直列化1回の区切りテキスト作業は、`全セル入力UTF-8 byte数 + 候補出力UTF-8 byte数`です。構造とNULを先に検査し、
候補出力長を完全文字列の割当て前に有限幅で測ります。出力上限、区切り作業、既存文字列構築、結果stackを
すべて検査してから出力文字列を1回構築します。

解析中は、文法と位置を最後まで検査できる飽和counterを使います。行・セル上限を越えた内容を完全保持せず、
文法失敗がなければ外側長、行長、論理セルの順で既存資源診断にします。

## 7. 判定順と原子性

解析は、命令・入力型・文字列不変条件、入力上限、区切り作業予約、1回走査、文法失敗、外側長、各行長、
論理セル、配列構築予約、結果stack、入力から結果への置換の順です。先に確定する入力上限・区切り作業診断は
文法失敗より優先し、走査後は文法失敗を配列資源診断より優先します。

直列化は、命令・入力型・配列不変条件、最初の0セル行またはragged行、最初のNULセル、候補出力長、出力上限、
区切り作業予約、文字列構築予約、結果stack、入力から文字列への置換の順です。

捕捉不能診断では入力stack、保存値、stdout、stderrを変更しません。受理済みの累積予算は後続失敗でも戻しません。
変換は時計、locale、timezone、既定文字コード、OS改行に依存しません。

## 8. traceと非開示

通常traceと診断`dataStack`では`区切りテキスト解析失敗:<redacted>`と表示します。`結果`へ包んだ場合も推移的に
伏せます。専用語で取り出した種類・位置は通常値です。成功表と直列化文字列は通常の文字列・二次元配列trace方針に
従い、ファイル由来taintは追加しません。

解析失敗と直列化診断へ、入力、セル、行、表、区切り、内容の接頭辞・hashを含めません。診断で公開できるのは
語名、1始まりの行・列index、件数、規範上限、閉じたreasonだけです。

## 9. 適合境界

期待値は本番parser、外部CSV library、表計算ソフトから生成しません。独立corpusでCSV/TSV、BOM、CR/LF/CRLF、
quoted改行、空field、引用符二重化、日本語、補助平面文字、全5失敗、位置、矩形性、NUL、往復、資源、原子性、
traceを固定します。

公開CLIの参照経路は、前半のファイル読取、厳密UTF-8復号、CSV/TSV解析、既存二次元配列操作、直列化、
厳密UTF-8符号化、原子的ファイル書込を終端までつなぎます。変換語単体には新しいCLI optionやTOML項目を
追加しません。

## 10. 対象外と後続互換性

任意delimiter、quoteなし方言、BOM付き出力、LF固定出力、寛容解析、型付き列、header mapping、formula安全化、
streaming、遅延行列、部分回復は後続です。追加する場合も初版4変換語の固定方言と決定的出力を変更せず、別語または
明示dialect型として設計します。
