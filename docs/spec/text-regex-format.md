# TEXT機能グループ: 文字列・正規表現のフォーマッタ仕様

> 本文は現行実装の規範契約です。

## 1. 既存リテラル

文字列と文字は[language-core-format.md](language-core-format.md)の値からの再構成を維持します。ASCII二重引用符は日本語二重かぎ括弧へ統一し、内容へNFCを適用しません。

TEXT機能グループの操作語、`正規表現`型、`配列<文字列>`は通常の名前・型として整形します。formatは文字列操作、数値変換、正規表現照合を実行しません。

## 2. 正規表現リテラル

rawパターンのコードポイント列を変更しません。通常文字列のエスケープ解決・再構成も適用しません。入力フラグだけを重複のない`ims`順へ並べます。

```text
正規表現「^[A-Z]+$」mi
```

`正規表現`と`「`、`」`とフラグの間に空白を置きません。リテラルの前後は通常トークンと同じ区切りを使います。パターン内の空白、`#`、`、`はコメントやトークン区切りでなくraw内容です。

終端不足、生改行、不正・重複フラグは字句エラーなのでformatも失敗します。エンジン構文エラー、未対応構文、キャプチャ・パターン・コンパイル命令上限はformatでは検査しません。

## 3. 冪等性

TEXT機能グループまでの字句・構文として有効な任意のソース`S`について、バイト列として次を満たします。

```text
format(format(S)) = format(S)
```

出力はBOMなしUTF-8、LF、末尾LFちょうど1個です。CORE〜NUM機能グループのcanonical資源は変更しません。
