# OPT機能グループ: `任意<T>`値と非必須検索

> 本文は現行実装の規範契約です。
>
> 先行する実装済み機能グループの規則は、ここで明示的に変更する箇所以外、引き続き有効です。

## 1. 範囲

`任意<T>`は、値がある`ある(T)`と値がない`ない`を区別する第一級の具体型です。
通常のBSB型は引き続きnull非許容であり、`任意<T>`を`T`の代用にはしません。
最初の生成元として、JSONオブジェクトの非必須キー検索を追加します。

`結果<T, E>`、失敗捕捉、HTTP、利用者定義の型・ジェネリック単語、
`配列<任意<T>>`はOPT機能グループに含めません。通信失敗を`ない`で表してはなりません。

## 2. 型構文と具体型

型参照を1引数の型構築子として解析し、次を受理します。

```text
type          := simpleType | "配列" "<" type ">" | "任意" "<" type ">"
optionalType  := "任意" "<" concreteType ">"
```

`任意<T>`の`T`には、現行の任意の具体型を置けます。したがって、スカラー型、
既存の1次元配列型、別の任意型を許します。

```text
任意<整数>
任意<正規表現>
任意<入力結果>
任意<配列<JSON>>
任意<任意<文字列>>
```

裸の`任意`、空の`任意<>`、型制約を入れた`任意<T>`・`任意<数値>`、未知型を入れた形は
具体型ではありません。`配列<任意<整数>>`は、配列要素型の既存制限により
`E_ARRAY_ELEMENT_TYPE_NOT_ALLOWED`です。`任意`、`ある`、`ない`と第5節の5語は予約名です。

型構築子の入れ子は、外側を含め256段以下です。257段目をAST再帰へ入る前に
`E_SYNTAX_DEPTH_LIMIT`で拒否します。この上限は制御構文の深さと同じ値ですが、
型参照1個の入れ子として独立に数えます。

## 3. 値、保存、合流

`ある(T)`は宣言された内包型と同じ値を1個持ち、`ない`は値を持ちません。
`ある(JSONヌル)`は値ありで、`ない`とは異なります。任意値は不変です。
値あり化とJSON検索は不変な内包値を複製せず参照共有し、ラッパーだけを新しく作ります。

`任意<T>`は定数、変数、局所保存、利用者定義語の入出力、早期復帰、分岐・ループの
スタック合流に使えます。`任意<A>`と`任意<B>`は`A`と`B`が同じ場合だけ同じ型です。
処理系は`ある`・`ない`の状態を静的型に含めず、到達可能な分岐を状態で消去しません。

## 4. 等価性、表示、トレース

`任意<T>`が`等しい`へ渡せるのは、`T`が等値比較可能な場合だけです。`ない`同士は等しく、
状態が異なれば等しくなく、`ある(x)`と`ある(y)`は内包値が等しい場合だけ等しいものとします。

`任意<T>`が表示可能なのは、`T`が表示可能な場合だけです。正規表示は次です。

```text
ない
ある（42）
ある（ある（値））
```

したがって`任意<正規表現>`、`任意<入力結果>`、`任意<日時>`は具体型として保存・受渡し
できますが、既存の内包型と同じく表示または等値比較の制約を満たしません。

トレースは型名を必ず示します。`TraceValuePolicy`が任意値の開示を許す場合だけ、状態と内包値を
既存規則で再帰的に整形し、`任意<整数>:ある(42)`または`任意<整数>:ない`とします。
内包型が非開示なら状態自体も情報になり得るため、既定ポリシーは値あり・値なしを区別せず
`任意<JSON>:<redacted>`、`任意<文字列>:<redacted>`、`任意<入力結果>:<redacted>`とします。
入れ子任意型は最内包型まで推移的に判定し、1層でも非開示なら外側全体を伏せます。
より厳しいホストポリシーも尊重します。
トレース整形は実行時の任意値を変更せず、予算を追加消費しません。

## 5. 組み込み語

| 正規語 | 辞書効果 | 具体化後の効果 | 意味 |
|---|---|---|---|
| `任意にする` | `T -- 任意<T>` | `整数 -- 任意<整数>`など | 入力を`ある(T)`へ包む |
| `任意に値がある` | `任意<T> -- 任意<T> 真偽` | 内包型を保持 | 入力を残して状態を判定 |
| `任意から値を取り出す` | `任意<T> -- T` | 内包型を出力 | `ある`を取り出し、`ない`なら失敗 |
| `任意を捨てる` | `任意<T> --` | 内包型を問わない | 状態を観測せず消費 |
| `JSONオブジェクトから任意値を取り出す` | `JSON 文字列 -- 任意<JSON>` | 固定 | キー検索 |

各多相語は呼出しごとに1つの具体的な`T`へ具体化し、その効果を検査済みCallとIRへ保存します。
利用者定義語の効果に辞書専用の`T`は書けません。

辞書の例は順に`42 を 任意にする`、`42 を 任意にする 任意に値がある`、
`42 を 任意にする 任意から値を取り出す`、`42 を 任意にする 任意を捨てる`、
`「{"x":1}」を JSONを解析する 「x」を JSONオブジェクトから任意値を取り出す`とします。
5語はいずれも副作用なしの初期値式で使用できます。

`ない`を単独構築する語は提供しません。期待型のないスタックで型を推測しないためです。
OPT機能グループではJSON非必須検索が`任意<JSON>`の`ない`を生成します。他の型の値なし生成は、
その型を返す後続APIまたは型注釈付き構築の独立提案に残します。この制限は
`任意<T>`の値あり化、保存、引数・戻り値利用を妨げません。

## 6. JSONの3状態

| オブジェクトとキー | 非必須取得 | 必須取得 |
|---|---|---|
| `{"x":"値"}`、`x` | `ある(JSON文字列)` | JSON文字列 |
| `{"x":null}`、`x` | `ある(JSONヌル)` | JSONヌル |
| `{}`、`x` | `ない` | `E_JSON_KEY_NOT_FOUND` |

非オブジェクトへの非必須検索は既存`E_JSON_KIND_MISMATCH`です。キーはJSON文字列の
完全一致で検索し、NFC正規化・大小文字変換を行いません。既存の存在検査・必須取得は変更しません。

## 7. 原子性と資源課金

5語は純粋で、能力・副作用を要求しません。任意値の包装、判定、取出し、破棄は命令予算だけを
消費し、独立した任意値予算を追加しません。1個の任意値はデータスタック上で1値です。

値あり任意値の等価比較と表示は、内包値へ同じ操作を直接行う場合の既存課金を再帰的に継承します。
たとえば`任意<JSON>`の等価比較は両JSONの既存作業単位、表示はJSON直列化・表示の既存作業単位と
出力上限を検査します。`任意<配列<JSON>>`は既存の配列・JSON複合課金を使います。値なし同士、
または値あり・値なし間の比較は内包値を観測しないため、追加作業単位を消費しません。入れ子任意型も、
最初に到達した値なしで内包値の観測を止めます。内包値の課金をラッパーで迂回してはなりません。

JSON非必須検索は、オブジェクト種別とキー文字列を確認した後、既存のキー存在検査と同じ
JSON作業単位を事前検査して消費します。任意値の包装はJSON構築単位を消費しません。
JSON作業診断と内部計測の安定した操作識別値は`objectGetOptional`です。
キー不在は正常結果なので作業量を消費します。種別失敗・作業上限失敗・空値取出し失敗、ならびに
内包値の等価比較・表示の事前検査失敗では、入力スタック、保存値、プログラムstdout/stderrと、
上限検査で拒否された予算予約を変更しません。既に成功して消費済みの作業は既存契約どおり戻しません。

## 8. format、説明、公開互換性

formatは型を評価せず、正規型名を空白なしの`任意<任意<JSON>>`として出力します。
追加5語は辞書のOPT機能グループ区画に第5節の順で置きます。`explain --json`は
`featureGroup="OPT"`、能力・副作用を空配列で返します。型規則の公開値は順に
`optionalWrap`、`optionalPredicate`、`optionalUnwrap`、`optionalDrop`、`fixed`です。
既存識別値の意味は変えません。新語・新型規則の追加であるため`schemaVersion=1`を維持します。
