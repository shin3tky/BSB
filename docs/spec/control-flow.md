# FLOW機能グループ: 制御構文と静的意味論

> 本文は現行実装の規範契約です。
>
> CORE機能グループの規則は、ここで明示的に変更する箇所以外、引き続き有効です。

## 1. 範囲と機能境界

FLOW機能グループでは、条件分岐、短絡論理評価、回数ループ、条件ループ、ループの脱出・継続、単語からの早期復帰、整数の大小比較を定義します。一般の定数・変数・配列・剰余演算は追加しません。

回数ループは反復回数だけを受け取り、現在の反復番号を利用者データスタックへ積みません。このため、反復番号の保存や更新を必要とする処理はBIND機能グループ以降で扱います。

`または`と`かつ`は通常の後置単語ではなく、評価しない右辺を構文木で保持するブロック構文です。

## 2. 正規語

| 分類 | 正規語 | 役割 |
|---|---|---|
| 条件分岐 | `ならば` | `真偽`を消費し、真側を開始する |
| 条件分岐 | `さもなければ` | 任意の偽側を開始する |
| 短絡評価 | `または` | 左辺が偽の場合だけ右辺評価ブロックを実行する |
| 短絡評価 | `かつ` | 左辺が真の場合だけ右辺評価ブロックを実行する |
| ブロック共通 | `つぎに` | 条件分岐または短絡評価を閉じる |
| 回数ループ | `回だけ` | `整数`を消費し、回数ループを開始する |
| 条件ループ | `ここから` | 各反復の条件計算部を開始する |
| 条件ループ | `続く間` | 条件計算部の`真偽`を消費し、本体を開始する |
| ループ共通 | `繰り返す` | 最も内側の未完了ループを閉じる |
| 制御移行 | `打ち切る` | 最も内側のループから脱出する |
| 制御移行 | `続ける` | 最も内側のループの次反復へ進む |
| 制御移行 | `戻る` | 現在の利用者定義単語から復帰する |

これらは構文予約語であり、利用者定義名、別名、型名として使用できません。FLOW機能グループでは正規語に対する別名を定義しません。Mindとの語彙対応は設計上の参考であり、`打ち切り`、`もう一度`、`終り`を代替入力として受理しません。

## 3. 文法

CORE機能グループの`body`を、入れ子を持つ次の文法へ置き換えます。`atom`はCORE機能グループのリテラル、組み込み値、呼出し可能な名前、助詞です。`trivia`は区切りまたはコメントです。

```text
body             := (atom | conditional | shortCircuit | countedLoop | conditionLoop
                     | transfer | trivia)*

conditional      := "ならば" body
                    ("さもなければ" body)?
                    "つぎに"

shortCircuit     := ("または" | "かつ") body "つぎに"

countedLoop      := "回だけ" body "繰り返す"

conditionLoop    := "ここから" body
                    "続く間" body
                    "繰り返す"

transfer         := "打ち切る" | "続ける" | "戻る"
```

`ならば`の条件、`または`・`かつ`の左辺、`回だけ`の回数は、開始語の直前までに通常の後置評価でスタックへ積みます。これらを構文木上の式として開始語へ取り込まず、開始語が現在の抽象スタックから値を消費します。

`ここから`と`続く間`の間は、反復のたびに実行する条件計算部です。したがって条件を作る複数の呼出しを、ループの構造として保持できます。

`さもなければ`は最も内側の未完了`ならば`へ対応し、`つぎに`は最も内側の未完了`ならば`・`または`・`かつ`へ対応します。`続く間`は最も内側の未完了な条件ループへ、`繰り返す`は最も内側の未完了ループへ対応します。異なる種類の構文を飛び越えて対応させません。

## 4. 条件分岐

```text
＜条件を作る処理＞ ならば
    ＜真側＞
さもなければ
    ＜偽側＞
つぎに
```

`さもなければ`は省略できます。

`ならば`は、実行時と静的検査時の両方でスタック最上部の`真偽`を1個消費します。整数、文字、文字列を暗黙に真偽へ変換しません。

分岐開始直前のスタックを`S + [真偽]`とすると、条件を消費した後の基準状態は`S`です。

- elseありで両側が到達可能なら、両出口の値数と位置ごとの型が完全に一致しなければならない
- elseなしで真側が到達可能なら、真側の出口は`S`と完全に一致しなければならない
- 一方だけが`戻る`などで到達不能なら、到達可能な側の出口を分岐後の状態とする
- 両側が到達不能なら、分岐後も到達不能とする
- elseなしには常に条件が偽の経路があるため、分岐後は少なくとも`S`で到達可能である

### 4.1 短絡する`または`・`かつ`

```text
＜左辺を作る処理＞ または
    ＜右辺を作る処理＞
つぎに
```

`かつ`も同じ形です。開始直前のスタックは`S + [真偽]`でなければなりません。右辺評価ブロックの到達可能な通常出口は、基準`S`へ`真偽`をちょうど1個追加した`S + [真偽]`でなければなりません。

- `または`は左辺が`はい`なら右辺を実行せず、結果`はい`を残す
- `または`は左辺が`いいえ`なら右辺を実行し、その真偽値を結果にする
- `かつ`は左辺が`いいえ`なら右辺を実行せず、結果`いいえ`を残す
- `かつ`は左辺が`はい`なら右辺を実行し、その真偽値を結果にする

短絡した右辺の呼出し、副作用、診断、実行予算消費は発生しません。静的な能力・副作用の説明では、実行時の左辺値を定数畳み込みせず、構造的に到達可能な右辺を保守的に含めます。右辺は独立した字句スコープを作り、その局所宣言は`つぎに`の後へ漏れません。

## 5. 回数ループ

```text
＜回数を作る処理＞ 回だけ
    ＜本体＞
繰り返す
```

`回だけ`はスタック最上部の`整数`を1個消費します。回数を消費した後のスタックをループ基準状態`S`とします。

- `0`は本体を0回実行する
- 正数`n`は本体を正確に`n`回実行する
- 負数は本体を実行せず、`E_NEGATIVE_REPEAT_COUNT`で実行を中止する
- 反復番号や残り回数は処理系内部の制御状態であり、利用者データスタックから観測できない
- 回数そのものに追加の上限は設けず、実際の実行は命令数と時間の上限で停止する

本体の通常終端と`続ける`の各経路は`S`と完全に一致しなければなりません。`打ち切る`の各経路も、ループ後へ合流するため`S`と一致しなければなりません。0回経路が常に存在するため、ループ後の状態は`S`です。

## 6. 条件ループ

```text
ここから
    ＜条件を作る処理＞
続く間
    ＜本体＞
繰り返す
```

`ここから`直前のスタックをループ基準状態`S`とします。各反復で条件計算部を実行し、`続く間`へ到達したスタックは正確に`S + [真偽]`でなければなりません。`続く間`が`真偽`を消費し、偽なら`S`でループ後へ進み、真なら`S`で本体へ進みます。

本体の通常終端と`続ける`は、次の条件計算へ戻るため`S`と一致しなければなりません。`打ち切る`も`S`でループ後へ進みます。

到達可能な`続く間`が1つでもあれば、条件が偽となる0回または終了経路を保守的に到達可能とみなし、ループ後は`S`です。条件計算部の全経路が`戻る`または`続ける`などで`続く間`へ到達せず、到達可能な`打ち切る`もなければ、ループ後は到達不能です。真偽値の定数畳み込みによってこの判定を変えません。

条件計算部の内部でも、同じ条件ループを対象とする`打ち切る`と`続ける`を使用できます。その地点のスタックは`S`でなければなりません。条件計算部で`戻る`により単語を終えることもできます。

## 7. 制御移行

### `打ち切る`

最も内側の字句上のループを終了し、そのループ直後へ進みます。ループの外では`E_BREAK_OUTSIDE_LOOP`です。外側のループを段数指定して打ち切る構文はFLOW機能グループにありません。

### `続ける`

最も内側の字句上のループの次反復へ進みます。回数ループでは内部回数を1回進め、条件ループでは条件計算部の先頭へ戻ります。ループの外では`E_CONTINUE_OUTSIDE_LOOP`です。

### `戻る`

現在の利用者定義単語から直ちに呼出元へ戻ります。`戻る`地点の型付きスタックは、その単語の宣言出力と完全に一致しなければなりません。一致しない場合は`E_RETURN_EFFECT_MISMATCH`です。

`メイン`でも`戻る`を使用でき、その地点のスタックは空でなければなりません。呼び出した単語内の`戻る`が、呼出元の単語や呼出元のループまで終了させることはありません。

## 8. 到達可能性と診断抑止

`打ち切る`、`続ける`、`戻る`の直後にある同じ要素列の残りは到達不能です。両側が到達不能となる条件分岐の直後も到達不能です。

到達不能な連続範囲ごとに、最初の実行要素へ`W_UNREACHABLE_CODE`を1件だけ報告します。コメントと区切りには報告しません。外側の到達不能構文へ警告した場合、その内部へ重複する警告を出しません。

処理系は到達不能範囲の名前・型・スタック検査を省略し、そこから派生する未定義語や型不一致を報告しません。IR生成時にもその範囲を省略します。`format`は到達可能性を検査せず、到達不能範囲を構文どおり保持して整形します。

真偽リテラルや`比べて小さい`の結果を使った定数畳み込みは、FLOW機能グループの到達可能性判定へ含めません。構造的な無条件移行だけを判定します。

## 9. 経路ごとの抽象スタック

静的検査では、型列と到達可能性を組にした制御状態を経路ごとに複製します。合流では次の順序を使います。

1. 到達不能な経路を除く。
2. 到達可能な経路が0本なら、合流後も到達不能とする。
3. 1本なら、その型列を合流後の状態とする。
4. 2本以上なら、値数と位置ごとの型がすべて一致した場合だけ合流する。
5. 一致しなければ、各経路の型列と関連位置を持つ専用診断を報告する。

助詞はCORE機能グループと同じくスタックを変更しません。制御予約語は呼出し可能な名前ではないため、助詞配置検査で「呼出し可能な名前」に数えません。

## 10. 整数比較

FLOW機能グループで組み込み単語を1個追加します。

```text
比べて小さい    （整数 整数 -- 真偽）
```

第1入力を左辺、第2入力を右辺とし、左辺が右辺より数学的に小さい場合だけ`はい`を返します。等しい場合は`いいえ`です。任意精度整数を比較し、差を計算しないため整数結果桁数上限の対象にはなりません。

```text
3 と 5 を 比べて小さい    # はい
5 と 3 を 比べて小さい    # いいえ
5 と 5 を 比べて小さい    # いいえ
```

別名と副作用はありません。CORE機能グループで`E_FEATURE_NOT_AVAILABLE`だったこの名前は、FLOW機能グループでは組み込み辞書へ解決します。

## 11. 構文深さ

条件分岐、短絡評価、回数ループ、条件ループを開始するたびに構文深さを1増やし、対応する終了語で1減らします。単語定義自体は数えません。

深さ256を受理し、257段目の開始語に`E_SYNTAX_DEPTH_LIMIT`を報告します。257段目のASTノードや再帰処理用フレームを確保する前に拒否します。

## 12. IRとトレースに必要な意味

FLOW機能グループのIRは少なくとも`Jump`と`BranchIfFalse`を追加します。`BranchIfFalse`は`真偽`を1個消費し、偽の場合だけ指定先へ移動します。回数ループの回数は利用者データスタックと分離した内部制御状態で保持します。

正確なJavaの型名は実装詳細ですが、トレースでは次の概念命令名を安定名として使います。

```text
Jump
BranchIfFalse
CountedLoopStart
CountedLoopNext
```

`打ち切る`、`続ける`、`戻る`は、それぞれ適切な飛び先または既存`Return`へ変換します。回数ループを途中で離れる場合は、そのループの内部制御状態も破棄します。

各制御命令は、分岐したか、飛び先、実行前後の内部ループ状態をトレースへ渡します。通常実行とトレース実行の出力、終了コード、最終データスタックは一致しなければなりません。
