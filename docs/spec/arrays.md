# ARRAY機能グループ: 配列

> 本文は現行実装の規範契約です。
>
> CORE〜BIND機能グループの規則は、ここで明示的に変更する箇所以外、引き続き有効です。
>
> NARRAY機能グループ注記: [二次元配列仕様](nested-arrays.md)が、本書の
> 「一次元のみ」「入れ子配列は未対応」という箇所を上書きします。本書の一次元配列契約は引き続き有効です。
>
> 任意・結果の合成注記: [任意・結果の合成](optional-result-composition-diagnostics.md)が、本書の
> 配列要素型の制限を拡張し、`任意<T>`と`結果<T,E>`を要素として許可します。

## 1. 範囲と機能境界

ARRAY機能グループでは、同じ型の値を順序つきで保持する1次元の不変配列を追加します。配列リテラル、具体的な配列型、型付き空配列、長さ、要素参照、安全な端取得、半開区間による一部取得、要素置換、前後への追加、配列連結、不変削除、逆順、検索、空判定、配列反復、構造的等価性、決定的表示を規範化します。

要素型にできるのは、BIND機能グループまでに実行可能な`整数`、`真偽`、`文字`、`文字列`の4スカラー型です。多次元配列、異種配列、可変な配列実体、小数配列、暗黙変換は追加しません。

ロードマップの平均計算は除算と小数実行を必要とするためNUM機能グループへ送ります。ARRAY機能グループの章末例は5件の点数について、合計、件数、各点数を表示します。

## 2. 正規語と記号

| 分類 | 標準形 | 役割 |
|---|---|---|
| 配列開始 | `【` | 配列リテラルを開始する |
| 要素区切り | `、` | 隣接する2個の要素式を分ける |
| 配列終端 | `】` | 配列リテラルを終了する |
| 配列型 | `配列<T>` | 要素型`T`を持つ配列型 |
| 型付き空配列値 | `空の整数配列`など | 具体的な要素型を持つ長さ0の配列値 |
| 配列反復開始 | `各要素について` | 配列を消費し、各要素で本体を実行する |
| 配列反復終端 | `繰り返す` | 次の要素へ進むか反復を終える |

入力では配列内の全角コンマ`，`も要素区切りとして受理し、`format`は`、`へ統一します。ASCIIコンマ`,`は受理しません。`【`と`】`にASCIIまたは別のUnicode括弧の代替表記はありません。

`配列`、型付き空配列値、`各要素について`、第7節の16個の組み込み単語は予約名です。`繰り返す`はFLOW機能グループからある構文予約語を共有します。

## 3. 配列型

配列型の標準形は次です。

```text
arrayType := "配列" "<" scalarType ">"
scalarType := "整数" | "真偽" | "文字" | "文字列"
```

`<`と`>`はASCII文字です。入力では記号の内側に通常区切りを置けますが、標準形では空白を置きません。したがって`配列 < 文字列 >`は`配列<文字列>`になります。

bare `配列`は具体型ではなく`E_ARRAY_ELEMENT_TYPE_REQUIRED`です。`配列<>`は構文エラー`E_EXPECTED_ARRAY_ELEMENT_TYPE`、閉じ`>`の不足は`E_EXPECTED_ARRAY_TYPE_END`です。`配列<小数>`はNUM機能グループの機能境界として既存の`E_FEATURE_NOT_AVAILABLE`、`配列<配列<整数>>`は`E_NESTED_ARRAY_NOT_AVAILABLE`です。

型の一致は要素型まで含む完全一致です。`配列<整数>`と`配列<文字列>`は異なる型で、代入、分岐合流、単語呼出しで暗黙変換しません。

組み込み辞書の説明に現れる`配列<T>`と`T`は対応する型変数です。利用者定義単語のスタック効果には型変数`T`を書けず、従来どおり具体型だけを書きます。

## 4. 配列リテラル

```text
arrayLiteral       := "【" arrayElements? "】"
arrayElements      := arrayElement (arraySeparator arrayElement)*
arraySeparator     := "、" | "，"
arrayElement       := (arrayElementAtom | trivia)*
```

配列リテラルは通常の本体要素、宣言の初期値、別の配列要素式に現れ得ます。ただし、ARRAY機能グループでは配列を配列要素として受理しないため、最後の配置は静的な`E_NESTED_ARRAY_NOT_AVAILABLE`になります。

空白だけでは要素を分けません。`【1 2】`は1個の要素式が2値を残す入力であり、`E_ARRAY_ELEMENT_VALUE_COUNT`です。先頭、連続、末尾の区切りは空要素を作るため`E_EXPECTED_ARRAY_ELEMENT`です。

各要素式は周囲の利用者データスタックから分離した空の抽象スタック`[]`から検査します。すべての到達可能な出口が正確に`[T]`となり、全要素の`T`が同じスカラー型である場合だけ、リテラル型を`配列<T>`とします。

- 0値なら`E_ARRAY_ELEMENT_VALUE_MISSING`
- 2値以上なら`E_ARRAY_ELEMENT_VALUE_COUNT`
- 最初の要素と型が異なる要素は`E_ARRAY_ELEMENT_TYPE_MISMATCH`
- 配列値を作る要素は`E_NESTED_ARRAY_NOT_AVAILABLE`

要素式で許可するものは、BIND機能グループの宣言初期値と同じく、リテラル、組み込み値、可視で初期化済みの値参照、助詞、副作用のない組み込み単語です。ARRAY機能グループの純粋な配列操作語も、必要な入力を同じ要素式内で作る場合は使用できます。利用者定義単語と副作用を持つ単語は`E_ARRAY_ELEMENT_CALL_NOT_ALLOWED`です。制御構文、宣言、代入は`E_ARRAY_ELEMENT_NOT_ALLOWED`です。

要素式は元ソース順に各1回評価します。リテラル全体の評価前に要素を先取りしたり、型が同じことを理由に評価順を変えたりしません。

## 5. 空配列

`【】`は構文として有効で`format`できますが、要素型を推論できないためcheckとrunでは`E_EMPTY_ARRAY_TYPE_REQUIRED`です。代入先や呼出し先から期待型を逆向きに伝播して`【】`を暗黙に型付けしません。

具体的な空配列には次の組み込み値を使います。

```text
空の整数配列      （-- 配列<整数>）
空の真偽配列      （-- 配列<真偽>）
空の文字配列      （-- 配列<文字>）
空の文字列配列    （-- 配列<文字列>）
```

これらは呼出しではなく`はい`・`いいえ`と同じ組み込み値です。毎回同じ論理値を作り、不変であるためオブジェクト共有の有無を観測できません。

## 6. 不変性と値の意味

配列値は要素型、長さ、0始まりの各位置の値で構成されます。作成後に要素列を変更できません。

要素置換、末尾追加、一部取得は新しい配列値を返します。元の配列を定数、変数、局所値、データスタックの別位置から参照していても、その内容は変わりません。実装はこの意味を守る限り構造共有できます。

変数の配列を更新する場合は次のように新しい値を明示的に代入します。

```text
点数は 変数 【70、80、90】。

メインとは （--）
    点数 と 1 と 85 を 配列の要素を置き換える を 点数 に 入れる
こと。
```

配列値は秘密性を持ちませんが、トレース値ポリシーが配列を非開示と判定した場合は、要素単位ではなく配列全体を伏せます。

## 7. 標準操作語

### 配列の長さ

```text
配列の長さ （配列<T> -- 整数）
```

配列を1個消費し、0以上65,536以下の要素数を返します。

### 配列から取り出す

```text
配列から取り出す （配列<T> 整数 -- T）
```

配列と添字を消費し、指定位置の要素を返します。長さ`N`の有効添字は`0 <= 添字 < N`です。負数と`N`以上は`E_ARRAY_INDEX_OUT_OF_BOUNDS`です。

### 配列の一部を取り出す

```text
配列の一部を取り出す （配列<T> 整数 整数 -- 配列<T>）
```

入力順は配列、開始、終了です。開始を含み終了を含まない`[開始, 終了)`を返します。長さ`N`に対して`0 <= 開始 <= 終了 <= N`を有効とします。`[N,N)`は空配列、`[0,N)`は元と同じ値の配列です。範囲不正は`E_ARRAY_RANGE_OUT_OF_BOUNDS`です。

### 配列の要素を置き換える

```text
配列の要素を置き換える （配列<T> 整数 T -- 配列<T>）
```

指定位置だけを入力値へ置き換えた新しい配列を返します。添字規則は要素参照と同じです。元の配列は変わりません。

### 配列の末尾へ追加する

```text
配列の末尾へ追加する （配列<T> T -- 配列<T>）
```

末尾へ入力値を1個追加した新しい配列を返します。入力が最大長65,536なら新しい長さが上限を超えるため`E_ARRAY_LENGTH_LIMIT`です。

### 配列をつなぐ

```text
配列をつなぐ （配列<T> 配列<T> -- 配列<T>）
```

第1配列の後ろへ第2配列の要素を順に置いた新しい配列を返します。両配列の要素型は型引数を含めて完全一致しなければなりません。結果長が65,536を超える場合は`E_ARRAY_LENGTH_LIMIT`です。

### 配列の先頭へ追加する

```text
配列の先頭へ追加する （配列<T> T -- 配列<T>）
```

先頭へ入力値を1個追加した新しい配列を返します。直接長と二次元配列の論理葉上限は末尾追加と同じです。

### 配列を逆順にする

```text
配列を逆順にする （配列<T> -- 配列<T>）
```

要素順を反転した新しい配列を返します。二次元配列では行順だけを反転し、各行の要素順は変えません。

### 配列に含まれる、配列から検索する

```text
配列に含まれる       （配列<T> T -- 真偽）
配列から検索する     （配列<T> T -- 整数）
```

添字0から昇順に既存の`等しい`と同じ構造的等価性で比較し、最初の一致で停止します。`配列に含まれる`は一致の有無、`配列から検索する`は最初の一致位置を返し、未発見時は`-1`です。`T`全体が等値比較可能でなければ静的な`E_TYPE_MISMATCH`です。

### 配列が空である

```text
配列が空である （配列<T> -- 真偽）
```

長さ0なら`はい`、それ以外は`いいえ`を返します。

### 配列の先頭を任意で取り出す、配列の末尾を任意で取り出す

```text
配列の先頭を任意で取り出す （配列<T> -- 任意<T>）
配列の末尾を任意で取り出す （配列<T> -- 任意<T>）
```

非空配列では対応する端の要素を値あり任意値で返し、空配列では具体的な`任意<T>`の値なしを返します。範囲外診断を発生させず、入力配列は結果へ残しません。

### 配列の先頭を削除する、配列の末尾を削除する

```text
配列の先頭を削除する （配列<T> -- 配列<T>）
配列の末尾を削除する （配列<T> -- 配列<T>）
```

非空配列では対応する端の1要素を除いた新しい配列を返します。空配列では同じ型の空配列を返し、失敗しません。

### 配列の一部を削除する

```text
配列の一部を削除する （配列<T> 整数 整数 -- 配列<T>）
```

入力順は配列、開始、終了です。半開区間`[開始, 終了)`の要素だけを除き、前後を元の順序で保持した新しい配列を返します。有効範囲は一部取得と同じ`0 <= 開始 <= 終了 <= N`で、`[N,N)`を含む空区間の削除は元と同じ論理値です。範囲不正は`E_ARRAY_RANGE_OUT_OF_BOUNDS`です。

16単語は副作用なしです。入力不足は既存の`E_STACK_UNDERFLOW`、配列・整数・要素型の不一致は既存の`E_TYPE_MISMATCH`です。辞書は各入力に対応する具体的な期待型を診断へ出せなければなりません。

## 8. 配列反復

```text
＜配列を作る処理＞ 各要素について
    ＜現在要素を使う本体＞
繰り返す
```

入口スタックを`S + [配列<T>]`とします。`各要素について`は配列を消費します。各反復の本体入口は`S + [T]`、通常の本体出口と`続ける`地点は正確に`S`でなければなりません。反復終了後も`S`です。

開始語の直前に置いた`を`は配列反復を区切る構文上の助詞として消費し、後続する本体内の単語へ持ち越しません。助詞自身はデータスタックを変えず、独立したトレースイベントも作りません。

要素は添字0から長さ-1まで順番に1回ずつ渡します。空配列では本体を0回実行します。反復本体は静的には空配列の場合も検査します。

`打ち切る`は残りの要素を処理せず反復後へ進みます。`続ける`は次の要素へ進みます。どちらも現在要素を含む余分な値を残せません。配列反復の内側にある条件・回数・条件ループと、外側にあるループの制御移行はFLOW機能グループの最内側ループ規則に従います。

配列反復本体は子の字句スコープです。本体で宣言した局所値は各要素への到達ごとに再初期化し、反復後から参照できません。

入口値不足は`E_ARRAY_LOOP_INPUT_UNDERFLOW`、最上部が配列でなければ`E_ARRAY_LOOP_INPUT_TYPE_MISMATCH`、本体・脱出・継続のスタック不一致は既存の`E_LOOP_STACK_MISMATCH`です。

## 9. 等価性と表示

`等しい`の型制約`T`へ具体的な配列型を追加します。比較できるのは完全に同じ配列型どうしです。長さが同じで、同じ添字の全要素が対応するスカラー型の等価性を満たす場合だけ`はい`です。順序は意味を持ちます。

配列型を`表示可能`へ追加します。表示形式は配列リテラルの標準形で、要素間に`、`を置き空白を入れません。

```text
【1、2、3】
【はい、いいえ】
【'A'、'\n'】
【「赤」、「青」】
```

文字と文字列は[language-core-format.md](language-core-format.md)と同じ引用・エスケープで値から再構成します。表示は配列全体を1回の原子的な出力として既存64 MiB上限へ照合し、上限超過時は一部も書きません。

## 10. IRと実行モデル

ARRAY機能グループで次の概念命令を追加します。

```text
BuildArray
ArrayLoopStart
ArrayLoopNext
```

`BuildArray`は要素型と要素数を保持し、直前に評価された要素をソース順の配列へまとめて1値を積みます。型付き空配列値は要素数0の定数値として扱えます。

`ArrayLoopStart`は配列を消費し、非空なら内部制御状態を作って先頭要素を積み、空なら本体後へ移動します。`ArrayLoopNext`は次要素があれば積んで本体先頭へ戻り、なければ内部状態を破棄して反復後へ進みます。配列参照、添字、現在要素番号を利用者データスタックへ隠して保持しません。

命令トレースのソース位置は、`BuildArray`が対応する`【`、`ArrayLoopStart`が`各要素について`、`ArrayLoopNext`が`繰り返す`の開始位置です。`ArrayLoopStart`の`target`は反復後、`branchTaken`は空配列で`true`、非空配列で`false`です。`ArrayLoopNext`の`target`は本体先頭で、次要素がある場合は`true`、終了する場合は`false`です。

検査済みIRから要素型不一致、BuildArray個数不足、不正な反復状態が発生することはありません。合成不正IRは内部エラー終了コード70です。

## 11. トレース

ARRAY機能グループではBIND機能グループの21列を変更しません。配列反復状態は既存`controlBefore`・`controlAfter`へ次の形で加えます。

```text
[array:現在添字/長さ]
```

現在添字は本体へ渡している要素の0始まり添字です。入れ子制御状態は外側から内側へコンマで並べます。空配列の`ArrayLoopStart`では状態を作りません。

トレース上の配列値は`配列<T>:【…】`です。先頭8要素だけを表示し、9要素以上なら末尾に`…(+省略数)`を加えます。文字・文字列の各要素は値部分を先頭16 Unicodeコードポイントに制限し、超過時は`…`を加えます。制御文字は既存のTSV用エスケープを適用します。

非開示ポリシーでは`配列<T>:<redacted>`とし、長さや先頭要素も出しません。トレース用の省略・非開示処理は配列構築単位・要素処理単位へ数えず、トレースの有無で実行結果を変えません。
