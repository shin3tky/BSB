# ARRAY機能グループ: 配列診断と資源境界

> 本文は現行実装の規範契約です。
>
> [language-core-diagnostics.md](language-core-diagnostics.md)、[control-flow-diagnostics.md](control-flow-diagnostics.md)、[bindings-diagnostics.md](bindings-diagnostics.md)の形式、終了コード、100件上限を引き継ぎます。
>
> NARRAY機能グループ注記: [診断・資源境界](nested-arrays-diagnostics.md)により二次元配列を受理し、
> `E_NESTED_ARRAY_NOT_AVAILABLE`は三次元以上へ限定されました。本書の一次元配列診断は引き続き有効です。

## 1. 処理段階と順序

```text
UTF-8
字句
構文
名前・スコープ・初期化順序
型・スタック・制御フロー
IR
実行時
```

同じ段階では元ソースのUTF-8開始位置、同じ位置では診断コードの昇順です。構文エラーが1件でもあれば名前以降へ進まず終了コード9、静的エラーが1件でもあればIRを生成せず終了コード8です。

配列要素式は元ソース順に検査します。同じリテラルで要素値個数を確定できない場合、その要素から派生する型不一致と入れ子診断を抑止します。

## 2. 構文診断: 終了コード9

| コード | 条件 | 位置 | 主な情報 |
|---|---|---|---|
| `E_EXPECTED_ARRAY_ELEMENT` | 先頭・連続・末尾の要素区切りで空要素になる | 不正な区切りまたは終端のspan | 配列開始位置、要素番号 |
| `E_EXPECTED_ARRAY_END` | `】`より先に宣言・単語終端またはEOFへ達する | 欠落point | 配列開始位置、挿入候補 |
| `E_UNEXPECTED_ARRAY_END` | 対応する`【`がない`】` | `】`のspan | 実際の記号 |
| `E_EXPECTED_ARRAY_ELEMENT_TYPE` | `配列<>`で要素型がない | `>`のspanまたは欠落point | 期待するスカラー型 |
| `E_EXPECTED_ARRAY_TYPE_END` | 配列型の閉じ`>`がない | 欠落pointまたは実トークンspan | 開始位置、挿入候補 |
| `E_EXPECTED_LOOP_END` | 配列反復の`繰り返す`がない | 欠落point | `loopKind=配列`、開始位置 |
| `E_ARRAY_ELEMENT_NOT_ALLOWED` | 要素式に制御構文、宣言、代入がある | 最初の禁止要素のspan | 要素番号、要素名 |

配列終端の回復は、同じ配列深さの`】`、現在の宣言終端、制御中間・終端、`こと。`、次の有効なトップレベル開始を同期点とします。異なる配列や制御構文を暗黙に閉じません。

配列リテラルと制御構文の入れ子は共通の構文深さとして数えます。開始`【`と`各要素について`を各1段とし、深さ256を受理、257段目を既存の`E_SYNTAX_DEPTH_LIMIT`で拒否します。ARRAY機能グループの正常な配列内配列はありませんが、有限回復を保証するため構文深さには数えます。

## 3. 型構文・配列要素診断: 終了コード8

| コード | 条件 | 位置 | 主な情報 |
|---|---|---|---|
| `E_ARRAY_ELEMENT_TYPE_REQUIRED` | bare `配列`を具体型として使う | `配列`のspan | 使用文脈、許可要素型 |
| `E_EMPTY_ARRAY_TYPE_REQUIRED` | `【】`の要素型を確定できない | 配列全体のspan | 型付き空配列値の候補 |
| `E_ARRAY_ELEMENT_VALUE_MISSING` | 要素式の出口が空 | 要素区切りまたは終端span | 要素番号、実スタック |
| `E_ARRAY_ELEMENT_VALUE_COUNT` | 要素式の出口に2値以上ある | 要素区切りまたは終端span | 要素番号、実個数、実スタック |
| `E_ARRAY_ELEMENT_TYPE_MISMATCH` | 要素型が先頭要素の型と違う | 不一致要素全体のspan | 要素番号、期待型、実型、先頭位置 |
| `E_ARRAY_ELEMENT_CALL_NOT_ALLOWED` | 要素式から利用者単語または副作用単語を呼ぶ | 呼出しspan | 要素番号、単語、呼出し種類 |
| `E_NESTED_ARRAY_NOT_AVAILABLE` | 配列要素または配列型が配列になる | 内側の配列または型span | 予定段階 |

配列要素式内の純粋単語について、入力不足と入力型不一致には既存の`E_STACK_UNDERFLOW`と`E_TYPE_MISMATCH`を使います。`配列<小数>`は既存`E_FEATURE_NOT_AVAILABLE`です。

配列型の代入不一致は`E_ASSIGNMENT_TYPE_MISMATCH`、分岐・ループ・単語効果不一致は既存の対応診断を使い、配列専用の同義コードを増やしません。

## 4. 配列反復診断: 終了コード8

| コード | 条件 | 位置 | 主な情報 |
|---|---|---|---|
| `E_ARRAY_LOOP_INPUT_UNDERFLOW` | `各要素について`に入力値がない | 開始語のspan | 必要型、実スタック |
| `E_ARRAY_LOOP_INPUT_TYPE_MISMATCH` | 最上部が配列型でない | 開始語のspan | 必要型制約、実型、実スタック |
| `E_LOOP_STACK_MISMATCH` | 本体通常出口、脱出、継続が基準`S`でない | `繰り返す`または移行語のspan | `loopKind=配列`、経路、基準、実型列 |

配列入力を検査できなかった場合は本体由来の合流診断を抑止します。他の単語の検査は続けます。

## 5. 実行時診断: 終了コード10

| コード | 条件 | 位置 | 主な情報 |
|---|---|---|---|
| `E_ARRAY_INDEX_OUT_OF_BOUNDS` | 参照または置換の添字が`[0,N)`外 | 操作語のspan | 操作、添字、長さ、有効範囲 |
| `E_ARRAY_RANGE_OUT_OF_BOUNDS` | 一部取得または一部削除が`0 <= 開始 <= 終了 <= N`を満たさない | 操作語のspan | 開始、終了、長さ、有効条件 |
| `E_ARRAY_LENGTH_LIMIT` | 動的操作の結果長が65,536を超える | 操作語のspan | 上限、結果長、操作 |
| `E_ARRAY_CONSTRUCTION_LIMIT` | 1実行の配列要素構築単位が1,000,000を超える | 失敗する構築命令・操作語のspan | 上限、累計、要求量 |
| `E_ARRAY_ELEMENT_OPERATION_LIMIT` | 1実行の配列要素処理単位が10,000,000を超える | 失敗する命令・操作語のspan | 上限、累計、要求量 |

範囲外診断は実際に操作へ到達した場合だけ発生します。失敗する参照・置換・一部取得・追加・連結・逆順・検索はデータスタック、保存領域、標準出力、拒否された資源予算へ部分結果を残しません。既に完了した過去の出力と代入は巻き戻しません。

## 6. 警告と到達不能範囲

到達不能な配列リテラル、配列操作、配列反復には既存の`W_UNREACHABLE_CODE`だけを報告し、型、要素、範囲、反復合流の派生診断を抑止します。`format`は警告を出しません。

配列リテラルの区切り`、`は構造記号であり、助詞配置警告の対象ではありません。配列要素式中の通常助詞は従来どおりです。

## 7. 配列長上限

1配列の最大長は65,536です。上限を含みます。

- ソースの配列リテラルは65,536要素を受理する
- 65,537個目の要素を静的検査で認識した時点で`E_ARRAY_LENGTH_LIMIT`
- 最大長の配列への先頭・末尾追加、合計長が超過する連結は実行時に同じコード
- 一部取得と置換は入力長を超える結果を作らない

静的なリテラル超過では終了コード8、動的操作では終了コード10です。診断の`operation`フィールドをそれぞれ`literal`、`append`とします。

## 8. 配列要素構築単位

1回のrunで新しく配列へ格納する論理要素参照を「配列要素構築単位」として数え、累計1,000,000を上限とします。

| 操作 | 構築単位 |
|---|---:|
| `BuildArray` | リテラル要素数 |
| 型付き空配列 | 0 |
| 先頭・末尾追加 | 1 |
| 連結 | 第2配列の直接要素数 |
| 逆順 | 入力の直接要素数 |
| 要素置換 | 1 |
| 一部取得、端削除、一部削除、位置削除、重複除去 | 0 |
| 位置挿入 | 1 |
| 同じ値による構築 | 結果長 |
| 読み出し、安全な端取得、長さ、含有・検索、空判定、等価性、反復、表示 | 0 |

一部取得の0は、配列が不変であり論理的に既存要素を共有できることに基づきます。実装が内部コピーを選んでも外部予算を増やしません。要求分を加える前に上限を検査し、超過する操作全体を実行しません。

## 9. 配列要素処理単位

配列に比例する処理を1回の組み込み呼出しへ隠して既存命令上限を迂回しないため、1回のrunで10,000,000要素処理単位を上限とします。

| 操作 | 処理単位 |
|---|---:|
| BuildArray | 要素数 |
| 長さ | 1 |
| 参照、安全な端取得、置換、先頭・末尾追加、位置挿入、空判定 | 1 |
| 連結 | 第2配列の直接要素数 |
| 逆順 | 入力の直接要素数 |
| 含有・検索 | 比較した直接要素数に、既存の構造比較量を加えた値 |
| 一部取得、端削除、一部削除、位置削除 | 結果長 |
| 個数、開始位置付き検索、重複除去 | 実際に行った比較数と既存の構造比較量 |
| 同じ値による構築 | 結果長 |
| 等価性 | 実際に比較した要素数。長さ不一致は0 |
| 配列表示 | 表示した要素数 |
| 配列反復 | 本体へ渡した要素ごとに1 |

境界違反を先に判定できる操作は、処理開始前に全要求量を検査します。含有・検索は最初の一致までの比較結果と配列・JSON・バイト列の作業量を先に計測し、全予算を原子的に予約します。汎用の等価性は要素比較直前に1ずつ検査します。トレースの値整形はこの予算へ数えません。

## 10. IR命令数

`BuildArray`、`ArrayLoopStart`、`ArrayLoopNext`を各1命令として既存250,000命令上限へ数えます。リテラルの要素値を作る命令も従来どおり個別に数えます。要素数、要素型、反復飛び先、内部配列参照は命令として数えません。

250,000命令を受理し、250,001個目の命令オブジェクトを確保する前に既存`E_IR_LIMIT`とします。

## 11. トレース境界

配列値のトレースは先頭8要素を含み、9個目以降を`…(+N)`へまとめます。各文字・文字列要素は16 Unicodeコードポイントを含み、17個目以降を`…`にします。

非開示ポリシーでは要素型だけを型名として残し、値全体を`<redacted>`にします。この変換中に利用者コードを呼ばず、出力、実行命令、配列予算、保存値を変更しません。
