# WST-FILE機能グループ: 名前付き作業領域と複数ファイル

> 本文は現行実装の規範契約です。
>
> WST-TABLE機能グループのCSV/TSVは本仕様に含めません。統合草案
> [名前付き作業領域、ファイル、CSV/TSV](workspace-tables.md)と内容が異なる場合、
> 作業領域・ファイルについては本仕様を優先します。

## 1. 目的と範囲

WST-FILE機能グループは、BSBプログラムへ任意のOSパスを渡さず、実行ホストが明示的に登録した有限個の
ファイルだけを、名前付き`作業領域`と論理ファイル名で読み書きできるようにします。1実行で複数の
作業領域と複数のファイルを扱えます。

この機能グループに含めるものは次です。

- トップレベルの`作業領域`宣言と、語に付ける静的作業領域引数
- 論理ファイル名を通常の`文字列`値として渡す全内容読取りと原子的な全置換書込み
- 読取・書込それぞれの閉じた回復可能失敗型
- `workspace.resolve`、`file.read`、`file.write`能力
- 複数ファイルを注入する反復`--file`と単一の版1 TOML
- `explain --json`による作業領域宣言と静的能力要求の説明
- 操作回数、累積バイト数、取消、原子性、非開示の境界

この機能グループに含めないものは次です。

- BSB値としてのOSパス、URI、ファイル記述子、directory handle
- directory rootへの包括的権限、列挙、glob、再帰走査、監視
- 削除、名前変更、追記、部分読書き、streaming、locking
- 複数ファイルをまたぐtransactionまたはrollback
- CSV/TSV解析・直列化、文字コード自動判定、外部コマンド

ファイル層は`バイト列`だけを扱います。テキストにはBYTES機能グループの厳密UTF-8変換を明示的に使います。

## 2. 境界モデル

### 2.1 名前付き作業領域

作業領域は、同じ目的の有限ファイル登録をまとめるソース上の静的名です。作業領域そのものは通常値ではなく、
保存slotも持ちません。ソースは作業領域名を宣言し、ホストは同じ正規化済み名へ実行時定義を与えます。

ホスト定義はdirectoryではありません。各ファイルを次の組で個別に登録します。

```text
(作業領域名, 論理ファイル名) -> (不透明なホスト参照, read/write許可)
```

したがって、論理名から未登録の兄弟ファイルや親directoryへ到達する操作はありません。ホスト参照がOSパスで
あることは標準CLIの実装詳細であり、埋込みホストはmemory object等を使えます。

### 2.2 論理ファイル名

論理ファイル名はBSBの`文字列`値で、次をすべて満たす単一の可搬名です。

- NFC正規化済みのUnicodeスカラー値列
- UTF-8で1〜255バイト
- `/`、`\`、NUL、U+0001〜U+001F、U+007Fを含まない
- `.`または`..`ではない

一致はUnicodeスカラー値列の完全一致です。OSの大小文字、正規化、localeの規則を適用しません。ホスト設定内の
OSパスはこの論理名規則を受けませんが、BSB入力、診断、trace、説明JSONへ公開しません。

### 2.3 複数ファイルの意味

1実行で異なる作業領域、同じ領域内の異なる論理名、同じ登録への複数回操作を許します。各操作は実行時に
独立して解決・認可します。ソース順の操作順序を維持し、自動並行実行、自動再試行、cacheを行いません。

書込成功はその1ファイルについて確定し、後続操作の失敗で戻しません。複数ファイルを一括commitする意味は
ありません。同じ物理対象を複数の登録が指すaliasはホスト責任であり、BSBは検出も特別扱いもしません。

## 3. ソース構文

### 3.1 宣言

```text
帳票は 作業領域。
```

文法はCONN機能グループの論理接続宣言と同じトップレベル規則を使います。

```text
program              := (wordDefinition | globalDeclaration
                         | logicalConnectionDeclaration
                         | workspaceDeclaration | trivia)* EOF
workspaceDeclaration := identifier immediately-followed-by "は"
                         separator+ "作業領域" separator* "。"
```

初期値は持ちません。トップレベル以外の宣言、値を伴う宣言、重複名、予約名、隠蔽は
[診断仕様](workspace-files-diagnostics.md)の順で処理します。論理接続、利用者定義語、大域値、
他の作業領域と同じ大域名前空間を共有します。前方参照を許します。

1ソースの作業領域宣言は10,000個までです。論理接続10,000個、値束縛10,000個とは別に数えます。

### 3.2 静的な作業領域引数

```text
「入力.dat」を ファイルを読む<帳票>
「出力.dat」と 結果のバイト列を ファイルへ書く<帳票>
```

`<帳票>`は正規語の直後に空白なしで置く静的引数です。ちょうど1個の作業領域宣言だけを指定でき、文字列、
値束縛、論理接続、型名は指定できません。正規形は次です。

```text
ファイルを読む<帳票>
ファイルへ書く<帳票>
```

作業領域名を通常の本体名、値、配列要素、型位置に書いても値にはなりません。構造的に到達不能な呼出しは
既存の到達不能規則に従い、能力要求へ含めません。

## 4. 型、語、辞書順

次の2具体型を追加します。

- `ファイル読取失敗`
- `ファイル書込失敗`

どちらも処理系だけが構築する閉じた不変値です。保存、分岐合流、`任意`・`結果`の型引数には使えますが、
表示、等値比較、配列要素には使えません。論理ファイル名、OSパス、例外、部分内容を保持しません。

NARRAY機能グループ完了時の155組み込み語の末尾へ、次の4語をこの順で追加します。

```text
ファイルを読む<作業領域> (文字列 -- 結果<バイト列,ファイル読取失敗>)
ファイルへ書く<作業領域> (文字列 バイト列 -- 結果<整数,ファイル書込失敗>)
ファイル読取失敗の種類を取り出す (ファイル読取失敗 -- 文字列)
ファイル書込失敗の種類を取り出す (ファイル書込失敗 -- 文字列)
```

別名はありません。4語とも`featureGroup`は`"WST"`、`typeRule`は`fixed`、
`returnsNormally`は`true`です。読取語の能力・副作用は`workspace.resolve`と`file.read`、書込語は
`workspace.resolve`と`file.write`です。取出し語は純粋です。

`作業領域`、2失敗型名、4語名を予約します。個々の作業領域名は言語全体の予約名には加えません。

## 5. 読取・書込契約

### 5.1 読取り

`ファイルを読む<作業領域>`は論理ファイル名を1個消費し、登録先の全内容を1回読みます。成功は外部変更から
独立した不変`バイト列`です。空ファイルは長さ0の成功です。別processによる同時変更に対するsnapshotや
lockingは保証しません。

回復可能な`ファイル読取失敗`の種類は次だけです。

| 種類 | 条件 |
|---|---|
| `notFound` | 登録先が操作時に存在しない |
| `notRegularFile` | 登録先の最終componentが通常ファイルでない |
| `tooLarge` | 作業領域の1回読取上限を超えることが確定した |
| `ioFailure` | 安全に細分類できない読取I/O失敗 |

成功値または閉じた失敗値だけを返し、部分内容は返しません。内容の不正UTF-8はファイル読取失敗ではなく、
後続の厳密UTF-8復号の失敗です。

### 5.2 書込み

`ファイルへ書く<作業領域>`は論理名と`バイト列`を消費し、登録先全体を置き換えます。成功整数は公開した
内容のバイト数です。

ホストは登録先と同じ親領域に一時内容を完成させ、全バイトの書込みが成功した後だけ、同じ登録先へ1回の
原子的置換で公開します。新規targetの作成を許します。公開前の失敗では既存targetを変更しません。
原子的置換を保証できないホストは通常moveや直接上書きへfallbackしません。

回復可能な`ファイル書込失敗`の種類は次だけです。

| 種類 | 条件 |
|---|---|
| `parentNotFound` | 登録先の親が操作時に存在しない、またはdirectoryでない |
| `targetNotRegularFile` | 既存targetの最終componentが通常ファイルでない |
| `tooLarge` | 作業領域の1回書込上限を超える |
| `atomicReplacementUnavailable` | 同じ登録先への原子的公開を保証できない |
| `ioFailure` | 安全に細分類できない書込I/O失敗 |

最終componentのsymbolic linkは通常ファイルとして扱わず、読取では`notRegularFile`、書込では
`targetNotRegularFile`です。親pathの解決はホスト設定責任です。標準JDK能力が保証するのは操作時の
最終componentを追わないことまでとし、外部processが検査と操作の間に行う敵対的なpath差替えへの耐性は
初版の保証に含めません。

成功は同じホスト能力から新内容全体を観測可能になったことを表します。停電耐久性、page cacheのflush、
metadataの維持、一時資源削除の個別結果は保証しません。

### 5.3 失敗種類の取出し

2個の取出し語は上表のASCII識別値だけを返します。再試行可能性を自動判定せず、OS例外、errno、path、
元の論理名を返しません。

## 6. ホスト能力

### 6.1 能力名と解決

次の平坦な能力を追加します。

```text
workspace.resolve
file.read
file.write
```

各操作は`workspace.resolve`をちょうど1回呼びます。入力は正規化済み作業領域名と`read|write`です。
応答は次の閉じた状態です。

| 状態 | 意味 |
|---|---|
| `RESOLVED` | 不透明な作業領域参照と、操作別の1ファイル上限を返す |
| `NOT_CONFIGURED` | ソース宣言に対応するホスト定義がない |
| `DENIED` | ホストが作業領域の操作全体を拒否した |
| `INVALID` | 埋込みホストの定義が能力契約を満たさない |

`RESOLVED`後、readまたはwrite能力を高々1回呼びます。入力は不透明な作業領域参照、論理名、実効上限、
書込時だけ全バイトです。応答は未登録、登録の操作不許可、取消、各回復可能失敗、成功の閉じた状態です。
自動retryは0回です。

null、未知状態、要求と異なる名前・操作・不透明参照、上限を越えた成功、読取の部分成功、書込成功バイト数の
不一致は能力契約違反です。終了70の既存`E_CAPABILITY_FAILURE`にし、自由な能力例外を公開しません。

### 6.2 パラメータ付き能力と説明

資源種別`workspace`と操作順`resolve, read, write`を追加します。読取は同じ作業領域へ`resolve`と`read`、
書込は`resolve`と`write`を要求します。同一利用者語と推移要求の重複は統合します。

`explain --json`は外側版1と`parameterizedCapabilities`内側版1を維持します。既存`declarations`は
論理接続宣言のままとし、加算的な`workspaceDeclarations`をソース順で追加します。
`summaryRequirements`と各利用者語の要求には`kind: "workspace"`を追加します。実行時論理名、登録一覧、
access、上限、OSパス、内容は推測掲載しません。

## 7. 標準CLIからの注入

### 7.1 直接指定

`run`のソース引数より前で、4引数の`--file`を反復できます。

```text
bsb run \
  --file <作業領域名> <論理ファイル名> <read|write|read-write> <OSパス> \
  [--file ...] [--connections <接続.toml>] <ソース.bsb> -- [引数...]
```

例です。

```text
bsb run \
  --file 帳票 入力.dat read ./data/input.dat \
  --file 帳票 出力.dat write ./out/result.dat \
  transform.bsb -- 入力.dat 出力.dat
```

反復は1〜4,096件です。同じ正規化済み作業領域名と完全一致論理名の組を重複指定できません。相対OSパスは
CLI processの開始時作業directoryを基準に、設定読込み時に1回だけ絶対正規化pathへ変換します。
symbolic linkの実path解決は行いません。直接指定の操作別上限は各16,777,216バイトです。

### 7.2 TOML版1

```text
bsb run --workspaces <設定.toml> [--connections <接続.toml>] <ソース.bsb> -- [引数...]
```

```toml
schema-version = 1

[workspaces."帳票"]
maximum-read-bytes = 16777216
maximum-write-bytes = 16777216

[workspaces."帳票".files."入力.dat"]
path = "../data/input.dat"
access = "read"

[workspaces."帳票".files."出力.dat"]
path = "../out/result.dat"
access = "write"
```

TOMLは1,048,576バイト以下、BOMなしの厳密UTF-8、TOML 1.0です。トップレベルは
`schema-version`と`workspaces`だけです。作業領域は1〜256、全登録は1〜4,096件です。作業領域名は
ソース識別子と同じ正規化・長さ規則、論理名は第2.2節、`access`は`read|write|read-write`だけです。

`maximum-read-bytes`と`maximum-write-bytes`は各作業領域で省略でき、既定値は16,777,216、範囲は
1〜67,108,864です。その領域の全登録へ操作別に適用します。各登録は`path`と`access`だけを必須で持ちます。
未知key、重複key、重複登録、型違い、空path、NULを含むpathを拒否します。相対pathは設定TOMLの
絶対正規化済み親directoryを基準に、設定読込み時に1回だけ絶対正規化pathへ変換します。

### 7.3 共通の設定境界

`--file`と`--workspaces`は相互排他です。`--connections`とは併用でき、ソースより前ならoption順は任意です。
`--workspaces`と`--connections`は各1回だけです。自動探索、複数TOMLのmerge、include、profile、環境変数・
tilde・glob展開、上書き規則はありません。

設定はプログラムの構文検査・実行より前に全件検証し、不正ならstdout 0バイト、終了78の
`作業領域設定エラー`にします。利用者が明示した設定TOMLのpathはCLI使用法の対象として表示できますが、
登録先path、TOML入力行、parser自由文は表示しません。設定にソース未宣言の作業領域があっても許可し、
ソース宣言に設定がない場合は実行時`E_WORKSPACE_NOT_CONFIGURED`です。

## 8. JDKファイル能力

標準CLI能力は設定時に固定した単一pathだけを操作します。読取は最終componentをlink追跡なしで検査し、
実効上限+1バイトまでのbounded readで完全成功または超過を決めます。属性sizeだけを成功判定に使わず、
読取中に増えたファイルも上限+1で検出します。

書込は既存targetと親を検査し、同じ親に推測困難な名前の一時通常ファイルを新規作成します。全バイトの書込みと
closeに成功した後、`ATOMIC_MOVE`と置換を要求してtargetへ1回公開します。atomic moveが使えなければ
`atomicReplacementUnavailable`です。全経路で一時ファイル削除を試みますが、公開前失敗時のtarget不変を
優先し、cleanup失敗のpathや例外を公開しません。

適合試験は不変な偽能力を規範oracleとします。JDK能力は一時directoryだけの統合試験で確認し、利用者home、
repository外、実権限変更、外部process、OS固有のsymbolic link作成を中央適合の必須条件にしません。

## 9. 資源上限と判定順

| 資源 | 上限 |
|---|---:|
| 1ソースの作業領域宣言 | 10,000 |
| 1実行の受理済みファイル操作 | 4,096 |
| 1回の読取・書込方針 | 1〜67,108,864バイト |
| CLI直接指定時の既定方針 | 16,777,216バイト |
| 1実行の読取成功バイト累積 | 134,217,728バイト |
| 1実行の書込試行バイト累積 | 134,217,728バイト |
| 1値のバイト列 | 67,108,864バイト（既存） |

操作回数は両能力の存在確認後、resolver前に1回予約します。予約に失敗した操作は加算しません。予約後の
未設定、拒否、未登録、操作不許可、物理失敗でも操作回数は戻しません。

読取では累積残量と方針上限の小さい値を実効上限とします。残量0でも空ファイルを区別できるよう能力は
0+1バイトのprobeを実行できます。完全内容が実効上限内なら、その実バイト数を読取累積と既存バイト列構築
予算へ成功前に一括予約します。実効上限超過を観測した場合、累積残量が方針上限以下なら
`E_FILE_READ_TOTAL_LIMIT`、それ以外は`tooLarge`です。超過probeや拒否された予約を読取累積へ加算せず、
部分内容も返しません。

書込では操作回数と本文全量の書込試行累積を両能力の存在確認後、resolver前に原子的に予約します。予約失敗時は
どちらも加算しません。予約成功後は未設定、拒否、未登録、操作不許可、方針`tooLarge`、物理失敗でも戻しません。
既存バイト列の1値上限は入力値の不変条件として先に成立済みです。

共通の判定順は、命令・能動時間、入力型と内部不変条件、能力存在、操作・累積予約、workspace解決、登録と
認可、file能力、閉じた応答検査、結果用資源、stack置換です。I/O待機は30秒の能動実行時間から除外しますが、
命令、操作回数、累積上限は適用します。取消は`E_FILE_CANCELLED`であり失敗値へ変換しません。

捕捉不能診断では入力stack、保存値、stdout、stderrを変更しません。ただし能力委譲済みの外部読取り、公開済みの
1ファイル書込み、受理済み予算は戻しません。公開後に結果用stack上限で失敗しても物理書込みは戻しません。

## 10. 非開示

次を診断message・fields・expected・actual・fixes・relatedLocations・`dataStack`、通常trace、能力event、
`explain --json`、設定エラーへ含めません。

- 登録先OSパス、実path、URI、親directory、一時ファイル名
- 登録済み・未登録を問わない論理ファイル名
- ファイル内容、部分内容、接頭辞、hash
- ホスト例外型・本文・stack trace、errno、権限、所有者、時刻

失敗値は通常traceで`ファイル読取失敗:<redacted>`または`ファイル書込失敗:<redacted>`です。`バイト列`と
入れ子の`任意`・`結果`は既存の推移的非開示を継承します。能力eventは能力名、既定では作業領域名、操作、
閉じた結果だけを持てます。より強いホスト方針は作業領域名も伏せられます。

失敗取出し語で得た種類と、読取後に利用者が明示変換した値は通常値です。ファイル由来taintは保持しないため、
内容をtraceへ出したくないホストはtrace無効化またはより強い値伏字方針を選びます。

## 11. 後方互換性と後半への境界

既存ソース、外側版1 JSON、論理接続、接続TOMLの意味は変更しません。WST-FILE機能グループの公開追加は2型、4語、
3能力、資源種別`workspace`、`workspaceDeclarations`、CLI optionだけです。

WST-TABLE機能グループのCSV/TSVは本仕様のfile bytesを厳密UTF-8で文字列へ変換した後に扱います。後半は
