# RESULT機能グループ: `結果<T,E>`値

> 本文は現行実装の規範契約です。
>
> ここで明示する追加以外は、先行する実装済み機能グループの契約を維持します。
> [診断](result-values-diagnostics.md)および[適合性](result-values-conformance.md)と一体です。

## 1. 範囲と失敗の意味

`結果<T,E>`は、成功値を1個持つ`成功(T)`または失敗値を1個持つ`失敗(E)`の不変な具体型です。
両方を同時に持つ状態、どちらも持たない状態、暗黙のnull状態はありません。
`E`は通常の具体型であり、Java例外、処理系の`Diagnostic`、終了コードではありません。

この機能グループでは値の構築・判定・取出し・破棄・保存・合流・表示・比較・トレースを提供します。
既存語の失敗捕捉、JSON解析の結果版、共通エラー型、HTTP、認証、取消、再試行は追加しません。
既存語の戻り型も変更しません。たとえば`JSONを解析する`の失敗は引き続き実行時診断であり、
後ろへ`成功にする`を置いても捕捉されません。資源超過やホスト内部失敗を`失敗(E)`へ変換しません。

`失敗(E)`は正常に生成・保存・受渡しできる値です。構築しただけでは診断、stderr、終了10、
スタック巻戻し、早期復帰を起こしません。利用者が判定・分岐し、必要なら既存の`戻る`や
`終了する`を明示します。後続の[任意・結果の合成](optional-result-composition-diagnostics.md)が追加する局所伝播を
利用者定義単語内で使うこともできます。結果値を残したまま`メイン`を終えることは、既存の`（--）`契約違反です。

## 2. 型構文、名前、深さ

```text
type       := simpleType | "配列" "<" type ">" | "任意" "<" type ">"
            | "結果" "<" type "," type ">"
resultType := "結果" "<" concreteType "," concreteType ">"
```

`T`・`E`は独立した具体型で、同型でも構いません。双方に現行10スカラー型、許可済みの
1次元配列、任意型、結果型を置けます。引数の順序は常に成功型、失敗型です。

```text
結果<整数,文字列>
結果<整数,整数>
結果<配列<JSON>,正規表現>
結果<任意<JSON>,文字列>
任意<結果<整数,文字列>>
結果<結果<整数,真偽>,結果<文字列,JSON>>
```

`配列<結果<T,E>>`と`配列<任意<T>>`は具体型として利用できます。ラッパー越しを含む配列型構築子は
各経路で最大2個です。
型制約、未知型、裸の`結果`、引数不足・過剰は具体型になりません。
利用者定義の型変数、型別名、ジェネリック単語は導入しません。

RESULT機能グループで`結果`、辞書専用型制約`E`、第4節の7正規語を予約します。既存の`T`等と同じく
`E`もソースの型位置では`E_TYPE_CONSTRAINT_NOT_ALLOWED`です。`成功`・`失敗`は説明上の
状態名であって単独リテラルでも新しい予約名でもありません。従来これら9個の新予約名を
利用者定義していたソースだけは名前の移行が必要です。既存予約名の意味は変えません。

型深さはスカラーを0、`配列<S>`を1、`任意<A>`を`1 + depth(A)`、
`結果<A,B>`を`1 + max(depth(A), depth(B))`とします。総ノード数や左右の深さの和ではなく、
根から葉までの最大構築子数です。上限256を左右両方に適用し、257段目の構文構築子へ入る前に
`E_SYNTAX_DEPTH_LIMIT`で拒否します。型付き構築呼出しも出力の`結果`1段を数えます。

型注釈だけでなく推論される型にも256段上限を適用します。たとえば深さ256の結果値を
`任意にする`で包もうとする場合、静的な`E_TYPE_DEPTH_LIMIT`です。Java例外や実行時失敗に
任せません。制御構文の深さとは独立です。型名、同一性、ハッシュ、型特性の検査は、
任意と結果が混在してもJava呼出しスタックへ依存せず停止するものとします。

### 2.1 区切りと標準形

型引数の区切りはASCIIの`,`だけです。標準形は空白なしの`結果<整数,文字列>`です。
`<`・`,`・`>`の前後には既存の空白と改行を許します。`、`・`，`は既存の区切りであり、
型引数を区切る`,`の代わりにはなりません。たとえば`結果<整数、文字列>`は区切り不足です。
型名の既存Unicode正規化は維持し、全角山括弧は追加しません。

ASCIIの`,`は、`結果<...>`または第3節の構築呼出しの型引数枠に属するときだけ新たに
トークンとして受理し、トークン上限へ1個と数えます。リテラル・コメント内は従来どおりです。
それ以外では従来の不正文字／不正候補の診断を維持し、一般の区切りや配列区切りへ昇格しません。
入れ子の区切りは最内側の型引数枠へ所属させます。単引数の`任意`・`配列`内部で`,`を
追加受理する拡張はしません。型引数枠は不正入力でも定義・宣言境界を越えて残しません。

型引数内のコメントは禁止し、`E_COMMENT_NOT_ALLOWED`を使います。既存のスタック効果内の
コメント禁止も維持します。`format`は意味解析や型推論を行わず、構文が有効なら未知型や
型不一致を含んでも整形します。成功時はBOMなしUTF-8、LF、入力非変更、冪等とします。

## 3. 明示型付き構築呼出し

```text
resultConstruction := ("成功にする" | "失敗にする") "<" type "," type ">"
```

```text
42 を 成功にする<整数,文字列>
「not-found」を 失敗にする<整数,文字列>
```

どちらも同じ`結果<整数,文字列>`を返します。成功構築はスタック最上部の`整数`だけを、
失敗構築は`文字列`だけを消費します。存在しない側のダミー値は生成も評価もしません。

両引数の明記を必須とします。入力からの片側推論、周囲の出力宣言からの逆向き推論、
分岐の他方との単一化、暗黙の失敗型`文字列`は採用しません。この選択により、定数の初期値など
期待型のない場所でも同じ規則で構築できます。余分な値や実行時の型証拠をスタックへ積みません。

構築語と`<`の間にも既存の空白・改行は置けますが、コメントは置けません。標準形では密着させます。
本体、制御ブロック、純粋な宣言初期値、既存の配列要素式で同じ呼出し構文を認識します。
配列要素式では、同じ具体的な`結果<T,E>`を各要素が残す配列も構築できます。
助詞は型引数の外側でのみ既存どおり扱い、引数内に助詞を入れません。

これは構築2語だけに付随する静的情報です。他の組み込み語や利用者定義語への型引数適用を
一般化しません。型引数はASTに保持し、解決後の具体的な入力・出力型をCallとIRへ保存します。
実行時は検証済みの出力型から非選択側の型も得ます。入力値だけから結果型を再推論しません。

## 4. 公開組み込み語

辞書は次の順で既存112語の後ろへ7語を追加し、119語になります。別名は追加しません。
表の`<T,E>`は構築呼出しに必要な付加構文であり、辞書の正規語名そのものには含めません。

| 正規語 | 呼出し表記 | 辞書スタック効果 | 公開型規則 |
|---|---|---|---|
| `成功にする` | `成功にする<T,E>` | `T -- 結果<T,E>` | `resultSuccessWrap` |
| `失敗にする` | `失敗にする<T,E>` | `E -- 結果<T,E>` | `resultFailureWrap` |
| `結果が成功である` | 正規語のみ | `結果<T,E> -- 結果<T,E> 真偽` | `resultPredicate` |
| `結果が失敗である` | 正規語のみ | `結果<T,E> -- 結果<T,E> 真偽` | `resultPredicate` |
| `結果から成功値を取り出す` | 正規語のみ | `結果<T,E> -- T` | `resultSuccessUnwrap` |
| `結果から失敗値を取り出す` | 正規語のみ | `結果<T,E> -- E` | `resultFailureUnwrap` |
| `結果を捨てる` | 正規語のみ | `結果<T,E> --` | `resultDrop` |

判定2語は元の結果値を残し、互いに反対の真偽値を返します。取出しはラッパーを消費し、
選択側の値を返します。反対側の取出しは`E_RESULT_STATE_MISMATCH`です。
破棄は状態や内包値を観測せず結果値を消費します。判定後も静的型は変わらず、
状態による到達可能経路の消去は行いません。

7語は純粋で能力・副作用は空、`featureGroup="RESULT"`、`returnsNormally=true`です。
構築以外の5語は入力結果型から`T`・`E`を呼出しごとに具体化します。
構築2語の辞書例は第3節の2例、残り5語の例は順にその成功例へ成功判定、失敗例へ失敗判定、
成功例へ成功取出し、失敗例へ失敗取出し、成功例へ破棄を続けたものとします。

## 5. 保存、合流、任意値との合成

定数、変数、局所保存、引数・戻り値、再帰、早期復帰、分岐、ループに使えます。
`結果<A,B>`と`結果<C,D>`は`A=C`かつ`B=D`の場合だけ同じ型です。不変で共変ではありません。
成功と失敗は同じ型へ合流しますが、非選択側だけが違っても型不一致です。
同型の変数を成功から失敗へ更新できます。内包値は複製せず共有し、元の保存値を変更しません。

`結果<任意<JSON>,文字列>`では次の状態を区別します。

| 状態 | 意味 |
|---|---|
| `成功(ある(JSON文字列))` | 処理が成功し、値がある |
| `成功(ある(JSONヌル))` | 処理が成功し、正当なJSONヌルがある |
| `成功(ない)` | 処理は成功したが、非必須値が欠落している |
| `失敗(文字列)` | 利用者が明示した検証失敗等 |

`任意<結果<T,E>>`も別の型として許します。結果と任意の暗黙変換、失敗を`ない`へ変換する語、
単独`ない`の型付き構築、エラーを捨てる暗黙のflattenは追加しません。

## 6. 表示、等価性、トレース

結果型が表示可能なのは`T`と`E`の両方が表示可能なときだけです。等値比較可能性も両方を要求します。
実際の状態ではなく型全体の性質とし、非選択側が正規表現・入力結果・日時である場合も制約違反です。
任意・結果の混在は全ての型引数を検査します。型不一致の実型は結果型全体の正規名です。

同型結果の等価比較は、状態が異なれば偽、同じなら選択側の内包値の等価性に従います。
成功値と失敗値のペイロードが同じでも等しくありません。JSONの構造比較、小数の数値比較、
文字列・配列の既存規則を継承します。値のJava同一性や表示文字列で比較しません。

正規表示は`成功（42）`、`失敗（not-found）`、`成功（ある（null））`です。
括弧は全角、状態名と括弧の間に空白はなく、内包値は既存の表示形式です。
この表示は再解析できるリテラルやJSON符号化ではありません。

通常トレースは必ず型名を示します。開示可能なら`結果<整数,真偽>:成功(42)`のように
半角括弧で状態と値を表し、末端値の32コードポイント、配列の8要素・文字列要素16コードポイント、
制御文字エスケープはOPT機能グループの制限を継承します。ラッパー分は別で、型深さ256により有限です。

既定の非開示判定は**非選択側も含む全型引数**へ推移的に適用します。たとえば
`結果<整数,文字列>`は成功42であっても`結果<整数,文字列>:<redacted>`です。
文字列、JSON、入力結果、それらの配列・任意・結果を含む型は、状態を含む結果全体を伏せます。
ホストのより厳しいポリシーがラッパーまたは選択側の内包値を拒否する場合も全体を伏せます。
保存前後のトレースにも同じ規則を使い、トレースによる予算消費・能力呼出しは追加しません。

これはトレースの非開示規則であり、情報フロー型システムではありません。利用者が明示的に判定・
取出し・表示した情報までは自動秘匿しません。状態不一致診断も状態名だけは示しますが、
ペイロードをメッセージ、fields、expected、actual、fix、relatedへ複写しません。

## 7. 資源と原子性

1結果値はデータスタック・保存領域で1値です。構築はラッパー1個を作り、選択側の不変値を
共有します。7語は各1 Call命令であり、独立した結果値作業／構築予算は追加しません。
判定は真偽1値を追加する前にデータスタック上限を検査します。

表示・比較は選択側へ同じ操作を直接行った場合の配列・JSON作業課金を継承します。
異状態比較はペイロードを調べず、追加作業0です。同状態比較では任意の`ない`など、
既存の短絡条件で止まります。存在しない側を走査・課金してはなりません。
表示はラッパーも含むUTF-8バイト数をstdout／stderrの各出力上限へ数え、
JSON内包値の直列化上限とJSON作業予算も維持します。

状態不一致、判定のスタック超過、表示・比較の事前検査失敗では入力スタック、保存値、
プログラムstdout/stderr、拒否された予算予約を変更しません。既に成功した先行命令・
配列要素の課金は既存規則どおり戻しません。命令予算の数え方も維持します。
表示時の能力委譲前検査と、物理出力の部分書込みを巻き戻せない境界はIO機能グループに従います。
既存の診断失敗を結果値で置き換えて原子性や上限を回避してはなりません。

最大ヒープ512 MiBを維持します。深い型だけでなく幅のある2分岐型、選択側が深い値、
非選択側だけが深い型、任意との交互入れ子を試験します。新しい型ノード総数予算は設けず、
ソース・トークン・出力等の既存上限を使います。型の参照共有を展開して指数的な中間構造を
作らず、走査量と型名生成の一時領域を入力構造に対して抑えます。

## 8. 公開互換性

`check --json`と`explain --json`の`schemaVersion=1`を維持します。新規診断と第4節の語・
型規則・型名のみを追加し、既存メンバーの意味は変えません。`builtinWords.name`は
`成功にする`等の正規語名、`example`は型付き表記、利用者語と束縛の型名は具体型です。
公開説明へ新たなASTや呼出しごとの型引数配列は追加しません。具体化済みCallの確認は
analyzer／IRの内部試験が受け持ちます。既存112語の辞書順、能力・副作用の順序を保ちます。

OPT機能グループ以前の適合期待は、公開辞書全体の追加7語、新予約名、新しい推論型深さ診断という
明示した差分だけを個別にレビューします。既存の必須JSON取得、非必須検索、数値、配列、
任意値だけのformat・実行・診断・トレースをまとめて新実装の出力へ置き換えてはなりません。
