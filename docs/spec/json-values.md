# JSON機能グループ: 第一級JSON値

> 本文は現行実装の規範契約です。
>
> 先行する実装済み機能グループの規則は、ここで明示的に変更する箇所以外、引き続き有効です。

## 1. 範囲と標準

JSON機能グループでは、文字列の別名ではない第一級の`JSON`型を追加します。JSON文字列の厳密な解析、
コンパクトJSONへの決定的な直列化、BSBスカラーとの明示変換、値種別検査、JSON配列と
JSONオブジェクトの不変操作を提供します。

JSON文法の基準は[RFC 8259](https://www.rfc-editor.org/rfc/rfc8259)です。BSBは相互運用性と
決定性のため、同仕様が許容または未規定とする部分を次のように狭めます。

- オブジェクトの重複キーをエラーにする
- 入力BOMを受理しない
- JSON文字列をUnicodeスカラー値列に限定し、孤立サロゲートを受理しない
- 数値を2進浮動小数へ変換せず、整数と正確な10進小数を区別する
- 入れ子、要素数、メンバー数、ノード数、数値、入出力長、累積作業量に規範上限を設ける
- 直列化は1つの決定的なコンパクト表記を返す

JSONリテラルのBSBソースへの直接記述、JSON Pointer、JSONPath、JSON Schema、`任意<T>`、
HTTPS、ファイル入出力はJSON機能グループに含めません。

## 2. 型と値

`JSON`は次の7種を内部に保持する1つの具体型です。

```text
JSON値 := JSONヌル
        | JSON真偽
        | JSON整数
        | JSON小数
        | JSON文字列
        | JSON配列
        | JSONオブジェクト
```

7種は実行時の値種別であり、利用者定義単語のスタック効果へ`JSON配列`や`JSONオブジェクト`を
型として書けません。静的型は常に`JSON`です。必要な値種別は判定語または必須変換語で検査します。

`JSON`は具体的なスカラー型であり、次を許します。

- 定数、変数、大域・局所保存、利用者定義単語の入出力
- 分岐・ループのスタック合流
- `等しい`による構造的比較
- `表示する`と`一行表示する`によるコンパクトJSON出力
- BSB配列の要素型`配列<JSON>`

`JSON`、`JSONヌル`、`空のJSON配列`、`空のJSONオブジェクト`、第11節の全組み込み語は
予約名です。`JSON配列`と`JSONオブジェクト`も将来の構文・説明用に予約を維持しますが、
JSON機能グループでは具体型名でも呼出し可能な単語名でもありません。

## 3. 各値種別

### 3.1 JSONヌル

JSONの`null`を正当なJSON値として保持します。トップレベル、配列要素、オブジェクト値の
いずれでも受理します。通常のBSB型はnull非許容であり、JSONヌルを`文字列`、`整数`などへ
暗黙変換しません。

### 3.2 JSON真偽

JSONの`true`と`false`を保持します。BSBの`はい`と`いいえ`との変換は明示的です。

### 3.3 JSON整数

小数点と指数部を持たないJSON数値を、符号つき任意精度整数として保持します。`-0`は値0へ
正規化しますが、JSON整数という値種別は保持します。直列化結果は`0`です。

### 3.4 JSON小数

小数点または指数部を持つJSON数値を、正確な10進小数として保持します。係数末尾の0と負の0は
NUM機能グループの`小数`と同じく値から除きますが、JSON小数という値種別は保持します。

| 入力 | 値 | 直列化 |
|---|---|---|
| `-0.0` | JSON小数の0 | `0.0` |
| `1.2300` | JSON小数の1.23 | `1.23` |
| `1e2` | JSON小数の100 | `100.0` |
| `1E-2` | JSON小数の0.01 | `0.01` |

JSON整数とJSON小数は数値として同じ大きさでも異なる値種別です。したがって`1`と`1.0`は
`等しい`で`いいえ`です。BSBの`整数`と`小数`の間にも暗黙変換を設けません。

### 3.5 JSON文字列

JSON文字列はUnicodeスカラー値列です。JSONのキーを含め、識別子用の全角英数字変換、NFC、
NFKC、大小文字変換を適用しません。例えばU+00E9と`e`+U+0301は異なる文字列です。

### 3.6 JSON配列

JSON配列はJSON値の順序つき不変列です。異なる値種別を混在でき、入れ子のJSON配列・
JSONオブジェクトも保持できます。位置は0始まり、範囲は終端を含まない半開区間です。

JSON配列はBSBの同種1次元配列`配列<JSON>`とは別の表現です。両者は第11節の明示変換で
相互に変換します。JSON配列から`配列<JSON>`へ変換した後は、既存の`各要素について`と
16個のBSB配列操作語を使用できます。

### 3.7 JSONオブジェクト

JSONオブジェクトは、JSON文字列キーからJSON値への不変な対応です。解析時と構築時の挿入順を
保持し、キー一覧と直列化はその順を使います。

- 同じUnicodeスカラー値列のキーを1オブジェクト内に2回置けない
- 既存キーの設定は値だけを置き換え、キー位置を変えない
- 新規キーの設定は末尾へ追加する
- 削除は残りのキーの相対順を変えない
- キー順が異なっても同じキーと等しい値の対応なら、オブジェクト値としては等しい

## 4. JSONテキストの解析

`JSONを解析する (文字列 -- JSON)`は、入力文字列全体を1個のJSONテキストとして解析します。
先頭と末尾には規定JSON空白を置けますが、JSON値の後に別の値や非空白を置けません。

### 4.1 空白

JSON空白として受理するのは次の4文字だけです。

| 文字 | コードポイント |
|---|---|
| space | U+0020 |
| horizontal tab | U+0009 |
| line feed | U+000A |
| carriage return | U+000D |

BOM U+FEFF、全角空白、NBSP、その他のUnicode空白、コメントを受理しません。

### 4.2 リテラル

`null`、`true`、`false`はASCII小文字の完全一致だけを受理します。大文字、全角文字、
省略、後続識別子文字を受理しません。

### 4.3 数値

入力文法は次です。

```text
number   := minus? int frac? exp?
minus    := "-"
int      := "0" | nonzero digit*
frac     := "." digit+
exp      := ("e" | "E") ("+" | "-")? digit+
digit    := "0".."9"
nonzero  := "1".."9"
```

正符号を数値先頭へ置けません。不要な先頭0、数字の区切り、16進数、`NaN`、`Infinity`を
受理しません。入力数字は符号、小数点、指数記号、指数符号を除いて4,096桁以下です。
指数と正規化後スケールは、巨大な`BigDecimal`や巨大中間文字列を作る前に検査します。

### 4.4 文字列

未エスケープで置けるのは、U+0020以上の`"`と`\`以外のUnicodeスカラー値です。
次のエスケープを受理します。

```text
\"  \\  \/  \b  \f  \n  \r  \t  \uXXXX
```

`\uXXXX`の16進数字は大文字・小文字を受理します。補助文字は高サロゲートのエスケープと
直後の低サロゲートのエスケープの組だけを受理し、1個のUnicodeスカラー値へ変換します。
高・低いずれの孤立サロゲートもエラーです。未エスケープU+0000〜U+001Fもエラーです。

### 4.5 オブジェクトの重複キー

重複はエスケープ展開後のUnicodeスカラー値列で判定します。`"x"`と`"\u0078"`は重複です。
NFC正規等価性は使わないため、`"é"`と`"e\u0301"`は別キーです。2個目のキー位置へ
`E_JSON_DUPLICATE_KEY`を報告し、どちらかを採用して解析を続けることはしません。

## 5. 決定的な直列化

`JSONを文字列に変換する (JSON -- 文字列)`とJSON値の表示は、同じ直列化規則を使います。

- JSONトークン間に空白や改行を置かない
- オブジェクトキーは保持した順で出力する
- 整数は先頭0と正符号のないASCII 10進表記にする
- 小数は指数を使わない固定小数点表記にし、整数値なら`.0`を付ける
- `"`、`\`、U+0000〜U+001Fをエスケープする
- BS、FF、LF、CR、HTABはそれぞれ`\b`、`\f`、`\n`、`\r`、`\t`を使う
- その他のU+0000〜U+001Fは大文字16進数字の`\u00XX`を使う
- `/`、U+2028、U+2029、その他のUnicodeスカラー値はUTF-8で直接出力する
- BOMを付けず、文字列値の末尾にLFを自動追加しない

同じJSON値、処理系版、資源上限からは、既定ロケール、タイムゾーン、OS改行、ハッシュ反復順に
依存しない同じUTF-8バイト列を得ます。`parse(serialize(value))`は7値種別と構造的等価性を
保ちます。元入力の空白、エスケープ選択、数値表記は保持しません。

## 6. 不変性と等価性

JSON値は作成後に変更できません。配列の一部取得・置換・追加、オブジェクトの設定・削除は
新しいJSON値を返します。実装は観測結果を保つ限り構造共有できます。

`等しい (T T -- 真偽)`へ`JSON`と`配列<JSON>`を追加します。JSONの等価性は次です。

- 値種別が異なれば等しくない
- ヌルはヌルと等しい
- 真偽、整数、小数、文字列は同じ種別の値比較を使う
- 配列は長さと同じ位置の全要素が等しい場合だけ等しい
- オブジェクトはキー順を無視し、同じキー集合の対応する全値が等しい場合だけ等しい

比較は規範上限内の値に対して停止し、Javaの再帰呼出し深さへ依存しません。比較自体は新しい
JSON値を構築しませんが、JSON走査予算を消費します。

## 7. JSONヌルとキー不在

JSONヌルは値、キー不在は値がない状態です。次を区別します。

| オブジェクトとキー | キー存在 | 必須取得 |
|---|---|---|
| `{"x":null}`の`x` | `はい` | JSONヌル |
| `{"x":1}`の`x` | `はい` | JSON整数1 |
| `{}`の`x` | `いいえ` | `E_JSON_KEY_NOT_FOUND` |

JSON機能グループでは`JSONオブジェクトにキーがある`と`JSONオブジェクトから必須値を取り出す`を
組み合わせます。キー不在をJSONヌルで代用しません。検索結果を値として返す`任意<JSON>`は、
汎用`任意<T>`型とともに後続契約で追加します。

## 8. BSBスカラーとの明示変換

### 8.1 JSONへ変換

| 単語 | 効果 | 結果 |
|---|---|---|
| `真偽をJSONに変換する` | `真偽 -- JSON` | `はい`をJSON true、`いいえ`をJSON false |
| `整数をJSONに変換する` | `整数 -- JSON` | 同じ任意精度値のJSON整数 |
| `小数をJSONに変換する` | `小数 -- JSON` | 同じ正確値のJSON小数 |
| `文字列をJSONに変換する` | `文字列 -- JSON` | 同じUnicodeスカラー値列のJSON文字列 |

### 8.2 JSONから必須変換

| 単語 | 効果 | 必要な値種別 |
|---|---|---|
| `JSONから真偽を取り出す` | `JSON -- 真偽` | JSON真偽 |
| `JSONから整数を取り出す` | `JSON -- 整数` | JSON整数 |
| `JSONから小数を取り出す` | `JSON -- 小数` | JSON小数 |
| `JSONから文字列を取り出す` | `JSON -- 文字列` | JSON文字列 |

値種別が異なる場合は`E_JSON_KIND_MISMATCH`です。JSON整数を小数へ、JSON小数を整数へ
暗黙変換しません。必要なら取り出した後にNUM機能グループの明示数値変換を使います。

## 9. 値種別検査

次の7語は入力JSONを残し、その上へ判定結果を積みます。

```text
JSONヌルである             (JSON -- JSON 真偽)
JSON真偽である             (JSON -- JSON 真偽)
JSON整数である             (JSON -- JSON 真偽)
JSON小数である             (JSON -- JSON 真偽)
JSON文字列である           (JSON -- JSON 真偽)
JSON配列である             (JSON -- JSON 真偽)
JSONオブジェクトである     (JSON -- JSON 真偽)
```

判定は失敗せず、該当種別なら`はい`、それ以外なら`いいえ`です。元JSONを残すため、直後の
`ならば`で真偽を消費した後に同じJSONを必須変換できます。

## 10. JSON配列とオブジェクトの操作

### 10.1 JSON配列

```text
JSONから配列に変換する             (JSON -- 配列<JSON>)
JSON配列に変換する                 (配列<JSON> -- JSON)
JSON配列の長さ                     (JSON -- 整数)
JSON配列から取り出す               (JSON 整数 -- JSON)
JSON配列の一部を取り出す           (JSON 整数 整数 -- JSON)
JSON配列の要素を置き換える         (JSON 整数 JSON -- JSON)
JSON配列の末尾へ追加する           (JSON JSON -- JSON)
```

最初のJSON入力がJSON配列でない場合は`E_JSON_KIND_MISMATCH`です。添字の有効範囲は長さ`N`に
対して`0 <= 添字 < N`、半開区間は`0 <= 開始 <= 終了 <= N`です。範囲失敗はそれぞれ
`E_JSON_INDEX_OUT_OF_BOUNDS`、`E_JSON_RANGE_OUT_OF_BOUNDS`です。

`JSONから配列に変換する`はJSON配列の各要素を`JsonRuntimeValue`として同じ順の
`配列<JSON>`へ写します。`JSON配列に変換する`は逆変換です。いずれも要素のJSON値自体は
不変なので共有できますが、結果の外側容器は別の不変値です。

### 10.2 JSONオブジェクト

```text
JSONオブジェクトの要素数                   (JSON -- 整数)
JSONオブジェクトのキー一覧                 (JSON -- 配列<文字列>)
JSONオブジェクトにキーがある               (JSON 文字列 -- JSON 真偽)
JSONオブジェクトから必須値を取り出す       (JSON 文字列 -- JSON)
JSONオブジェクトに設定する                 (JSON 文字列 JSON -- JSON)
JSONオブジェクトから削除する               (JSON 文字列 -- JSON)
```

最初のJSON入力がJSONオブジェクトでない場合は`E_JSON_KIND_MISMATCH`です。キー一覧は保持順です。
キー存在語は元オブジェクトを残します。必須取得はキーがなければ`E_JSON_KEY_NOT_FOUND`です。

設定は既存キーなら位置を保って値を置換し、新規キーなら末尾へ加えます。削除対象がない場合は
エラーにせず、入力と等価な新しいJSONオブジェクトを返します。

| 32 | `JSONオブジェクトに設定する` | `[JSON, 文字列, JSON]` | `[JSON]` | キーを設定した新しいJSONオブジェクトを返します。 | `空のJSONオブジェクトと「x」と JSONヌルを JSONオブジェクトに設定する` |
| 33 | `JSONオブジェクトから削除する` | `[JSON, 文字列]` | `[JSON]` | キーを削除した新しいJSONオブジェクトを返します。 | `空のJSONオブジェクトと「x」を JSONオブジェクトから削除する` |

別名は全語で空です。表中の助詞は読みやすさの推奨であり、従来どおり実行意味を変えません。

## 12. 資源上限

| 資源 | 上限 | 数え方 |
|---|---:|---|
| JSON入力文字列 | 16,777,216 UTF-8バイト | 既存`文字列`上限を共有 |
| JSON直列化結果 | 16,777,216 UTF-8バイト | 完成したBSB文字列のバイト数 |
| JSON入れ子 | 256段 | ルート容器を1段とする配列・オブジェクト深さ |
| 1 JSON配列 | 65,536要素 | 直接要素数 |
| 1 JSONオブジェクト | 65,536メンバー | 直接キー数 |
| 1 JSON値 | 250,000値ノード | ルートと全子値。オブジェクトキーは含めない |
| JSON数値入力 | 4,096数字 | 符号、小数点、指数記号、指数符号を除くASCII数字 |
| JSON整数値 | 65,536桁 | 符号を除く正規10進桁 |
| JSON小数値 | 有効桁65,536、絶対スケール65,536 | NUM機能グループと同じ正規化後指標 |
| JSON構築単位 | 1実行1,000,000 | 新しく保持する値ノード・要素参照・メンバー参照 |
| JSON作業単位 | 1実行67,108,864 | 解析・直列化・走査で処理するUTF-8バイト、値、要素、メンバー |

JSON入力はBSB`文字列`なので、16 MiBを超える入力値はJSON語へ到達する前に既存文字列上限で
拒否済みです。JSON直列化は上限を超える候補を部分的に作らず`E_JSON_OUTPUT_LIMIT`にします。

解析では、入力UTF-8バイト数をJSON作業単位として先に予約し、値ノードを作るごとにJSON構築単位を
消費します。不正文法で後から失敗しても、予約済み作業単位は消費済みです。値ノードとして公開しない
解析途中オブジェクトを構築単位へ数える詳細は[json-diagnostics.md](json-diagnostics.md)に従います。

不変更新は新しい外側容器が保持する直接要素・メンバー参照と容器自身を構築単位へ数えます。
既存の不変な子JSON値を共有する場合、その子の全子孫を再度数えません。JSONと`配列<JSON>`の変換は、
JSON構築予算または既存BSB配列構築予算のうち、新しく作る側の容器予算だけを消費します。

## 13. 診断、原子性、トレース

診断コード、優先順位、JSON入力内位置、資源課金の詳細は
[json-diagnostics.md](json-diagnostics.md)に従います。

失敗するJSON語は入力スタック、保存値、stdout、stderr、元JSON値を変更しません。予算は同仕様で
「予約済み」と定めた作業だけが消費済みになり、上限検査に失敗した予約は一切加算しません。

JSONはAPIイベント、個人情報、トークン相当の値を含み得るため、JSON機能グループの既定トレースでは
`JSON:<redacted>`とし、値種別、長さ、キー、要素を公開しません。`配列<JSON>`も配列全体を
`配列<JSON>:<redacted>`とします。利用者が明示的に表示したJSONは通常のプログラム出力であり、
このトレース非開示規則の対象ではありません。

トレース用の型名・非開示表記はJSON作業単位を消費せず、トレースの有無で実行結果、予算、診断を
変えません。

## 14. CLI JSONとの境界

`check --json`と`explain --json`のJSON文書はCLIの公開スキーマです。JSON機能グループの`JSON`値は
BSBプログラムの実行時値であり、次を共有しません。

- CLI DTOとJSON機能グループ`JsonValue`の型
- `schemaVersion`、キー順、必須キー
- 64 MiBのCLI文書上限と16 MiBのBSB文字列上限
- CLIの`JsonOutput`とJSON機能グループの解析器・直列化器

JSON機能グループの33組み込み語追加は`explain --json`版1の加算的変更です。必須キーと既存識別値の意味を
変えないため`schemaVersion`を増やしません。`featureGroup`へ文字列`JSON`を追加し、読取側は
既存規則どおり未知の機能グループ文字列を保持できます。
