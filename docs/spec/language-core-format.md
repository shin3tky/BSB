# CORE機能グループ: フォーマッタ仕様

> 本文は現行実装の規範契約です。
>
> この文書は `bsb format` が出力するCORE機能グループの正規表記を一意に定めます。

## 1. 入力と出力

`format` はUTF-8、字句、構文の検査だけを行います。名前、型、スタック効果、副作用は検査しません。このため、未定義単語、重複定義、`メイン` の欠落、小数リテラルを含む構文として有効なソースも整形できます。

構文系エラーでは標準出力へ何も書かず、診断を標準エラーへ書いて終了コード9を返します。成功時は正規表記だけを標準出力へ書き、終了コード0を返します。

出力はBOMなしUTF-8、改行はLFです。トークンまたはコメントを1つ以上含む出力はLFちょうど1つで終わります。空ファイルの出力は0バイトです。

## 2. ファイル全体

- 先頭と末尾の空行を出力しない
- トップレベル単語定義の間は空行ちょうど1行とする
- 連続するトップレベルのコメントだけの行の間へ空行を追加しない
- コメントだけのファイルは、コメント行を保持し、最後にLFを1つ出力する
- `、` と `，` は区切りとして消去する
- タブと全角空白は、コメントとリテラルの外ではASCII空白へ変換する
- コメント本文とリテラルの値にはNFCその他のUnicode正規化を適用しない

## 3. 単語定義

定義ヘッダーは次の形にします。

```text
＜正規化後の単語名＞とは ＜スタック効果＞
```

スタック効果は全角括弧、ASCIIハイフン2個、要素間のASCII空白1個を使用します。

```text
（整数 文字列 -- 真偽）
（--）
```

本体は4個のASCII空白で字下げします。空本体ではヘッダーの次の行へ直ちに `こと。` を出力します。`こと。` は字下げしません。

## 4. 本体の行分け

CORE機能グループでは、本体中の識別子はすべて単語呼び出しです。フォーマッタは、コメントを除くトークン列を先頭から読み、次の規則で行を確定します。

1. リテラル、組み込み値、助詞を現在の行へ追加する。
2. 単語呼び出しの識別子を追加した直後に、その行を確定する。
3. `こと。` の直前にリテラル、組み込み値、助詞だけが残った場合は、それらを1行として確定する。
4. 行内のトークン間はASCII空白1個とする。
5. 行の長さによる折り返しは行わない。

たとえば次の構文として有効な入力を、

```text
メインとは (--)  21、を　二倍 表示する 改行する こと 。
```

次の形へ整形します。

```text
メインとは （--）
    21 を 二倍
    表示する
    改行する
こと。
```

フォーマッタは名前解決を行わないため、未定義の識別子も単語呼び出しとして行を確定します。

## 5. コメント

`#` から物理行末までの文字列をコメント本文として保持します。コメント本文には `#` 自身を含めます。

- 実行トークンと同じ物理行に始まったコメントは、直前の整形後の行へASCII空白1個を置いて付ける
- コメントより前に実行トークンがない場合は、コメントだけの行として出力する
- 単語本体内のコメントだけの行は4個のASCII空白で字下げする
- トップレベルのコメントだけの行は字下げしない
- コメント本文中の空白と末尾空白は変更しない
- コメントは、字句上で直前と直後にあった非コメントトークンの順序の間から移動しない

`こと` と `。` の間にはコメントと改行を許さないため、終端コメントを移動する必要はありません。

## 6. リテラルの正規表記

### 6.1 整数と小数

整数は符号付き10進表記にし、正数へ `+` を付けず、不要な先頭の0を出力しません。`-0` は `0` にします。

小数はNUM機能グループまで値として解釈しないため、CORE機能グループのフォーマッタは有効な字句をそのまま保持します。したがって `-0.0` と末尾の0を変更しません。

### 6.2 真偽値

`はい` と `いいえ` をそのまま出力します。

### 6.3 文字列

文字列は必ず `「` と `」` で囲み、字句解析後の値から再構成します。次の値は指定のエスケープを使います。

| 値 | 正規エスケープ |
|---|---|
| LF | `\n` |
| CR | `\r` |
| タブ | `\t` |
| バックスラッシュ | `\\` |
| `「` | `\「` |
| `」` | `\」` |

ASCII二重引用符とASCII単一引用符は、日本語二重かぎ括弧の内部ではエスケープせず、そのまま出力します。

上表以外のC0・C1制御文字と、ソースへ直接置くことを禁止する不可視文字は `\u{X}` で出力します。`X` は先頭の0を省いた大文字16進数です。文字列のコードポイント列は正規化しません。

### 6.4 文字

文字はASCII単一引用符で囲み、値から再構成します。LF、CR、タブ、バックスラッシュは文字列と同じ正規エスケープを使い、ASCII単一引用符は `\'` とします。`「`、`」`、ASCII二重引用符はそのまま出力します。その他の制御文字と不可視文字は `\u{X}` にします。

## 7. 識別子

識別子は、全角英数字のASCII変換とNFC正規化を終えた名前を出力します。英字の大小文字は変更しません。CORE機能グループの組み込み辞書には別名がないため、別名から正規名への変換は発生しません。

## 8. 終端表記

入力では `こと` と `。` の間にU+0020、U+0009、U+3000を0個以上置けます。改行、コメント、`、`、`，`は置けません。出力は必ず `こと。` です。

## 9. 冪等性

任意の構文として有効なソース `S` について、バイト列として次を満たさなければなりません。

```text
format(format(S)) = format(S)
```

冪等性は、BOM、改行形式、引用符、コメント、空本体、小数、未定義単語を含む適合データで検証します。
