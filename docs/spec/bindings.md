# BIND機能グループ: 定数、変数、スコープ

> 本文は現行実装の規範契約です。
>
> CORE・FLOW機能グループの規則は、ここで明示的に変更する箇所以外、引き続き有効です。

## 1. 範囲と機能境界

BIND機能グループでは、名前付きの不変値である定数、明示的に更新できる変数、大域・単語・制御ブロックの字句スコープ、初期値からの型推論、値参照、代入を追加します。

BIND機能グループで推論できる宣言型は、FLOW機能グループまでに実行できる`整数`、`真偽`、`文字`、`文字列`の4型だけです。小数、配列、利用者定義型、暗黙の型変換、分割代入、型注釈、局所単語、短絡真偽演算は追加しません。局所単語は現行仕様に含まれず、将来検討時の論点だけを[非規範の設計ノート](../design-notes/local-words.md)に分離します。

単語定義のスタック効果はBIND機能グループでも必須です。通常の非再帰単語に対するスタック効果の省略・推論は、名前付き値の型推論とは分離し、後続機能グループで導入します。

## 2. 正規語

| 分類 | 正規語 | 役割 |
|---|---|---|
| 宣言標識 | `は` | 隣接する直前の識別子を宣言名にする |
| 宣言種別 | `定数` | 初期化後に更新できない名前付き値を宣言する |
| 宣言種別 | `変数` | 同じ型の値へ更新できる名前付き値を宣言する |
| 代入 | `入れる` | 指定した変数へスタック最上部の値を保存する |

`は`、`定数`、`変数`、`入れる`は現在の構文予約語です。利用者定義単語、定数、変数、別名、型名として使用できません。BIND機能グループでは別名を定義しません。

`を`と`に`は引き続き助詞であり、それ自体はデータスタックを変更しません。ただし、`を ＜名前＞ に 入れる`の並びでは代入構文を区切ります。

通常の助詞メタデータは、名前付き値のLoadを越えて後続の単語呼出しへ関連づけます。たとえば`単価 と 個数 を 掛ける`の`と`と`を`は`掛ける`のメタデータです。代入を区切る`を`と`に`は通常の助詞配置警告とCallメタデータの対象にせず、助詞自身の独立イベントも作りません。

## 3. 文法

FLOW機能グループの`program`、`body`、`atom`へ次を追加します。`initializerAtom`はリテラル、組み込み値、助詞、現在値の参照、初期値で許可された組み込み単語です。`trivia`は区切りまたはコメントです。

```text
program             := (wordDefinition | globalDeclaration | trivia)*

body                := (atom | localDeclaration | assignment
                        | conditional | countedLoop | conditionLoop
                        | transfer | trivia)*

globalDeclaration   := declaration
localDeclaration    := declaration

declaration         := declarationStart declarationKind initializer "。"
declarationStart    := identifier "は"
declarationKind     := "定数" | "変数"
initializer         := (initializerAtom | trivia)*

assignment          := "を" identifier "に" "入れる"
```

宣言開始では、正規化前の識別子と`は`が元ソース上で隣接しなければなりません。`合計は`は宣言開始ですが、`合計 は`は`E_DECLARATION_ADJACENCY`です。字句解析器は、識別子候補の末尾が`は`で、その後の最初の非コメントトークンが`定数`、`変数`、または宣言終端`。`である場合に、末尾の`は`を宣言標識として分けます。したがって、通常の識別子`母は強い`の末尾を無条件には分割しません。`。`を直後の候補に含めることで、宣言種別の欠落を専用診断にできます。

`は`と宣言種別の間には1個以上の通常区切りが必要です。コメントは置けません。宣言種別の直後から最初の`。`までが初期値です。文字列・文字・コメント内の`。`は終端ではありません。宣言内へ別の宣言を入れ子にできません。

代入では4個の実行・構文トークンをこの順序で必要とします。これらの間へコメントを置けません。区切り、`、`、`，`は使用できます。直前に値を作る処理は代入ASTの子にせず、既存の後置評価どおり先行する本体要素です。

## 4. 初期値

初期値は、周囲の利用者データスタックとは分離した空の抽象スタックから検査します。初期値の入口を`[]`とし、すべての到達可能な出口が正確に`[T]`となる場合だけ受理し、その`T`を宣言型とします。

- 値を残さない初期値は`E_INITIALIZER_VALUE_MISSING`
- 2個以上の値を残す初期値は`E_INITIALIZER_VALUE_COUNT`
- 初期値内部の組み込み単語で値が不足する場合は既存の`E_STACK_UNDERFLOW`
- 初期値内部の型不一致は既存の`E_TYPE_MISMATCH`

初期値で許可する処理は次です。

- BIND機能グループで実行可能なリテラルと組み込み値
- その地点で初期化済みかつ可視な定数・変数の読み出し
- 助詞
- 副作用なしと辞書に記録された`足す`、`引く`、`掛ける`、`等しい`、`比べて小さい`

利用者定義単語は、実際の本体が副作用を持たない場合も初期値から呼べません。`表示する`、`一行表示する`、`改行する`など副作用を持つ組み込み単語も呼べません。どちらも`E_INITIALIZER_CALL_NOT_ALLOWED`です。BIND機能グループでは利用者定義単語の効果推論を追加しません。

条件分岐、ループ、`打ち切る`、`続ける`、`戻る`、宣言、代入も初期値へ書けず、構文解析で`E_INITIALIZER_ELEMENT_NOT_ALLOWED`です。

定数はコンパイル時定数を意味しません。定数と変数はどちらも実行時の不変値オブジェクトを保存領域へ保持し、更新可能性だけが異なります。

## 5. 大域初期化

トップレベルの単語定義と大域宣言は混在できます。名前衝突検査のため、すべてのトップレベル名を本体検査より先に収集します。

大域宣言は、元ソースに現れる順で`メイン`より前にちょうど1回初期化します。単語定義の位置は初期化順へ数えません。大域初期値から読み出せる名前付き値は、ソース上で先に初期化を完了する大域定数・変数だけです。

- 自分自身または後方の大域宣言を読むと`E_REFERENCE_BEFORE_INITIALIZATION`
- 大域初期値から利用者定義単語を呼べないため、単語を経由した未初期化参照は生じない
- 初期値に副作用がないため、大域初期化中に標準出力や外部状態を変更しない
- すべての大域初期化が成功してから`メイン`を開始する

単語本体からは、ソース上の宣言順にかかわらず、すべての大域宣言を参照できます。単語本体が実行される時点では大域初期化が完了しているためです。

## 6. 字句スコープ

BIND機能グループのスコープは次の階層です。

```text
大域スコープ
  └─ 単語本体スコープ（呼出しごと）
       ├─ 条件分岐の真側スコープ
       ├─ 条件分岐の偽側スコープ
       ├─ 回数ループ本体スコープ
       ├─ 条件ループの条件計算スコープ
       └─ 条件ループ本体スコープ
```

入れ子の制御構文は同じ規則で子スコープを作ります。条件分岐の真側と偽側、条件ループの条件計算部と本体は互いに兄弟であり、一方の局所名を他方から参照できません。

局所宣言の可視範囲は、宣言終端`。`の直後から、その宣言を直接含む本体要素列の末尾までです。可視範囲内の子スコープからも参照できます。宣言自身の初期値、宣言より前、親スコープ、兄弟スコープからは参照できません。

同じスコープで同じ正規化後の名前を再宣言すると`E_DUPLICATE_NAME`です。内側の宣言が、可視な外側の局所名、大域の単語・定数・変数、組み込み名、予約名を隠すことはできず、`E_NAME_SHADOWING`です。互いに可視でない兄弟スコープでは同じ局所名を宣言できます。

大域・局所を問わず、単語、定数、変数は同じ利用者可視名前空間を共有します。正規化、予約名、confusable警告はCORE機能グループの規則を引き継ぎます。

## 7. 局所値の寿命

局所定数・変数は利用者定義単語の呼出しフレームに属します。再帰を含む呼出しごとに独立した保存領域を持ち、呼出し終了後は参照できません。

局所宣言へ実行が到達するたびに初期値を評価し直します。ループ本体の宣言は各反復で再初期化されます。条件分岐の選ばれなかった側と、`戻る`などで到達しなかった宣言は初期化しません。

実装は単語ごとに固定スロットを割り当ててもよいですが、宣言への再到達時には必ず初期値で上書きし、字句上の寿命外に残った値を観測可能にしてはなりません。

## 8. 名前参照

通常の本体位置にある識別子は、次の順で解決します。

1. その位置で可視な最も内側の局所定数・変数
2. 大域定数・変数
3. 利用者定義単語
4. 組み込み辞書
5. 現在の非呼出し名、後段予約名、未知名の診断

隠蔽禁止と単一名前空間により、正常なプログラムで複数候補が同時に一致することはありません。

定数または変数の参照は、現在値をデータスタックへ1個積みます。

```text
定数・変数名    （-- T）
```

同じスコープの後方に宣言がある名前を先に読む場合は`E_REFERENCE_BEFORE_DECLARATION`です。終了済みの子・兄弟スコープに同名宣言がある場合は`E_BINDING_OUT_OF_SCOPE`です。それ以外の未知名は従来どおり`E_UNDEFINED_WORD`です。

到達不能範囲はFLOW機能グループどおり名前・型検査を省略するため、その範囲の宣言を登録せず、参照診断も生成しません。

## 9. 代入

```text
＜値を作る処理＞ を ＜変数名＞ に 入れる
```

代入直前のスタックを`S + [T]`とすると、`入れる`は`T`を消費して変数へ保存し、出口を`S`とします。代入式自身は値を返しません。

- 値がない場合は`E_ASSIGNMENT_STACK_UNDERFLOW`
- 変数の宣言型と`T`が異なる場合は`E_ASSIGNMENT_TYPE_MISMATCH`
- 定数が代入先なら`E_ASSIGN_TO_CONSTANT`
- 利用者定義単語または組み込み単語が代入先なら`E_ASSIGNMENT_TARGET_NOT_VARIABLE`
- 未知名が代入先なら`E_UNDEFINED_ASSIGNMENT_TARGET`
- 宣言前またはスコープ外なら読み出しと同じ可視性診断

整数から小数、文字から文字列などの暗黙変換は行いません。代入が分岐やループ内にあっても、変数の静的な型は変化しません。

## 10. 到達可能性との関係

宣言、参照、代入は通常の本体要素です。`戻る`、`打ち切る`、`続ける`後の到達不能範囲では、`W_UNREACHABLE_CODE`だけを最大連続範囲ごとに報告し、宣言重複、未定義参照、初期値、代入の派生診断を抑止します。IRにも生成しません。

宣言は実行後のデータスタックを変えないため、分岐・ループのスタック合流規則へ保存領域の値を加えません。変数の値を経路ごとに定数伝播せず、型と可変性だけを静的に追跡します。

## 11. IRと実行モデル

BIND機能グループでは次の概念命令名をトレース上の安定名とします。

```text
InitializeGlobal
InitializeLocal
LoadGlobal
LoadLocal
StoreGlobal
StoreLocal
```

各命令は静的に解決済みの束縛IDとスロット番号を持ちます。実行時に利用者名を検索しません。`Initialize*`と`Store*`はデータスタック最上部を1個消費し、`Load*`は現在値を1個積みます。

大域初期化命令列は内部名`<大域初期化>`を持つ専用IR単語として、`メイン`より先に1回実行します。末尾の`Return`は最後の大域宣言終端の位置を持ちます。大域宣言が0個なら専用単語を生成しません。

検査済みIRから未初期化Load、定数へのStore、不正なスロットが発生することはありません。合成した不正IRを検出した場合は利用者プログラムの実行時診断ではなく、処理系内部エラー終了コード70です。

## 12. 名前解決説明

BIND機能グループでは、公開CLIへ`explain`をまだ追加せず、検査済みプログラムから決定的な束縛表を生成する内部説明APIを規範化します。公開するJSONスキーマを内部TSVへ拙速に固定しないためです。

適合データの`chapter/04-chapter.bindings.tsv`は、各値参照・代入先について次を持ちます。

```text
line
column
spelling
use
bindingId
bindingName
bindingKind
scope
type
declarationLine
declarationColumn
```

`use`は`read`または`write`、`bindingKind`は`constant`または`variable`、`scope`は`global`または`local:＜所有単語名＞`です。束縛IDは、到達可能な宣言を元ソース順に数えた1始まりの`B1`、`B2`、…です。同じソースから常に同じ表を生成します。

公開`explain --json`は、単語の効果・副作用も含む外部スキーマを別途決定した段階で追加します。
