# TEXT機能グループ: Unicode正規表現

> 本文は現行実装の規範契約です。

## 1. リテラル

正規表現リテラルの標準形は次です。

```text
正規表現「pattern」flags
```

`正規表現`と始めかぎ括弧の間に空白を置きません。内容は通常の文字列エスケープを適用しないrawパターンで、バックスラッシュをそのまま正規表現構文へ渡します。これにより`\p{Han}`を書くために`\\p{Han}`と二重化する必要がありません。

未エスケープのCR/LFと終わりかぎ括弧`」`を内容へ直接書けません。U+300Dを照合する場合は`\x{300D}`と書きます。終端不足と生改行は字句エラーです。終端探索で`」`が入力末尾まで見つからなければ`E_UNTERMINATED_REGEX_LITERAL`を先にし、終端が見つかった内容にCR/LFがあれば最初の改行を`E_NEWLINE_IN_REGEX_LITERAL`にします。

フラグは0個以上のASCII小文字で、入力では任意順、標準形では`ims`順です。同じフラグの重複と他の文字を拒否します。

| フラグ | 意味 |
|---|---|
| `i` | ASCII `A-Z`と`a-z`だけの大小文字無視 |
| `m` | `^`と`$`を入力全体に加えてLFの直後・直前へ一致させる |
| `s` | `.`をLFを含む任意のUnicodeスカラー値へ一致させる |

通常文字列にはUnicode 16.0の大小文字変換と大小文字無視比較がありますが、正規表現の`i`は引き続きASCIIだけを対象にします。Unicodeケースフォールドを含む正規表現照合は提供しません。

## 2. 採用エンジンとUnicode適合層

照合核にはRE2/J 1.8を採用します。RE2/Jはバックトラック型でなく、入力長に対して線形時間の照合を目的とします。TEXT機能グループの言語仕様はJava APIを直接公開しません。

技術検証では、日本語リテラル、補助平面漢字、Unicodeクラス、`(?<name>...)`、名前指定取得、`${name}`置換、後方参照・先読みの拒否、`programSize`を確認しました。一方、RE2/J 1.8内蔵の`\p{Han}`はUnicode 15.1で追加されたU+2EBF0を含みません。

この差を実行環境依存にしないため、BSBは次の適合層を必須とします。

1. `\p{...}`と`\P{...}`をUnicode 16.0のデータで解決する。
2. General_Categoryの短縮名・完全名とScript名を、ICU4J 76.1または同じUnicode 16.0データからコードポイント範囲へ展開する。
3. 展開後のクラスをRE2/Jへ渡し、RE2/J内蔵Unicodeプロパティ表へ暗黙フォールバックしない。
4. U+2EBF0、U+20BB7、ひらがな、カタカナ、結合文字を適合データで固定する。

参照: [RE2/J README](https://github.com/google/re2j/blob/master/README.md)、[RE2/J 1.8 release](https://github.com/google/re2j/releases/tag/re2j-1.8)

## 3. サポートする構文

- Unicodeスカラー値リテラル、連結、選択`|`
- `.`、`^`、`$`
- `(...)`、`(?:...)`、`(?<name>...)`
- `?`、`*`、`+`、`{m}`、`{m,}`、`{m,n}`と非貪欲接尾辞`?`
- 文字クラス`[...]`、否定`[^...]`、範囲
- `\n`、`\r`、`\t`、`\f`、`\a`、`\xHH`、`\x{H...}`
- ASCIIクラス`\d`、`\s`、`\w`と否定形
- Unicode 16.0クラス`\p{...}`、`\P{...}`

`\d`は`[0-9]`、`\w`は`[A-Za-z0-9_]`、`\s`はASCII空白`[\t\n\f\r ]`です。Unicode分類には明示的に`\p{Nd}`などを使います。

量指定子の整数は0以上1,000以下とし、有限上限は下限以上でなければなりません。`*`、`+`、`{m,}`の上限なし反復は受理します。1,001以上は、エンジンへ渡す前に`E_REGEX_SYNTAX`とします。

名前付きキャプチャ名は`[A-Za-z][A-Za-z0-9_]{0,63}`で一意とします。キャプチャ全体は名前なしを含め64個以下です。照合はUnicodeスカラー値列上のRE2 leftmost-first意味論を使い、UTF-16サロゲートの途中へ境界を作りません。書記素境界は正規表現操作では要求しません。

`正規表現`と本節の全操作語は予約名です。リテラルは式位置にある連続した`正規表現「`から開始し、通常の識別子`正規表現`と文字列リテラルの2トークンには分けません。

## 4. サポートしない構文

次は`E_REGEX_UNSUPPORTED_CONSTRUCT`です。RE2/Jが受理しても第3節の一覧にない構文は同じ診断にします。

- 数字・名前による後方参照
- 肯定・否定の先読みと後読み
- 原子的グループ、所有的量指定子、条件分岐、再帰、埋め込みコード
- Java固有の境界・領域・Unicodeフラグ
- リテラル内部でのフラグ変更

その他の不正構文、範囲逆転、不正量指定、重複名は`E_REGEX_SYNTAX`です。正規表現リテラルは静的に既知なので、check時にコンパイルし、失敗したASTからIRを作りません。formatはパターンをコンパイルしません。

## 5. 操作語

```text
正規表現に完全一致する                    （文字列 正規表現 -- 真偽）
正規表現を含む                            （文字列 正規表現 -- 真偽）
正規表現で最初を取り出す                  （文字列 正規表現 -- 文字列）
正規表現の名前付き部分を取り出す          （文字列 正規表現 文字列 -- 文字列）
正規表現で置き換える                      （文字列 正規表現 文字列 -- 文字列）
正規表現で分割する                        （文字列 正規表現 -- 配列<文字列>）
```

完全一致は入力全体、含む・抽出・置換・分割はleftmost-first検索を使います。最初の抽出で一致がなければ`E_REGEX_NO_MATCH`です。

名前付き抽出は、キャプチャ名の存在、一致全体の存在、その一致でキャプチャが参加したこと、の順に検査します。存在しない名前は`E_REGEX_GROUP_NOT_FOUND`、一致なしは`E_REGEX_NO_MATCH`、選択枝などにより不参加なら`E_REGEX_GROUP_UNMATCHED`です。空文字列への参加は成功して空文字列を返します。

## 6. 置換テンプレート

置換テンプレートは通常の`文字列`値で、次だけを展開します。

| 表記 | 展開 |
|---|---|
| `$$` | `$`1個 |
| `$0` | 一致全体 |
| `$1`〜`$99` | 対応する番号付きキャプチャ |
| `${name}` | 対応する名前付きキャプチャ |

存在しない番号・名前、不完全な`${...}`、単独の`$`は`E_REGEX_REPLACEMENT_TEMPLATE`です。不参加キャプチャは空文字列へ展開します。置換は重ならない一致を左から右へすべて処理します。

空文字列へ一致した後は、同じ位置で再一致せず1コードポイント先の境界から再開します。入力末尾の空一致は1回だけ処理します。これにより有限の結果を保証します。

## 7. 正規表現分割

各一致の直前までを要素とし、一致部分を捨てます。先頭、連続、末尾の空要素を保持します。ゼロ幅一致も区切りとして扱い、置換と同じ進行規則を使います。空パターンで`ab`を分割した結果は`【「」、「a」、「b」、「」】`です。

## 8. 資源量

| 対象 | 上限 | 判定時点 |
|---|---:|---|
| rawパターン | 65,536 UTF-8バイト | コンパイル前 |
| キャプチャ | 64個 | コンパイル時 |
| BSBコンパイル命令 | 65,536個 | Unicodeクラス展開・コンパイル後 |
| 1呼出し照合単位 | 1,000,000,000 | 照合前 |
| 1実行累積照合単位 | 10,000,000,000 | 各照合前 |

1呼出し照合単位は次です。加算・乗算は飽和させず任意精度整数で上限超過を判定します。

```text
コンパイル命令数 × (入力コードポイント数 + 1)
```

TEXT機能グループの「BSBコンパイル命令数」は、Unicode 16.0プロパティを範囲へ展開してRE2/J 1.8でコンパイルした後の`Pattern.programSize()`と同じ整数です。この値は利用者プログラムへ公開しませんが、適合実装とTEXT-R境界の観測値を一意にします。別エンジンへ移行する場合は、同じ値になる互換層または新しい言語仕様決定が必要です。

完全一致、検索、抽出、置換、分割は1呼出しにつき1回だけこの単位を加算し、内部の一致件数では再加算しません。構文検査、テンプレート検査、結果長、配列長を照合より先に確定できる場合は先に検査します。既存30秒実行上限は独立して残ります。
