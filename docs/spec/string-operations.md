# TEXT機能グループ: 文字列操作

> 本文は現行実装の規範契約です。
>
> CORE〜NUM機能グループの規則は、ここで明示的に変更する箇所以外、引き続き有効です。
>
> 現行契約: DTXT機能グループでは[小数文字列の指数表記](decimal-text.md)が、
> 本文の`decimalText`と指数を拒否する境界を上書きします。`integerText`は変更しません。

## 1. 範囲と機能境界

TEXT機能グループでは、不変な`文字列`に対する連結、比較、Unicode 16.0に固定した大小文字変換と大小文字無視比較、前後空白除去、長さ、参照、半開区間、検索、置換、分割、整数・小数との明示変換を追加します。利用者向け操作はUnicode 16.0の拡張書記素クラスタ、低水準操作はUnicodeスカラー値（以下、コードポイント）を単位とし、正規語から区別できるようにします。

`正規表現`を新しい具体型として追加し、リテラル、完全一致、検索、抽出、名前付きキャプチャ、全置換、分割を提供します。文字列と正規表現は不変値です。

次は追加しません。

- 暗黙の文字列・数値変換、指数表記、先頭`+`、桁区切り
- Unicode正規化、ロケール依存照合、自然言語の照合順
- 可変文字列、バイト位置、UTF-16コード単位位置、バイト列
- 多次元・異種配列、`配列<正規表現>`
- 正規表現の後方参照、先読み、後読み、条件分岐、埋め込みコード

## 2. 文字列値とUnicode単位

文字列値は[language-core-unicode.md](language-core-unicode.md)のUnicodeスカラー値列で、内容をNFCその他へ正規化しません。値の同一性と検索はスカラー値列の完全一致です。正規等価でも符号化列が異なる`が`（U+304C）と`か`+U+3099は同じ値とはしません。

利用者向けの単位はUnicode 16.0版UAX #29のExtended Grapheme Clusterです。低水準単語はコードポイント単位で数え、書記素クラスタの途中を切り出し得ます。どちらも0始まりで、UTF-8バイト位置とUTF-16コード単位位置を返しません。

## 3. 正規語とスタック効果

### 3.1 共通操作

```text
つなぐ                    （文字列 文字列 -- 文字列）
文字列を比較する          （文字列 文字列 -- 整数）
大文字に変換する          （文字列 -- 文字列）
小文字に変換する          （文字列 -- 文字列）
大小文字を無視して比較する（文字列 文字列 -- 整数）
前後の空白を除く          （文字列 -- 文字列）
```

`つなぐ`は第1入力の後ろへ第2入力を連結します。結果が16 MiBを超える場合は、結果を確保する前に失敗します。

`文字列を比較する`はUnicodeスカラー値の数値順で辞書式比較し、第1入力が前なら`-1`、同じなら`0`、後なら`1`だけを返します。書記素、ロケール、正規等価、大小文字を特別扱いしません。

`大文字に変換する`と`小文字に変換する`は、Unicode 16.0のDefault Case Conversionに従う完全文字列写像をroot localeで適用します。1コードポイントを複数コードポイントへ展開する写像と文脈依存写像を含みます。例えば`Straße`の大文字は`STRASSE`、`ΟΣ`の小文字は`ος`、`İ`の小文字は`i`+U+0307です。ホストの既定localeを参照せず、トルコ語などの言語固有写像は提供しません。

`大小文字を無視して比較する`は、両入力へUnicode 16.0のDefault Case Foldingの完全写像を適用し、その結果をUnicodeスカラー値順で比較して`-1`、`0`、`1`のいずれかを返します。したがって`Straße`と`STRASSE`、`Σ`と`ς`は`0`です。Default Case FoldingのTurkic指定は使いません。

これら3語はNFC、NFDその他の正規化を暗黙に行いません。大小文字以外のスカラー値列が異なる場合はその差を保持するため、合成済み`が`と`か`+U+3099は大小文字無視比較でも同じになりません。変換結果だけを返し、元の文字列値は変更しません。

`前後の空白を除く`はUnicode 16.0の`White_Space`プロパティを持つコードポイントを先頭と末尾から除き、内部の空白を保持します。

### 3.2 書記素クラスタ操作

```text
文字列の長さ                  （文字列 -- 整数）
文字列から取り出す            （文字列 整数 -- 文字）
文字列の一部を取り出す        （文字列 整数 整数 -- 文字列）
文字列から探す                （文字列 文字列 -- 整数）
文字列を置き換える            （文字列 文字列 文字列 -- 文字列）
文字列を分割する              （文字列 文字列 -- 配列<文字列>）
```

長さ`N`の有効な位置は`0 <= 位置 < N`、有効な範囲は`0 <= 開始 <= 終了 <= N`です。一部取得は`[開始, 終了)`を返し、`[N,N)`を空文字列として受理します。

検索は、第1入力を対象、第2入力を検索文字列とし、両端が書記素境界に一致する最初の完全なスカラー値部分列を探します。成功時は開始書記素位置、失敗時は`-1`です。空の検索文字列は常に位置0で見つかります。

置換は対象、検索文字列、置換文字列の順です。空でない検索文字列について、書記素境界に一致する重ならない出現を左から右へすべて置換します。空の検索文字列は`E_EMPTY_SEARCH_TEXT`です。

分割は対象、区切り文字列の順です。空でない区切りの重ならない出現で分け、先頭・連続・末尾の空欄を空文字列要素として保持します。空の対象は`【「」】`です。空の区切りは`E_EMPTY_DELIMITER`です。

### 3.3 コードポイント操作

```text
文字列のコードポイント数                    （文字列 -- 整数）
文字列からコードポイントを取り出す          （文字列 整数 -- 文字）
コードポイント範囲で文字列の一部を取り出す  （文字列 整数 整数 -- 文字列）
コードポイント位置で文字列から探す          （文字列 文字列 -- 整数）
```

位置、半開区間、失敗時の`-1`、空検索の位置0は書記素操作と同じで、`N`だけをコードポイント数へ置き換えます。検索は書記素境界を要求しません。

1コードポイントを取り出した結果は、その1スカラー値だけからなる`文字`です。元の文字列内で結合文字やZWJ列の一部だった場合も、独立した1クラスタとして保持します。

## 4. 数値との明示変換

```text
整数を文字列に変換する    （整数 -- 文字列）
小数を文字列に変換する    （小数 -- 文字列）
文字列を整数に変換する    （文字列 -- 整数）
文字列を小数に変換する    （文字列 -- 小数）
```

数値から文字列への変換はNUM機能グループの正規値表示をそのまま使います。整数はASCIIの任意の`-`と数字、小数は小数点を必ず含む固定小数点です。

文字列からの変換は次のASCII文法だけを受理します。

```text
integerText := "-"? ("0" | nonZeroDigit digit*)
decimalText := "-"? ("0" | nonZeroDigit digit*) "." digit+
digit := "0".."9"
nonZeroDigit := "1".."9"
```

`-0`と`-0.0`は受理し、正規値の0へ変換します。2桁以上の先頭0、先頭末尾の空白、`+`、全角数字、桁区切りは受理しません。小数文字列の指数表記にはDTXT機能グループの契約を適用し、完全な文法と検査順は[DTXT機能グループ仕様](decimal-text.md)に従います。

## 5. 型、配列、等価性

`正規表現`はリテラルからだけ作る具体型で、定数、変数、局所値、利用者定義単語の具体的スタック効果に使用できます。文字列から実行時に正規表現をコンパイルする単語はありません。

`正規表現`は`等しい`と`表示可能`の型制約へ追加しません。意味の確認には正規表現操作を使います。`配列<正規表現>`は`E_ARRAY_ELEMENT_TYPE_NOT_ALLOWED`です。

既存の`配列<文字列>`は、分割結果にも使います。不変性、最大65,536要素、構築・要素処理予算、構造的等価性、表示を変更しません。

## 6. 原子性と評価順

各単語は入力をすべて検証し、結果の文字列長、配列長、正規表現予算を確認してから入力を消費して結果を積みます。大小文字変換で写像結果が16 MiBを超える場合は`E_STRING_UTF8_LIMIT`とし、入力をスタックに残します。失敗した呼出しは利用者スタック、保存値、stdoutを変更しません。呼出しより前に完了した処理は巻き戻しません。

文字列操作と配列操作を同じ式で組み合わせた場合は、ソース評価順で最初に到達した診断を報告します。

## 7. IRとトレース

文字列操作は具体的な効果を持つ既存`Call`、正規表現リテラルは型付き`PushConst`として表せます。IRには書記素境界表や正規表現エンジンの可変状態を保存しません。合成不正IRの型違いは内部エラー70です。

大小文字の3語は既存184語の辞書接頭辞を変更せず末尾へこの節の順で追加し、辞書は187語です。いずれも`TEXT`、`fixed`、能力なし、副作用なしの具体的`Call`です。UnicodeデータとlocaleはIRへ保存せず、処理系が固定するUnicode 16.0とroot localeを使います。

TEXT機能グループも21列TSVを変更しません。文字列は既存の`文字列:<値>`、正規表現は`正規表現:正規表現「<パターン>」<flags>`です。値部分は[text-regex-diagnostics.md](text-regex-diagnostics.md)のトレース境界で省略し、非開示時は長さ、パターン、フラグ、配列要素数を漏らしません。
