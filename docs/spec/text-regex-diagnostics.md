# TEXT機能グループ: 文字列・正規表現診断と資源境界

> 本文は現行実装の規範契約です。
>
> 現行契約: DTXT機能グループでは[小数文字列指数表記の診断](decimal-text-diagnostics.md)が、
> `E_DECIMAL_TEXT_INVALID`の入力文法と`E_DECIMAL_SCALE_LIMIT`の実行時フィールド・優先順位を上書きします。

## 1. 字句・静的診断

| コード | 段階 | 条件 | 位置 |
|---|---|---|---|
| `E_UNTERMINATED_REGEX_LITERAL` | 字句 | `正規表現「`に対応する`」`がない | リテラル開始から入力末尾 |
| `E_NEWLINE_IN_REGEX_LITERAL` | 字句 | rawパターンにCR/LFがある | 改行位置 |
| `E_REGEX_FLAG` | 字句 | `i`、`m`、`s`以外または重複 | フラグ文字 |
| `E_REGEX_SYNTAX` | 静的 | 規範部分集合として不正なパターン | パターン内のコードポイント位置 |
| `E_REGEX_UNSUPPORTED_CONSTRUCT` | 静的 | 後方参照、先読みなど | 構文の開始位置 |
| `E_REGEX_PATTERN_LIMIT` | 静的 | rawパターンが65,536 UTF-8バイト超 | リテラルspan |
| `E_REGEX_CAPTURE_LIMIT` | 静的 | キャプチャが64個超 | 65個目の開始 |
| `E_REGEX_PROGRAM_LIMIT` | 静的 | コンパイル命令が65,536個超 | リテラルspan |

型違い、スタック不足、代入不一致、`配列<正規表現>`は既存の`E_TYPE_MISMATCH`、`E_STACK_UNDERFLOW`、`E_ASSIGNMENT_TYPE_MISMATCH`、`E_ARRAY_ELEMENT_TYPE_NOT_ALLOWED`を再利用します。

## 2. 実行時診断

| コード | 条件 | 主なフィールド |
|---|---|---|
| `E_STRING_INDEX_OUT_OF_BOUNDS` | 書記素位置が`[0,N)`外 | `unit=grapheme`、位置、長さ、有効範囲 |
| `E_STRING_RANGE_OUT_OF_BOUNDS` | 書記素範囲が`0 <= 開始 <= 終了 <= N`外 | `unit=grapheme`、開始、終了、長さ |
| `E_CODE_POINT_INDEX_OUT_OF_BOUNDS` | コードポイント位置が`[0,N)`外 | `unit=codePoint`、位置、長さ、有効範囲 |
| `E_CODE_POINT_RANGE_OUT_OF_BOUNDS` | コードポイント範囲が不正 | `unit=codePoint`、開始、終了、長さ |
| `E_EMPTY_SEARCH_TEXT` | 通常置換の検索文字列が空 | `word` |
| `E_EMPTY_DELIMITER` | 通常分割の区切り文字列が空 | `word` |
| `E_INTEGER_TEXT_INVALID` | 整数入力文法に一致しない | 入力プレビュー、期待形式 |
| `E_DECIMAL_TEXT_INVALID` | 小数入力文法に一致しない | 入力プレビュー、期待形式 |
| `E_NUMERIC_TEXT_DIGIT_LIMIT` | 数字が4,096桁超 | 種類、上限、観測値 |
| `E_STRING_UTF8_LIMIT` | 生成結果が16,777,216 UTF-8バイト超 | 操作語、上限、観測値、入力プレビュー |
| `E_REGEX_NO_MATCH` | 抽出対象に一致がない | 操作語、入力・パターンプレビュー |
| `E_REGEX_GROUP_NOT_FOUND` | 指定名がパターンにない | 名前、利用可能名 |
| `E_REGEX_GROUP_UNMATCHED` | 一致した選択枝で指定群が不参加 | 名前、パターンプレビュー |
| `E_REGEX_REPLACEMENT_TEMPLATE` | 置換テンプレートが不正 | テンプレート位置、参照、群数・名前 |
| `E_REGEX_WORK_LIMIT` | 1呼出し照合単位が10億超 | 命令数、入力コードポイント、上限、観測値 |
| `E_REGEX_TOTAL_WORK_LIMIT` | 1実行累積照合単位が100億超 | 使用前、加算量、上限、観測値 |

分割結果には既存の`E_ARRAY_LENGTH_LIMIT`、`E_ARRAY_CONSTRUCTION_LIMIT`を適用します。数値変換の値上限はNUM機能グループの`E_INTEGER_RESULT_LIMIT`、`E_DECIMAL_RESULT_PRECISION_LIMIT`、`E_DECIMAL_SCALE_LIMIT`を再利用します。DTXT機能グループの小数文字列変換は構築前・正規化後スケールを値構築前に検査し、この経路では有効桁上限へ先に達しません。

## 3. 1呼出し内の優先順位

静的検査済みの1呼出しでは次の順で最初の1件だけを報告します。

1. 添字・範囲、空の検索文字列・区切り、名前付き群の存在、置換テンプレート構文
2. 数値入力文法、数字4,096桁上限
3. 正規表現の1呼出し・累積照合単位
4. 実際の照合に依存する一致なし・群不参加
5. 結果配列長と構築予算
6. 結果文字列のUTF-8長
7. 数値結果の有効桁、スケール、整数桁

事前に正確な結果長を求められる連結は照合を伴わず、直接6を検査します。置換・分割は照合を実行しても、結果を利用者スタックへ公開する前に全上限を検査します。

## 4. 診断プレビュー

文字列、正規表現、置換テンプレートの値部分が64 Unicodeコードポイントを超える場合は、先頭32、`…(+省略数)`、末尾16を使います。制御文字、引用符、バックスラッシュは文字列の標準エスケープで表し、長さの計数はエスケープ前のコードポイント列で行います。

構造化フィールドには省略前の`CodePoints`と`Utf8Bytes`を含められます。非開示ポリシーでは`<redacted>`だけとし、長さ、フラグ、群名、配列長を出しません。

## 5. トレース境界

- 非配列の文字列・文字・正規表現は値部分32コードポイントまで
- 文字列配列は先頭8要素、各要素16コードポイントまで
- 非配列値と配列内の長い文字・文字列は末尾`…`、9要素目以降は`…(+N)`、非開示は型名と`<redacted>`だけ

トレースのための書記素分割、コードポイント計数、正規表現表示は、文字列・配列・照合予算へ数えません。トレースの有無で実行結果と資源診断を変えません。

## 6. 原子性と到達不能コード

失敗する文字列・正規表現・変換単語は、入力スタック、保存値、stdout、配列構築単位を変更しません。照合単位は、その呼出しが上限検査を通って照合を開始するときに累積へ加えます。照合後に一致なし、群不参加、結果上限で失敗しても、その照合単位は消費済みです。照合開始前のテンプレート・予算検査で失敗した呼出しは累積を変更しません。

到達不能な文字列操作、変換、正規表現には既存の`W_UNREACHABLE_CODE`だけを報告し、派生する型・構文・資源診断を抑止します。formatは警告を出しません。
