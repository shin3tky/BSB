# WST機能グループ: 名前付き作業領域、ファイル、CSV/TSV

> 本文は現行実装の規範契約です。
>
> 前半の作業領域・ファイルは
> [前半の規範仕様](workspace-files.md)として確定しました。前半について内容が異なる場合は
> 前半仕様を優先します。CSV/TSVは
> [後半の規範仕様](delimited-tables.md)を確定し、内容が異なる場合は後半仕様を優先します。

## 1. 目的と範囲

WST機能グループは、事務作業で複数の入力ファイルを読み、CSVまたはTSVを検査・変換し、別の出力ファイルへ
書き戻す一周を完成させます。BSBプログラムへ任意のOSパスを渡さず、ソースで宣言した名前付き
`作業領域`と、ホストがその領域へ登録した論理ファイル名だけを使います。

前半で名前付き作業領域と`バイト列`による複数ファイル読書きを完成させ、後半でNARRAY機能グループの
`配列<配列<文字列>>`を使うCSV/TSVを追加します。前半の中央適合を後半のparser実装より先に完了します。

初期範囲は次です。

- 1ソースに複数の作業領域を宣言できる
- 1作業領域に複数の論理ファイル名を登録できる
- 論理ファイル名を`文字列`値として選び、ファイル全体を`バイト列`で読み書きする
- 読取り成功は完全内容を不変値にし、書込みはファイル単位の原子的な全置換とする
- 厳密UTF-8へは既存の`バイト列`変換語を明示的に通す
- CSVとTSVを、矩形性を検証した不変`配列<配列<文字列>>`へ解析し、決定的に直列化する
- CLIの反復`--file`と、単一の版付きTOMLの両方から複数ファイルを注入できる
- `explain --json`で作業領域ごとの読取・書込要求を静的に説明できる

次は含めません。

- BSB値としてのOSパス、URI、ファイル記述子、ディレクトリハンドル
- ディレクトリ列挙、glob、再帰走査、監視、削除、名前変更、追記、部分読書き
- シンボリックリンク、実パス、所有者、権限、時刻、拡張属性の観測
- 文字コード自動判定、Shift_JIS等の他文字コード、置換文字による寛容復号
- CSVの区切り文字自動判定、任意区切り、型推論、headerの特別扱い
- 複数ファイルをまたぐトランザクション、ロック、外部processとの同時更新保証、外部コマンド実行
- streaming、遅延行列、巨大ファイルの分割処理

## 2. 境界モデル

### 2.1 作業領域と論理ファイル名

作業領域は、ホストが提供する有限個の論理ファイル登録をまとめる名前付き資源です。各登録は次を持ちます。

| 項目 | 意味 |
|---|---|
| 作業領域名 | BSBソースで静的に宣言する名前 |
| 論理ファイル名 | BSBの`文字列`と完全一致させる可搬名 |
| 不透明なファイル参照 | OSパス等をBSBへ出さずにホストだけが保持する参照 |
| 許可操作 | `read`、`write`、または両方 |
| 1ファイル上限 | 読取・書込それぞれのバイト上限 |

初版の論理ファイル名は単一の名前であり、相対パスではありません。次をすべて満たします。

- NFC正規化済みのUnicodeスカラー値列
- UTF-8で1〜255バイト
- `/`、`\\`、NUL、U+0001〜U+001F、U+007Fを含まない
- `.`または`..`ではない

一致は、OSの大小文字規則や正規化規則ではなくUnicodeスカラー値列の完全一致です。BSBは論理名から
OSパスを構築できず、未登録名を使って作業領域外へ到達できません。ホスト設定内のOSパスはこの言語仕様の
ファイル名規則を受けず、ホストだけが解釈します。

### 2.2 複数ファイル

1実行で異なる作業領域、異なる論理ファイル名、同じ論理ファイルへの複数回操作を許します。各操作は
独立に解決・認可します。1ファイルへの書込み成功は他ファイルの後続失敗で戻しません。複数ファイルを
一括commitする意味はありません。

論理ファイル名は通常の`文字列`なので、ソース定数、計算結果、既存の起動引数から取得できます。
ただし、どの名前が実ファイルへ登録されるかはホスト設定だけが決めます。作業領域名自体は文字列にせず、
静的引数に固定します。

## 3. ソース構文

### 3.1 作業領域宣言

```text
帳票は 作業領域。
```

文法はCONN機能グループの論理接続宣言と同じトップレベル規則を使います。

```text
program                   := (wordDefinition | globalDeclaration
                              | logicalConnectionDeclaration
                              | workspaceDeclaration | trivia)* EOF
workspaceDeclaration      := identifier immediately-followed-by "は"
                              separator+ "作業領域" separator* "。"
```

初期値は持ちません。トップレベル以外の宣言、値を伴う宣言、重複名、予約名、隠蔽は、作業領域専用診断と
既存の名前診断をWST機能グループ診断仕様の順で返します。論理接続、利用者定義語、大域値、他の作業領域と
同じ大域名前空間を共有します。前方参照を許し、実行時保存スロットは持ちません。

1ソースの作業領域宣言は10,000個までとし、論理接続10,000個、値束縛10,000個とは別に数えます。

### 3.2 静的な作業領域引数

```text
「入力.csv」を ファイルを読む<帳票>
「出力.csv」と 結果のバイト列を ファイルへ書く<帳票>
```

`<帳票>`はCONN機能グループと同じく、正規語の直後に空白なしで置く静的引数です。引数は作業領域宣言へ解決し、
文字列、値束縛、論理接続、型名は指定できません。標準形は次です。

```text
ファイルを読む<帳票>
ファイルへ書く<帳票>
```

作業領域名を通常の本体名、値、配列要素、型位置に書いても値にはなりません。

## 4. ファイル値と操作

### 4.1 型

次の2失敗型を追加します。

- `ファイル読取失敗`
- `ファイル書込失敗`

どちらも閉じた不変値で、利用者は構築できません。保存、分岐合流、`任意`・`結果`の型引数には使えますが、
表示、等値比較、配列要素には使えません。元の論理ファイル名、OSパス、例外、部分データを保持しません。

### 4.2 読取り

```text
ファイルを読む<作業領域> (文字列 -- 結果<バイト列,ファイル読取失敗>)
```

入力は論理ファイル名です。ホストは登録済みの不透明参照を1回だけ読み、完全な内容を不変`バイト列`として
返します。空ファイルは長さ0の成功です。成功後の値は外部変更から独立しますが、別processが同じ物理
ファイルを同時に書き換える場合のsnapshot整合性やlockingは保証しません。次だけを回復可能な失敗値にします。

| 種類 | 条件 |
|---|---|
| `notFound` | 登録先の通常ファイルが操作時に存在しない |
| `notRegularFile` | 登録先が通常ファイルではない |
| `tooLarge` | 作業領域の読取方針上限を超えることが確定した |
| `ioFailure` | 安全に細分類できない読取I/O失敗 |

未登録名、利用拒否、能力不在・失敗、全実行上限、取消は捕捉不能診断です。ファイル内容が不正UTF-8、
CSV不正、TSV不正であることはファイル読取失敗ではありません。

### 4.3 書込み

```text
ファイルへ書く<作業領域> (文字列 バイト列 -- 結果<整数,ファイル書込失敗>)
```

成功整数は公開されたファイル内容のバイト数です。書込みは登録先全体を置き換えます。既存先または新規先と
同じ親領域に一時内容を完成させ、内容全体の書込み成功後に1回の原子的置換で公開します。公開前の失敗では
元の登録先を変更しません。原子的置換を保証できないホストは非原子的な上書きへfallbackしません。

読取・既存先検査は登録先の最終path componentでシンボリックリンクを追いません。最終componentが
シンボリックリンク、ディレクトリ、その他の特殊ファイルなら通常ファイルでない失敗です。親pathの解決方法は
ホスト設定責任ですが、解決結果やシンボリックリンク情報をBSBへ公開しません。

次だけを回復可能な失敗値にします。

| 種類 | 条件 |
|---|---|
| `parentNotFound` | 登録先の親が操作時に存在しない |
| `targetNotRegularFile` | 既存登録先が通常ファイルではない |
| `tooLarge` | 作業領域の書込方針上限を超える |
| `atomicReplacementUnavailable` | ホストが同一登録先への原子的公開を保証できない |
| `ioFailure` | 安全に細分類できない書込I/O失敗 |

成功は、後続の同じ作業領域能力から新内容全体が観測可能になったことを表します。停電耐久性、OS page cacheの
flush、権限・所有者・時刻・拡張属性の維持は保証しません。一時資源の削除失敗をBSBへ別の結果として返しません。

### 4.4 失敗種類の取出し

```text
ファイル読取失敗の種類を取り出す (ファイル読取失敗 -- 文字列)
ファイル書込失敗の種類を取り出す (ファイル書込失敗 -- 文字列)
```

返す値は第4.2節または第4.3節の安定ASCII識別値です。再試行可能性を種類から自動判定しません。

## 5. ホスト能力

### 5.1 能力と閉じた応答

次の平坦な能力を追加します。

```text
workspace.resolve
file.read
file.write
```

ファイル操作は作業領域を送信時と同様に毎回再解決します。resolverは正規化済み作業領域名と
`read|write`を受け、`RESOLVED`、`NOT_CONFIGURED`、`DENIED`、`INVALID`の閉じた4状態を返します。
`RESOLVED`は不透明な作業領域参照、許可操作、1ファイルの読取・書込上限だけをホスト内部に返します。

file能力は、不透明な作業領域参照、論理ファイル名、操作上限を受けます。物理パスを入力または応答の
公開部分へ含めません。登録なし、アクセス拒否、取消、回復可能失敗、成功を閉じた状態で返します。
null、未知状態、名前・参照不一致、上限を越えた成功値は内部契約違反で終了70です。

### 5.2 パラメータ付き能力

資源種別`workspace`と次の操作順を追加します。

```text
resolve, read, write
```

読取呼出しは同じ作業領域へ`resolve`と`read`、書込呼出しは`resolve`と`write`を要求します。同一利用者語と
推移要求の重複は統合します。実行時文字列である論理ファイル名は静的説明へ推測掲載しません。

`explain --json`外側版1と`parameterizedCapabilities`内側版1を維持します。既存の
`declarations`は論理接続宣言のままとし、加算的な`workspaceDeclarations`を追加します。
`summaryRequirements`と各利用者語の要求には既存形の`kind: "workspace"`を追加します。

## 6. NARRAY機能グループの二次元配列との境界

CSV/TSV専用の`表`型は追加しません。値表現はNARRAY機能グループの`配列<配列<文字列>>`です。行・セルの取出し、
置換、追加、反復、等価性、表示は既存配列語を使います。

二次元配列自体はraggedと0セル行を許します。CSV/TSV解析成功値は全行が同じ1個以上の列数を持つ矩形に
限定し、空文書だけを0行として許します。CSV/TSV直列化は入力二次元配列を検査し、raggedまたは0セル行を
捕捉不能な形式診断で拒否します。矩形性は配列型や配列値の不変条件へ追加しません。

header、列名、型、null、欠損値は引き続き持ちません。空文字列は通常のセルです。

## 7. CSV/TSVの厳密方言

### 7.1 共通文法

CSVはASCII comma U+002C、TSVはASCII tab U+0009を区切りとし、それ以外は同じ文法です。
[RFC 4180](https://www.rfc-editor.org/rfc/rfc4180.html)を参考にしますが、ここに記す規則をBSBの規範とし、
特定ライブラリの挙動を採用しません。

```text
document       := bom? (record lineBreak)* record? lineBreak?
record         := field (delimiter field)*
field          := unquoted | quoted
quoted         := DQUOTE quotedContent* DQUOTE
quotedContent  := nonQuoteScalar | delimiter | CR | LF | DQUOTE DQUOTE
lineBreak      := CRLF | LF | CR
bom            := U+FEFF at document start only
```

実際の解析器はCRLFを1改行として消費し、CRとLFを別々の2改行にしません。次を固定します。

- 入力はBSB`文字列`であり、ファイルからは既存の厳密UTF-8復号を先に行う
- 文書先頭のU+FEFFを最大1個だけBOMとして除去する
- BOM以外のU+FEFFは通常のセル文字
- 引用符はU+0022で、quoted field内の`""`だけが1個の引用符になる
- unquoted fieldの区切り、CR、LF、引用符は文法文字でありデータにできない
- quoted fieldの閉じ引用符後は、区切り、改行、入力末尾だけを許す
- 空白をtrimせず、comment、backslash escape、区切り自動判定を行わない
- NULはquoted/unquotedのどちらでも拒否する
- 空入力は0行0列
- 区切りだけの入力は1行2空セル、1改行だけの入力は1行1空セル
- 改行はその時点のrecordを終端し、入力が改行直後に終わっても次の空recordを開始しない
- この規則により末尾改行は任意で、`LF LF`は空セル1個のrecordを2行、`LF`は1行として扱う
- 2行目以後の列数が最初の行と異なる場合は解析失敗
- 最初の行をheaderとして扱わない

### 7.2 解析

```text
CSVを表として解析する (文字列 -- 結果<配列<配列<文字列>>,区切りテキスト解析失敗>)
TSVを表として解析する (文字列 -- 結果<配列<配列<文字列>>,区切りテキスト解析失敗>)
```

外部データの文法不正だけを失敗値にします。安定種類は次です。

```text
unexpectedQuote
unexpectedCharacterAfterQuote
unterminatedQuotedField
nulCharacter
columnCountMismatch
```

`区切りテキスト解析失敗`は種類、0始まりUTF-8バイト位置、1始まり物理行、1始まりUnicodeスカラー列だけを
保持します。元入力、セル、期待列数・実列数、delimiter、例外を保持しません。取出し語は次の4個です。

```text
区切りテキスト解析失敗の種類を取り出す
区切りテキスト解析失敗のバイト位置を取り出す
区切りテキスト解析失敗の行を取り出す
区切りテキスト解析失敗の列を取り出す
```

CSV/TSVの行数、列数、セル数、構築・作業上限は資源診断であり、失敗値へ変換しません。

### 7.3 直列化

```text
表をCSVに変換する (配列<配列<文字列>> -- 文字列)
表をTSVに変換する (配列<配列<文字列>> -- 文字列)
```

直列化は次の一意な形式です。

- BOMを付けない
- record間と最終record後にCRLFを1個置く
- 空の外側配列は空文字列
- 非空入力の各行は1セル以上で、先頭行と同じセル数でなければ診断終了
- delimiter、引用符、CR、LFを含むセルだけをquoted fieldにする
- quoted field内の引用符を`""`へ置換する
- それ以外の文字を正規化、trim、型変換しない

セル先頭の`=`, `+`, `-`, `@`等を表計算式対策として自動変更しません。利用者データを忠実に保つ層と、
特定表計算ソフト向けの安全化方針を分離します。BOM付き出力、LF固定出力、任意dialectは後続です。

### 7.4 辞書順と効果

WST機能グループの公開項目は、NARRAY機能グループ完了予定の155項目の後ろへ、ファイル4、CSV/TSV変換4、
解析失敗取出し4の順で12項目を追加します。別名はありません。すべて`featureGroup`は`"WST"`、
`typeRule`は`fixed`、`returnsNormally`は`true`です。

CSV/TSV解析・直列化と失敗取出しは純粋です。ファイル読取は`workspace.resolve`と`file.read`、
書込は`workspace.resolve`と`file.write`を能力・副作用へ持ちます。読取も外部状態を観測するため、現行辞書で
能力と副作用が同じ文字列になる扱いを維持しますが、2概念を統合しません。

`作業領域`、新3失敗型名、新12項目名を予約します。個々の作業領域名は利用者名であり、言語全体の予約名には
加えません。

## 8. 資源上限

### 8.1 ファイル

| 資源 | 上限 |
|---|---:|
| 1ソースの作業領域宣言 | 10,000 |
| 1実行の受理済みファイル操作 | 4,096 |
| 1ファイルの読取・書込方針 | 1〜67,108,864バイト |
| CLI直接指定時の既定上限 | 16,777,216バイト |
| 1実行のファイル読取累積 | 134,217,728バイト |
| 1実行のファイル書込試行累積 | 134,217,728バイト |
| 1値のバイト列 | 67,108,864バイト（既存） |

読取累積は実際に受け取った完全内容だけを成功前に加算します。上限+1読取りで全実行残量超過が確定した場合は、
上限を越えない値まで加算して捕捉不能診断にします。書込試行累積は能力へ委譲する前に本文全量を加算し、
回復可能失敗でも戻しません。拒否された予約は加算しません。

### 8.2 CSV/TSVと二次元文字列配列

| 資源 | 上限 |
|---|---:|
| CSV/TSV入力・出力 | 16,777,216 UTF-8バイト（既存文字列上限） |
| 1行・外側配列の直接要素 | 65,536（NARRAY機能グループ配列上限） |
| 1二次元値の論理セル | 1,000,000（NARRAY機能グループ論理葉上限） |
| 1実行の配列構築単位 | 1,000,000（既存・NARRAY機能グループ） |
| 1実行の配列要素処理単位 | 10,000,000（既存・NARRAY機能グループ） |
| 1実行の区切りテキスト作業 | 134,217,728 |

解析成功時は各行のセル参照と外側の行参照を既存配列構築単位へ課金します。解析1回の区切りテキスト作業は
`入力UTF-8バイト数 + 入力Unicodeスカラー数`、直列化1回は
`全セルの入力UTF-8バイト数 + 候補出力UTF-8バイト数`です。いずれも有限幅で一括予約し、累積上限へ
加算します。既存文字列・配列・バイト列予算を、この作業予算を理由に省略しません。巨大候補は完全な
中間文字列や二次元配列を作る前に有限幅で測ります。

## 9. 原子性、判定順、時間

ファイル操作は、命令・能動時間、内部不変条件、能力存在、操作回数・累積予約、workspace解決、登録・認可、
file能力委譲、閉じた応答検査、バイト列または結果の構築、スタック置換の順です。捕捉不能診断では入力
スタック、保存値、両出力を変更しません。物理読書きと受理済み累積予算は、能力委譲後の失敗で戻しません。

ファイルI/O待機はHTTP待機と同じく30秒の能動実行時間から除外しますが、命令数、ファイル操作回数、
累積バイト上限は適用します。取消は全実行の診断であり、失敗結果へ変換しません。

CSV/TSV解析は第8.2節の区切りテキスト作業を予約してから1回走査し、成功時だけ内側・外側の
配列構築を予約して入力文字列を結果へ置換します。文法失敗では作業を戻しません。直列化は矩形性、
0セル行、候補資源、予算、出力スタックを検査してから原子的に置換します。

## 10. 非開示とtrace

通常traceと診断`dataStack`では次を常に伏せます。

```text
ファイル読取失敗:<redacted>
ファイル書込失敗:<redacted>
区切りテキスト解析失敗:<redacted>
```

`バイト列`と入れ子の`任意`・`結果`は既存の推移的非開示を継承します。能力イベントは能力名、既定では
作業領域名、`read|write`、閉じた結果だけを保持します。論理ファイル名、OSパス、内容、長さ、delimiter、
一時ファイル名、例外を含めません。より強いホスト方針は作業領域名も伏せられます。

専用語で取り出した失敗種類・位置は通常値です。CSV/TSV成功値は通常の二次元文字列配列なので、セルは
NARRAY機能グループの配列・文字列trace方針に従います。ファイル由来というtaintを値へ保持せず、内容をtraceへ出したくない
ホストはtrace無効化または強い値伏字方針を選びます。ファイル能力イベント自体は内容を公開しません。

## 11. CLIとTOML注入

### 11.1 直接指定

`run`のソース前で、次の4引数組を反復できます。

```text
bsb run \
  --file <作業領域名> <論理ファイル名> <read|write|read-write> <OSパス> \
  [--file ...] [--connections <接続.toml>] <ソース.bsb> -- [引数...]
```

例です。

```text
bsb run \
  --file 帳票 入力.csv read ./data/sales.csv \
  --file 帳票 出力.csv write ./out/summary.csv \
  transform.bsb -- 入力.csv 出力.csv
```

反復`--file`は最大4,096件です。作業領域名・論理ファイル名の同じ組を重複指定できません。相対OSパスは
CLIプロセスの作業ディレクトリ基準です。直接指定の1ファイル上限は読書きとも16 MiBです。

### 11.2 TOML指定

```text
bsb run --workspaces <設定.toml> [--connections <接続.toml>] <ソース.bsb> -- [引数...]
```

版1の例です。

```toml
schema-version = 1

[workspaces."帳票"]
maximum-read-bytes = 16777216
maximum-write-bytes = 16777216

[workspaces."帳票".files."入力.csv"]
path = "../data/sales.csv"
access = "read"

[workspaces."帳票".files."出力.csv"]
path = "../out/summary.csv"
access = "write"
```

TOMLは1 MiB以下、BOMなし厳密UTF-8、TOML 1.0、作業領域1〜256、全ファイル1〜4,096件です。
未知・重複・型違いの項目を拒否します。相対OSパスは設定TOMLの親ディレクトリ基準です。
最大値の省略時は16 MiB、指定可能範囲は1〜64 MiBです。

`--file`と`--workspaces`は同時使用できません。`--connections`とは併用でき、順序はソースより前なら任意、
各設定ファイル指定は1回だけです。自動探索、複数TOMLのmerge、include、profile、上書き規則、環境変数展開は
行いません。

設定エラーはプログラム実行前、stdout 0バイト、秘密を含まない`作業領域設定エラー`、終了78です。
設定ファイル自身の明示パスは対象として表示できますが、登録先OSパス、TOML入力行、parser自由文は
表示しません。

## 12. 適合環境

中央適合は実OSファイルシステムを使わず、複数作業領域・複数ファイル、読取、原子的書込成功、各閉じた失敗、
取消、能力失敗、予算、traceを再現する不変な偽能力を使います。JDK実ファイル能力は一時ディレクトリだけを
使う統合試験とし、利用者ホーム、リポジトリ外、シンボリックリンク、実権限変更へ依存しません。

CSV/TSVの期待値は本番parser、外部CSVライブラリ、表計算ソフトの出力から生成せず、仕様表から独立に固定します。
RFC 4180との差やTSV方言は適合READMEに明記します。

## 13. 後続互換性と対象外

後続でディレクトリ型や相対パスを追加しても、初版の有限登録、論理名完全一致、静的作業領域名、全読書き、
原子的置換の意味を変更しません。directory root方式を追加する場合は別のホスト設定schema版とし、
初版の`--file`を暗黙に広いroot権限へ昇格させません。

streaming CSV、行iterator、型付き列、header mapping、dialect設定、BOM付き出力、複数ファイルtransaction、
preview/diff/確認、ファイル削除、外部コマンドは利用実績を見て別の機能グループで設計します。
