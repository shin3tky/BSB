# CORE機能グループ: プログラム表記の基本

> 本文は現行実装の規範契約です。
>
> この文書は、BSBのCORE機能グループについて、正常例、失敗例、期待診断を含む適合条件を定めます。全機能グループにまたがる意味論とCLIの概要は[最小言語仕様の概説](../language-overview.md)を参照してください。

この文書と次の文書を合わせて、CORE機能グループの規範仕様とします。内容が重なる場合は、対象を専門に扱う文書の記述を優先します。

- [language-core-grammar.md](language-core-grammar.md): 字句、構文、予約機能、名前境界
- [language-core-unicode.md](language-core-unicode.md): Unicode 16.0適合
- [language-core-format.md](language-core-format.md): 一意な標準形
- [language-core-builtins.md](language-core-builtins.md): 初期7組み込み単語の意味論と辞書情報
- [language-core-diagnostics.md](language-core-diagnostics.md): 診断コード、資源上限、数え方
- [language-core-conformance.md](language-core-conformance.md): 適合データ、章末プログラム、トレース

## 1. 適用範囲

CORE機能グループは、UTF-8ソースを読み、単語定義を解析し、名前、型、スタック効果を検査し、最小の組み込み辞書を使って `メイン` を実行できるところまでを対象とします。

CORE機能グループで実行できる値の型は次の4種類です。

```text
整数
真偽
文字
文字列
```

CORE機能グループの組み込み辞書は次の7単語です。

```text
足す             （整数 整数 -- 整数）
引く             （整数 整数 -- 整数）
掛ける           （整数 整数 -- 整数）
等しい           （T T -- 真偽）
表示する         （表示可能 --）
一行表示する     （表示可能 --）
改行する         （--）
```

`T` と `表示可能` は辞書専用の型制約です。意味論と副作用を含む完全な辞書は [language-core-builtins.md](language-core-builtins.md) に従います。利用者定義単語のスタック効果には書けません。

条件分岐、繰り返し、定数、変数、配列、数値演算の拡張、文字列操作、コンソール入力は後続機能グループで導入します。後続機能グループのために予約された型、値、単語をCORE機能グループで使った場合は、未定義とはせず `E_FEATURE_NOT_AVAILABLE` を報告します。

## 2. ソースファイル

### 2.1 UTF-8

ソースファイルの文字コードはUTF-8です。不正なUTF-8バイト列は、字句解析より前に `E_INVALID_UTF8` とします。

ファイル先頭のUTF-8 BOM、すなわちバイト列 `EF BB BF` は受理し、プログラム上の文字として扱いません。`bsb format` はBOMを出力しません。ファイル途中のU+FEFFは不可視文字として `E_INVISIBLE_CHARACTER` にします。

ソースファイルの大きさと診断位置のUTF-8バイトオフセットは、BOMを含む元ファイルを基準にします。したがってBOMつきファイルでは、最初の実トークンの `utf8Start` は3です。

### 2.2 改行と区切り

LF、CR、CRLFを改行として受理し、CRLFは1改行として数えます。単語の区切りとして受理する文字は次のものだけです。

- U+0020 ASCII空白
- U+0009 タブ
- U+3000 全角空白
- LF、CR、CRLF
- `、` U+3001
- `，` U+FF0C

`、` と `，` は空白相当の区切りで、構文木には残しません。ASCIIの `,` は区切りではありません。上記以外のUnicode空白は `E_DISALLOWED_WHITESPACE` にします。

### 2.3 コメント

文字列・文字リテラル外の `#` から物理行末までは行コメントです。`#` の直前に空白は必要ありません。ブロックコメントはありません。

文字列・文字リテラル内の `#` と `。` は通常の文字です。

## 3. 字句

### 3.1 識別子

識別子は、全角英数字だけをASCII相当へ変換した後、NFCで正規化します。英字の大文字と小文字は区別します。カテゴリー、NFC、書記素クラスタ、紛らわしい名前の判定はUnicode 16.0へ固定し、[language-core-unicode.md](language-core-unicode.md) に従います。

```text
識別子先頭 := Unicode Letter
識別子継続 := Unicode Letter
            | Unicode Mark
            | Unicode Number
            | "_"
            | "・"
```

制御文字、ゼロ幅文字、双方向テキスト制御文字、Variation Selectorなどの不可視書式文字は、Unicodeカテゴリー上の許可規則にかかわらず禁止します。識別子は正規化後で最大128 Unicodeコードポイントです。

### 3.2 数値リテラル

> 基本の固定小数点文法は次のとおりです。EXP機能グループでは
> [指数表記仕様](exponent-literals.md)がこの小節の数値文法と指数拒否だけを上書きします。

```text
ASCII数字    := "0" | "1" | ... | "9"
非ゼロ数字   := "1" | ... | "9"
整数          := "-"? ("0" | 非ゼロ数字 ASCII数字*)
小数          := "-"? ("0" | 非ゼロ数字 ASCII数字*) "." ASCII数字+
```

正数の `+`、複数桁の先頭の0、`.5`、`1.`、指数表記、桁区切り、全角数字は受理しません。リテラルは最大4,096桁です。符号と小数点は桁数に含めません。

数値リテラルの直後には、区切り、`。`、`#`、またはファイル終端が必要です。`123円` のような入力を2単語へ暗黙分割しません。

小数リテラルはCORE機能グループでも字句解析と構文解析を行い、`bsb format` で整形できます。ただし、CORE機能グループの型付き実行には含めません。`bsb check` と `bsb run` は小数リテラルまたはスタック効果中の `小数` に `E_FEATURE_NOT_AVAILABLE` を報告します。

### 3.3 真偽値

`はい` と `いいえ` は `真偽` 型の組み込み値です。利用者定義名として使用できません。

### 3.4 文字列と文字

文字列の標準形は `「` と `」` で囲みます。ASCIIの `"` で囲む表記も入力として受理します。文字はASCIIの `'` で囲みます。

```text
「こんにちは」
"こんにちは"
'A'
'𠮷'
```

文字列と文字では次のエスケープを使用できます。

| 表記 | 値 |
|---|---|
| `\n` | LF |
| `\r` | CR |
| `\t` | タブ |
| `\\` | バックスラッシュ |
| `\"` | ASCII二重引用符 |
| `\'` | ASCII単一引用符 |
| `\「` | 始め二重かぎ括弧 |
| `\」` | 終わり二重かぎ括弧 |
| `\u{...}` | Unicodeスカラー値 |

`\u{...}` は1桁以上6桁以下の16進数字を受理します。U+10FFFFを超える値とサロゲート領域を拒否します。未エスケープのCRまたはLFをリテラル内に直接書けません。

文字リテラルはエスケープ展開後に拡張書記素クラスタちょうど1つでなければなりません。内容に識別子用のNFC正規化は適用しません。

文字列の最大UTF-8長は、エスケープ展開後で16,777,216バイトです。

## 4. 構文

この節は構文の概要です。トークンの走査、`とは`の分割、終端、予約機能、エラー回復を含む完全な規則は [language-core-grammar.md](language-core-grammar.md) に従います。

```text
ソース         := 区切り* (単語定義 区切り*)* EOF

単語定義       := 定義開始 区切り+ スタック効果
                  単語本体
                  "こと" 水平空白* "。"

定義開始       := 識別子 "とは"  # 空白なし

スタック効果   := "（" 型列? "--" 型列? "）"
                | "(" 型列? "--" 型列? ")"

型列           := 型名 (区切り+ 型名)*

単語本体       := 本体要素*
本体要素       := リテラル | 識別子 | 助詞 | 区切り
```

単語名と `とは` の間に空白は許しません。`こと` と `。` の間にはASCII空白、タブ、全角空白だけを受理します。改行、コメント、`、`、`，`は受理しません。標準形は空白なしの `こと。` です。

全角とASCIIのスタック効果括弧を混在させません。入力と出力の区切りはASCIIハイフン2個の `--` だけです。

定義開始とスタック効果の間、およびスタック効果の括弧内にはコメントを置けません。コメントはスタック効果の後、単語本体、またはトップレベルへ置きます。

トップレベルには単語定義だけを書けます。すべての単語定義にスタック効果が必要です。

### 4.1 空の単語本体

空の単語本体を許可します。空の本体はスタックを変更しないため、宣言した入力型列と出力型列が同一の場合にスタック効果検査へ合格します。

```text
何もしないとは （--）
こと。

そのままとは （整数 -- 整数）
こと。
```

次は、本体が空であることではなく、宣言した効果と実際の効果が一致しないためエラーです。

```text
捨てるとは （整数 --）
こと。
```

## 5. 名前解決

処理系は、すべてのトップレベル定義名を本体の検査より先に収集します。前方参照、直接再帰、相互再帰を許可します。

正規化後の名前で重複と予約名との衝突を判定します。衝突診断には入力名、正規化後の名前、先に登録された名前と位置を含めます。

利用者が別名を定義する構文はCORE機能グループに含めません。別名は組み込み辞書のメタデータとして扱い、CORE機能グループの7組み込み単語の別名集合は空です。

`メイン` はちょうど1つ必要です。スタック効果は `（--）` でなければなりません。正常終了時にデータスタックへ値を残せません。

## 6. 型とスタック効果の検査

利用者定義単語の検査では、宣言された入力型列を仮想スタックの初期状態とし、本体の各要素を順に適用します。助詞は型付きスタックを変更しません。本体終了時の型列は、宣言された出力型列と完全に一致しなければなりません。

呼び出し時には、単語が必要とする値の個数と型をスタック最上部側から検査します。暗黙の型変換は行いません。単語を呼ぶ前からスタックにあった、呼び出しが消費しない値はそのまま残ります。

空の本体にも同じ検査を適用し、特別な例外規則は設けません。

## 7. 助詞

`を`、`に`、`と`、`から`、`で` は実行時のスタックを変更しません。字句トークンと構文木には種類と位置を保持し、実行用IRの命令にはしません。

CORE機能グループでは日本語としての助詞選択までは判定せず、次の構造的な問題だけを `W_PARTICLE_POSITION` として警告します。

- 単語本体の先頭にある
- 単語本体の末尾にある
- 助詞が連続している
- コメントと区切りを除いた直前または直後に、リテラルまたは呼び出し可能な名前がない

```text
を 10 表示する
10 を と 表示する
10 表示する を
```

警告だけの場合、`check` と `run` の終了コードは0です。助詞の選択や順序によって値を並べ替えません。

## 8. フォーマッタ

`bsb format` は字句解析と構文解析に成功したソースを標準出力へ書き、入力ファイルを変更しません。名前解決、型検査、スタック効果検査は行いません。

BOM、改行、空行、コメント、行分け、引用符、エスケープ、整数、小数、識別子、ファイル末尾を含む完全な標準形は [language-core-format.md](language-core-format.md) に従います。任意の有効なソース `S` について、バイト列として `format(format(S)) = format(S)` でなければなりません。

## 9. 診断契約

診断フィールド、順序、抑止、全コード、人間向け表示、資源上限の数え方は [language-core-diagnostics.md](language-core-diagnostics.md) に従います。初版CLIは人間向け表示だけを実装しますが、後から追加するJSON診断も同じ内部情報から生成します。

```text
二倍とは （整数 -- 整数）

こと。
```

| `bsb check` | なし | なし | 0 |
| `bsb run` | `42` とLF | なし | 0 |

### CORE-N019: 空の本体

```text

    42 を そのまま
    一行表示する
こと。
```

`bsb run` は `42` とLFを出力し、終了コード0を返します。

### CORE-F014: 定義終端の欠落

```text
メインとは （--）
    改行する
```

期待診断:

```text
sample.bsb:3:1: エラー[E_EXPECTED_WORD_END]: 「メイン」の定義を閉じる「こと。」が必要です。
  修正候補: ここに「こと。」を追加してください。
```

元ソースに対応する文字がないため、EOFの挿入位置を `point` として保持します。

### CORE-F017: 正規化後の重複

```text
請求Ａ１とは （--）
こと。

請求A1とは （--）
こと。
```

期待診断:

```text
sample.bsb:4:1: エラー[E_DUPLICATE_NAME]: 「請求A1」は正規化すると、すでに定義されている「請求Ａ１」と同じ名前になります。
  正規化後: 請求A1
  最初の定義: 1行1列
```

### CORE-F021: スタック不足

```text
メインとは （--）
    1 を 足す
こと。
```

期待診断:

```text

  必要: [整数, 整数]
  実際: [整数]
  修正候補: 「足す」の前に整数をもう1つ置いてください。
```

### CORE-F022: 型不一致

```text
メインとは （--）
    「10」 と 20 を 足す
    表示する
こと。
```

期待診断:

```text
sample.bsb:2:17: エラー[E_TYPE_MISMATCH]: 「足す」の第1入力には整数が必要ですが、文字列が渡されています。
  必要: [整数, 整数]
```

## 12. CORE機能グループの完了条件

- CORE-N001からCORE-N022までの正常例が機械可読な期待値どおりに検査、整形、実行できる
- CORE-F001からCORE-F030まで（枝番を含む）がコマンド別に同じ診断コード、診断情報、標準出力、標準エラー、終了コードを返す
- CORE-R001からCORE-R014までが上限ちょうどを受理し、1単位超えた入力を規定コードで拒否する
- 診断の行、列、UTF-8バイト範囲が元ソースを指す
- Unicode 16.0の識別子、NFC、UAX #29、UTS #39適合データを通過する
- 助詞を構文木とソースマップへ保持し、IR命令にはしない
- 検査に失敗した構文木からIRを生成しない
- `format` の冪等性テストがすべて成功する
- 初期7組み込み単語の全辞書項目を内部APIから取得できる
- 章末プログラムの通常実行とトレース実行が同じ終了コード、出力、最終スタックになり、規定の命令トレースと一致する
