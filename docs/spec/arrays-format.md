# ARRAY機能グループ: 配列のフォーマッタ仕様

> 本文は現行実装の規範契約です。
>
> [language-core-format.md](language-core-format.md)、[control-flow-format.md](control-flow-format.md)、[bindings-format.md](bindings-format.md)へ追加する規則を定めます。

## 1. 基本原則

`format`はUTF-8、字句、構文だけを検査します。配列要素型、空配列型、スタック効果、添字範囲、到達可能性は検査しません。

出力はBOMなしUTF-8、LF、末尾LFちょうど1個です。BIND機能グループまでの構文だけからなる入力の正規出力は変更しません。

## 2. コメントを含まない配列

コメントを含まない配列リテラルは、要素式の個数や出力行長にかかわらず1行にします。

```text
【1、2、3】
【1 と 2 を 足す、値】
【】
```

- `【`の直後、`】`の直前に空白を置かない
- 要素間は`、`1個とし、その前後に空白を置かない
- 要素式内部は通常の本体行と同じくトークン間にASCII空白1個を置く
- 入力の全角コンマ`，`は`、`へ変換する
- 空配列は`【】`とする

静的に不正な`【】`、混在型、複数値要素も、構文として有効なら整形に成功します。

## 3. コメントを含む配列

配列内にコメントが1個でもある場合、開始記号、各要素式、終端記号を別の行へ置きます。

```text
【
    70、 # 国語
    80、 # 数学
    90
】
```

配列を含む外側要素の字下げを基準に、要素式を1段深くします。終端`】`は開始`【`と同じ字下げです。最後以外の要素行にはコメントより前に`、`を付け、最後の要素には付けません。

コメントだけの行は、そのコメントが属する要素境界を変えず要素の字下げへ置きます。コメントを越えて要素式を移動しません。要素式内の行末コメントはASCII空白1個を置いて結合します。

コメントを含む配列が宣言初期値にある場合も、宣言の複数行規則と配列の字下げを合成します。

```text
点数は 定数
    【
        70、 # 国語
        80
    】
。
```

## 4. 配列型

配列型はASCIIの`<`と`>`を使い、内部に空白を置きません。

```text
配列<整数>
配列<文字列>
```

入力`配列 < 整数 >`も構文として受理した場合は`配列<整数>`へ統一します。型名は既存どおり正規化後の正式名を出します。多次元配列や後段型でも、構文として有効なら型・機能診断を行わず同じ記号配置へ整形します。

## 5. 配列操作

5個の配列操作語は通常の組み込み単語と同じく、その呼出しで現在行を確定します。

```text
点数 を 配列の長さ
点数 と 0 を 配列から取り出す
点数 と 1 と 4 を 配列の一部を取り出す
点数 と 2 と 100 を 配列の要素を置き換える
点数 と 95 を 配列の末尾へ追加する
```

助詞は値の順序を変えません。組み込み単語名の内部にある`の`、`から`、`を`、`へ`を別トークンへ分割しません。

## 6. 配列反復

`各要素について`は現在の未確定行へ追加して行を確定し、本体を1段深くします。`繰り返す`は開始語と同じ字下げの独立行です。

```text
点数 を 各要素について
    一行表示する
繰り返す
```

空本体、到達不能な本体、静的に不正なスタックを構文どおり保持します。入れ子の条件分岐、既存ループ、配列反復は各1段ずつ字下げします。

## 7. 冪等性

任意のARRAY機能グループまでの構文として有効なソース`S`について、バイト列として次を満たします。

```text
format(format(S)) = format(S)
```

適合試験では、1行配列、コメントつき配列、型表記、配列反復、静的失敗を含む全format成功ケースへ2回目の適用を行います。
