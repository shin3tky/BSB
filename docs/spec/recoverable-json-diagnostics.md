# RJSON機能グループ: 回復可能なJSON解析の診断と失敗境界

> 本文は現行実装の規範契約です。

本仕様は[回復可能なJSON解析](recoverable-json-parsing.md)について、結果値へ変換する失敗、
捕捉不能診断、優先順位、予算、原子性、非開示を定めます。

## 1. 新規診断コード

RJSON機能グループでは診断コードを追加しません。静的な入力不足・型不一致と、捕捉不能なJSON・実行資源上限は
既存コードを再利用します。回復可能な入力不正は診断ではなく`JSON解析失敗`値です。

`JSONを解析して結果を返す`が失敗結果を返した実行は、他の後続失敗がなければ終了0、CLI診断なしです。

## 2. 回復可能な失敗への写像

厳密JSONパーサーが次を返した場合だけ、入力1値を`失敗(JSON解析失敗)`1値へ置き換えます。

| 内部解析分類 | 公開種類 | 公開位置 | 診断 |
|---|---|---|---|
| `SYNTAX` | 既存`reason`の12値 | UTF-8バイト位置、行、列 | なし |
| `DUPLICATE_KEY` | `duplicateKey` | 2個目のキーの開始位置 | なし |

`expected`、重複キー文字列、最初のキー位置は失敗値へ写しません。同じ入力に対する既存
`JSONを解析する`は、従来どおり`E_JSON_SYNTAX`または`E_JSON_DUPLICATE_KEY`を返します。

## 3. 捕捉不能診断

次は結果値へ変換しません。

| 条件 | 既存診断 | 理由 |
|---|---|---|
| BSB入力文字列またはJSON入力長の上限 | `E_STRING_UTF8_LIMIT` | 値・資源上限 |
| JSON数値の桁・精度・スケール上限 | `E_JSON_NUMBER_LIMIT` | 資源境界 |
| JSON容器の深さ上限 | `E_JSON_DEPTH_LIMIT` | 資源境界 |
| JSON値ノード数上限 | `E_JSON_NODE_LIMIT` | 資源境界 |
| 1配列の要素数上限 | `E_JSON_ARRAY_LENGTH_LIMIT` | 資源境界 |
| 1オブジェクトのメンバー数上限 | `E_JSON_OBJECT_MEMBER_LIMIT` | 資源境界 |
| JSON構築累積上限 | `E_JSON_CONSTRUCTION_LIMIT` | 全実行の資源境界 |
| JSON作業累積上限 | `E_JSON_WORK_LIMIT` | 全実行の資源境界 |
| データスタック上限 | `E_DATA_STACK_LIMIT` | 全実行の資源境界 |
| 命令数・実行時間上限 | `E_INSTRUCTION_LIMIT`、`E_EXECUTION_TIMEOUT` | 全実行の制御境界 |
| 型・スタック・合流・保存の誤り | 既存の静的診断 | プログラム契約違反 |
| 能力不在・拒否、全実行取消 | 各既存または後続診断 | ホストが強制する境界 |
| 未知の内部解析分類、値不変条件違反 | 内部失敗 | 処理系契約違反 |

能力不在・拒否と全実行取消はこの純粋操作自身からは発生しませんが、回復可能な操作全体の境界として
固定します。将来HTTP操作が同じ結果型方針を使っても、ホストの利用拒否や全実行取消を通信失敗値へ
縮退させません。

## 4. 静的診断

結果返却操作と取出し4語には、固定スタック効果の既存診断を適用します。

| 条件 | 診断 | 必須fieldsの基準 |
|---|---|---|
| 入力不足 | `E_STACK_UNDERFLOW` | `word`、`requiredCount`、`actualCount` |
| 入力型不一致 | `E_TYPE_MISMATCH` | `word`、`inputIndex`、`expectedType`、`actualType` |
| 新しい型・語名の再定義 | `E_RESERVED_NAME` | 既存予約名規則 |
| 非表示型の表示 | `E_TYPE_MISMATCH` | `expectedType=表示可能`、原因型`JSON解析失敗` |
| 非比較型の等値比較 | `E_TYPE_MISMATCH` | `expectedType=等値比較可能`、原因型`JSON解析失敗` |

分岐、ループ、代入、利用者語の効果不一致は既存の診断順とfieldsを使います。到達不能コードは
`W_UNREACHABLE_CODE`により派生する型・スタック診断を抑止します。新しい構文はないため、字句・
構文診断と`format`規則を追加しません。

## 5. 実行順と最初の失敗

`JSONを解析して結果を返す`は次の順で処理し、捕捉不能条件では最初の1診断だけを返します。

1. 既存の静的スタック・型検査
2. 呼出し前の命令数、実行時間上限
3. 入力`文字列`の不変条件とUTF-8長
4. 入力UTF-8バイト数のJSON作業単位を一括予約
5. JSON文法を先頭から検査
6. 各位置で構文、容器深さ、容器長、ノード数、数値上限、重複キーを既存順で判定
7. `SYNTAX`または`DUPLICATE_KEY`なら失敗値を構築し、スタックを1対1で置換
8. 全入力を受理した場合はJSON構築単位を一括予約
9. 成功JSONを構築し、スタックを成功結果へ1対1で置換

同じ入力位置で文法と資源条件が同時に不正なら、[JSON機能グループの診断仕様](json-diagnostics.md)の
解析順を維持します。文法として確定した`SYNTAX`または`DUPLICATE_KEY`だけが手順7へ進みます。
資源上限を文法失敗に見せかけたり、先に失敗結果を公開してから資源診断へ変更したりしません。

種類・位置の取出し4語は、命令数・実行時間を検査した後に入力値を出力値へ置き換えます。
型検査済み値の内部不変条件が壊れている場合は利用者向け診断に変換しません。

## 6. 予算消費

| 終了 | JSON作業 | JSON構築 | スタック |
|---|---|---|---|
| 解析成功 | 入力UTF-8バイト数 | 既存の値ノード＋全直接要素・メンバー | `文字列`を`成功(JSON)`へ置換 |
| 回復可能な入力不正 | 入力UTF-8バイト数 | 0 | `文字列`を`失敗(JSON解析失敗)`へ置換 |
| 作業予約の拒否 | 0追加 | 0 | 不変 |
| 解析中の捕捉不能上限 | 入力UTF-8バイト数 | 0 | 不変 |
| JSON構築予約の拒否 | 入力UTF-8バイト数 | 0追加 | 不変 |

表の「0追加」は失敗した予約が累積値を変えない意味です。先行する成功操作と命令課金は戻しません。
失敗値または結果ラッパーの構築をJSON構築単位へ数えず、取出し4語は命令以外の専用予算を使いません。

## 7. 原子性

回復可能な入力不正は操作として正常終了します。入力文字列1値を失敗結果1値へ一度に置き換え、
中間の空スタック、部分JSON、仮の失敗文字列を観測可能にしません。保存値、stdout、stderr、能力イベントは
不変です。

捕捉不能診断では入力文字列をスタックに残し、保存値、両プログラム出力、能力イベントを変更しません。
消費済みJSON作業と命令数だけは第6節どおり維持します。Javaの`StackOverflowError`、
`OutOfMemoryError`、例外クラス名、部分的な結果値を規範上の終了として認めません。

取出し4語は1対1の置換なので追加スタック枠を必要としません。入力型は静的に保証され、正常な
`JSON解析失敗`からの取出しは状態不一致診断を持ちません。

## 8. 診断とトレースの非開示

結果返却操作が発生させる捕捉不能診断は、既存コード、`word`、上限、件数、入力内位置など判定に
必要な構造化情報だけを返します。次を`fields`、`expected`、`actual`、`fixes`、`related`、
人間向けメッセージへ入れません。

- 元入力文字列またはそのプレビュー
- 不正トークンの原文
- 重複したキーと利用可能なキー一覧
- 部分的に構築したJSON値
- `JSON解析失敗`の内部表現またはJava例外名

捕捉不能診断時は実行スタックを原子的に保つため入力文字列が残りますが、共通`dataStack`では当該
入力スロットを`文字列:<redacted>`とします。他スロットの既存非開示規則を弱めません。

既定トレースは呼出し前の入力文字列、呼出し後の成功・失敗結果、保存された失敗値をすべて伏せます。
トレースの有無は結果、予算、能力イベント、診断を変更しません。

## 9. 既存診断との互換性

既存`JSONを解析する`の14診断、fields、優先順位、終了10、入力スタック原子性は変更しません。
RJSON機能グループで追加する非開示文脈は新しい結果返却語の呼出しに限定し、既存goldenを理由なく書き換えません。

診断カタログは182件のままです。公開`check --json`と`explain --json`は版1を維持し、
回復可能な失敗値を診断配列へ混入させません。

## 10. 実装監査点

- `JsonCodec`／厳密パーサーを共有し、2つの公開語で文法や位置が分岐しない
- 内部解析分類を、結果へ写す2分類と診断へ写す6分類に全列挙する
- 将来enum値追加時に暗黙の既定枝で捕捉範囲が広がらない
- 失敗値へ`JsonParseException`や入力`String`の参照を保持しない
- 成功JSONを結果で包んでも既存構築・作業予算を迂回しない
- 結果失敗時には既存診断を生成せず、捕捉不能時には失敗結果を生成しない
- `dataStack`非開示が実行値や原子性を変更しない
