# DTXT機能グループ: 小数文字列の指数表記

> 本文は現行実装の規範契約です。
>
> 本仕様はTEXT機能グループの`decimalText`と、EXP機能グループの「文字列変換は指数を拒否する」という
> 機能境界を変更します。ここで明示的に変更しない規則は、両機能グループから引き継ぎます。

## 1. 範囲

DTXT機能グループでは、`文字列を小数に変換する`が受理するASCII入力文法へ10進指数表記を追加します。
新しい型、組み込み語、診断コード、暗黙変換、桁区切り、2進・8進・16進表記、16進浮動小数、
`NaN`、無限大は追加しません。

次は変更しません。

- `文字列を整数に変換する`の入力文法と値
- BSBソース数値リテラルのEXP機能グループ文法、字句診断、`format`
- JSON数値のRFC 8259文法とJSON固有診断
- `小数`の正確な値、正規化、固定小数点表示、等価性、演算、トレース
- 公開辞書107語、`check --json`と`explain --json`の版1

## 2. 入力文法

```text
digit          := "0" | "1" | ... | "9"
nonZeroDigit   := "1" | ... | "9"
integerPart    := "0" | nonZeroDigit digit*
fraction       := "." digit+
exponent       := ("e" | "E") ("+" | "-")? digit+

decimalText    := "-"? integerPart (fraction exponent? | exponent)
```

小数点または指数部の少なくとも一方が必要です。`1.0`、`1e2`、`1E2`、`1e+2`、
`1e-2`、`1.5e3`、`-0e10`、`1e002`を受理します。指数部の先頭0は許可します。

`1`、`+1e2`、`01e2`、`.5e2`、`1.e2`、`1e`、`1e+`、`1e-`、`1ee2`、
前後に空白を持つ入力、全角数字、桁区切りは拒否します。文字列値全体が文法へ一致する必要があり、
ソースLexerの区切り規則やUnicode正規化は適用しません。

TEXT機能グループの`integerText := "-"? ("0" | nonZeroDigit digit*)`は変更しません。
したがって`文字列を整数に変換する`は`1e2`と`1.0`を引き続き拒否します。

## 3. 型、値、表示

指数の有無や数学的な値にかかわらず、成功結果は常に`小数`です。仮数の小数点を除いた
符号つき係数を`c`、小数部の数字数を`f`、符号つき指数を`p`とすると、値は次です。

```text
値              = c × 10^(p - f)
構築前スケール  = f - p
```

値は丸めません。0は正規の0へ、0以外は係数末尾0を除いたNUM機能グループの`DecimalValue`へ変換します。
表示には指数を使わず、小数点を必ず含めます。例として`1e2`は`100.0`、`1.500e2`は
`150.0`、`1e-2`は`0.01`、`-0e10`は`0.0`です。

## 4. 資源上限と安全な構築

入力数字は4,096個までです。仮数と指数部に現れるASCII数字を、先頭0と末尾0を含めて
すべて数えます。先頭符号、小数点、指数記号、指数符号は数えません。

1呼出しは次の順で検査します。

1. 入力全体が第2節の`decimalText`に一致するか
2. 入力数字が4,096個以下か
3. 構築前スケール`f - p`の絶対値が65,536以下か
4. 正規化後スケールの絶対値が65,536以下か
5. 検査済みの係数とスケールから正規小数を構築できるか

構築前スケールは、値が0で正規化後スケールが0になる場合にも検査します。`0e65536`は成功し、
`0e65537`は失敗します。`10e65535`は正規化後スケール`-65536`で成功し、`10e65536`は
`-65537`で失敗します。

指数は有限幅へ飽和させながら走査します。巨大指数を`Integer.parseInt`、無検査の
`BigDecimal(String)`、指数展開した固定小数文字列へ渡してはなりません。入力数字上限により
正規化係数の有効桁は4,096以下なので、この変換経路で
`E_DECIMAL_RESULT_PRECISION_LIMIT`は発生しません。

## 5. 原子性、CLI、整形

失敗した変換は入力文字列をスタックに残し、保存値、stdout、配列・JSON予算を変更しません。
呼出しより前に完了した処理は巻き戻しません。

`check`と`format`は文字列の内容を数値として評価しません。したがって、実行時には文法または
資源上限で失敗する文字列を含むソースも、静的に型が正しければ`check`でき、`format`は文字列内容を
保持します。`run`だけが変換呼出しへ到達した時点で第4節を適用し、実行時終了10を返します。

通常CLIと`check --json`の版、終了コード、出力チャネルは変更しません。実行時診断は通常の
`run`でstderrへ出し、失敗呼出しによるstdoutの部分結果を出しません。

## 6. 独立契約の境界

文法判定と値構築はEXP機能グループの有限幅小数字句解析を共有できますが、次を混同しません。

- ソース数値は字句・静的段階、文字列変換は実行時段階で診断する
- ソースの数字超過は`E_NUMBER_LIMIT`、文字列変換は`E_NUMERIC_TEXT_DIGIT_LIMIT`を使う
- 不正ソースは`E_INVALID_NUMBER_LITERAL`とreason、不正文字列は`E_DECIMAL_TEXT_INVALID`を使う
- JSON解析はJSONパーサーとJSON固有診断を維持する
- `format`はソース数値字句と文字列リテラルの元表記を保持し、変換後の値表示とは独立する
