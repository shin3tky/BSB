# NUM機能グループ: 数値のフォーマッタ仕様

> 本文は現行実装の規範契約です。
>
> [language-core-format.md](language-core-format.md)から[arrays-format.md](arrays-format.md)へ追加する規則を定めます。
>
> EXP機能グループでは[指数表記仕様](exponent-literals.md)が、有効な指数字句も元表記のまま保持する規則を追加します。

## 1. ソース字句と実行値を分ける

`format`はUTF-8、字句、構文だけを検査し、小数値の生成、型検査、除算、丸めを行いません。

CORE機能グループから受理している有効な小数字句は、その字句を保持します。したがって次の入力はformat後も同じです。

```text
-0.0
1.00
0.00100
```

これはCORE〜ARRAY機能グループのformat互換性を維持するためのソース表記規則です。`run`の値表示は[numerics.md](numerics.md)の正規値表記を使うため、同じ3値は`0.0`、`1.0`、`0.001`と表示されます。

## 2. 型と組み込み値

`小数`、`丸め方法`、`配列<小数>`はそれぞれこの表記へ正規化します。配列型の`<`と`>`の内側には空白を置きません。

5個の丸め方法値とNUM機能グループの組み込み単語名は通常の名前として保持します。助詞は値を並べ替えません。

## 3. 小数配列

小数配列もARRAY機能グループの配列規則に従います。

```text
【1.20、2.0、3.250】
空の小数配列
```

formatは要素の字句を値として正規化せず、整数と小数の混在も検査しません。コメントなしは1行、コメントありは要素単位の複数行です。

## 4. 冪等性

NUM機能グループまでの構文として有効な任意のソース`S`について、バイト列として次を満たします。

```text
format(format(S)) = format(S)
```

出力はBOMなしUTF-8、LF、末尾LFちょうど1個です。ARRAY機能グループまでのcanonical資源は変更しません。
