# RJSON機能グループ: 回復可能なJSON解析と`JSON解析失敗`

> 本文は現行実装の規範契約です。
>
> 先行する実装済み機能グループの規則は、ここで明示的に変更する箇所以外、引き続き有効です。

## 1. 目的と範囲

RJSON機能グループでは、回復可能であることを操作自身が宣言する最初の実例として、文字列をJSONへ解析し、
入力データに起因する失敗を`結果<JSON,JSON解析失敗>`で返す操作を追加します。これにより利用者は、
不正な外部入力を実行全体の診断終了にせず、通常の分岐で処理できます。

この機能グループは、任意の実行時診断を捕捉する構文・語、結果の自動伝播、汎用`map`、利用者定義の失敗型、
HTTP、認証、論理接続、再試行を追加しません。既存`JSONを解析する (文字列 -- JSON)`の名前、効果、
診断、終了方法も変更しません。

診断と捕捉不能境界は[RJSON機能グループの診断仕様](recoverable-json-diagnostics.md)で定めます。

## 2. 公開型

### 2.1 `JSON解析失敗`

`JSON解析失敗`は、回復可能なJSON入力不正を表す、null非許容・不変・閉じた組み込み具体型です。
値は次の情報だけを保持します。

| 項目 | 型 | 意味 |
|---|---|---|
| 種類 | `文字列` | 第3節の安定ASCII識別値 |
| UTF-8バイト位置 | `整数` | 入力先頭を0とする失敗位置 |
| 行 | `整数` | 1始まりの物理行 |
| 列 | `整数` | 1始まりのUnicodeスカラー値列 |

元の入力文字列、部分文字列、重複したキー、期待トークン、人間向けメッセージ、Java例外は保持しません。
利用者が`JSON解析失敗`を直接構築する語やリテラルはありません。第4節の結果返却操作だけが値を
生成します。

`JSON解析失敗`は次に利用できます。

- 定数、変数、大域・局所保存、利用者定義語の入出力
- 分岐・ループのスタック合流
- `任意<JSON解析失敗>`、`結果<T,JSON解析失敗>`を含む型引数

一方、`表示する`、`一行表示する`、`等しい`の対象、および`配列<T>`の要素型にはできません。
失敗内容は専用の取出し語で観測します。これにより、位置や種類を確認したいコードと、失敗値全体を
誤って出力するコードを区別します。

`JSON解析失敗`とIO機能グループの`入力結果`は別型です。前者は通常の失敗結果のペイロードであり、
能力取消や全実行の取消を表しません。

## 3. 安定した失敗種類

`JSON解析失敗の種類を取り出す`が返す文字列は、次の13値のいずれかです。

```text
emptyInput
unexpectedToken
trailingContent
expectedObjectKey
expectedColon
expectedCommaOrEnd
unterminatedString
unescapedControl
invalidEscape
invalidUnicodeEscape
isolatedSurrogate
invalidNumber
duplicateKey
```

先頭12値は既存`E_JSON_SYNTAX.fields.reason`と同じ意味です。重複キーは既存診断コードとの対応が
明確になるよう`duplicateKey`とします。値の綴りと意味は公開契約です。大文字小文字、区切り、
日本語化を行いません。

この集合はRJSON機能グループでは閉じています。将来種類を追加する場合は、未知文字列を受け取った利用側が
既定枝へ進める前提で追加し、既存値の意味を変えません。数値桁、深さ、ノード数、容器長、入力長、
累積予算の上限超過をこの集合へ追加しません。

## 4. 結果を返す解析操作

### 4.1 正規語と効果

```text
JSONを解析して結果を返す (文字列 -- 結果<JSON,JSON解析失敗>)
```

入力文字列全体を、[JSON機能グループのJSON仕様](json-values.md)と同じ文法、値モデル、入力内位置規則で
解析します。空白、数値、Unicode、重複キー、決定的なJSON値は既存解析と同一です。

| 結果 | 出力 |
|---|---|
| 規範JSONとして解析成功 | `成功(JSON)` |
| 第3節の入力不正 | `失敗(JSON解析失敗)` |
| 捕捉不能条件 | RJSON機能グループの診断仕様に従って実行終了 |

結果値はRESULT機能グループの通常の`結果<T,E>`です。専用の判定・伝播構文は追加しません。

### 4.2 利用例

```text
JSON入力を読むとは （文字列 -- 文字列）
    JSONを解析して結果を返す
    結果が成功である ならば
        結果から成功値を取り出す
        JSONを文字列に変換する
    さもなければ
        結果から失敗値を取り出す
        JSON解析失敗の種類を取り出す
    つぎに
こと。
```

有効な`{"x":1}`は正規化されたJSON文字列を返し、不正な`{`は`expectedObjectKey`を返します。
返された失敗値は診断ではなく正常な値なので、後続命令を自動終了させません。

### 4.3 既存解析語との共存

既存語はそのまま残します。

| 語 | 入力不正 | 主な用途 |
|---|---|---|
| `JSONを解析する` | 既存`E_JSON_SYNTAX`または`E_JSON_DUPLICATE_KEY`で終了 | 入力が有効であることを前提にする処理 |
| `JSONを解析して結果を返す` | `失敗(JSON解析失敗)`を返して継続 | 外部入力を利用者コードで分類する処理 |

一方を他方の別名にせず、`format`も各正規語を維持します。内部では同じ厳密パーサーと位置計算を
共有してよいものとしますが、公開終了方法は呼出し語ごとに固定します。

## 5. 失敗値の取出し語

次の4語を追加します。すべて入力の`JSON解析失敗`を消費し、外部能力と追加の専用予算を使いません。

| 正規語 | スタック効果 | 結果 |
|---|---|---|
| `JSON解析失敗の種類を取り出す` | `JSON解析失敗 -- 文字列` | 第3節の安定識別値 |
| `JSON解析失敗のバイト位置を取り出す` | `JSON解析失敗 -- 整数` | 0始まりUTF-8バイト位置 |
| `JSON解析失敗の行を取り出す` | `JSON解析失敗 -- 整数` | 1始まりの行 |
| `JSON解析失敗の列を取り出す` | `JSON解析失敗 -- 整数` | 1始まりUnicodeスカラー列 |

行と列はCR、LF、CRLFを各1改行として扱い、タブを1 Unicodeスカラー・1列として数える既存規則を
継承します。入力末尾の欠落はUTF-8長と等しいバイト位置と、最終文字直後の行・列を返します。

複数項目が必要なら、失敗値を保存して各取出し語の前に読み出します。取出し時に入力JSONを再解析せず、
JSON作業・構築予算を追加消費しません。

## 6. 型検査、保存、表示、等価性

結果返却操作と4取出し語は固定スタック効果です。既存の静的検査をそのまま適用します。

- 入力不足は`E_STACK_UNDERFLOW`
- 入力型不一致は`E_TYPE_MISMATCH`
- 分岐、ループ、代入、利用者語の効果不一致は既存の各診断
- 構造的に到達不能な呼出しは`W_UNREACHABLE_CODE`だけを報告

`JSON解析失敗`を含む`結果`や`任意`も、非選択側を含む型全体で表示可能性と等値比較可能性を
判定します。このため`結果<JSON,JSON解析失敗>`は表示・等値比較できません。状態を判定して対応する
値を取り出してから、JSONまたは失敗情報を個別に扱います。

型名、保存、合流、IRスタック効果では常に正規名`JSON解析失敗`を使います。暗黙の文字列変換、
JSON値への埋込み、汎用エラー型への昇格は行いません。

## 7. 非開示

`JSON解析失敗`は元入力を保持しません。既定トレースでは、失敗値を次の形で常に伏せます。

```text
JSON解析失敗:<redacted>
結果<JSON,JSON解析失敗>:<redacted>
```

`任意`・`結果`に入れ子になった場合も、型全体へ推移的に適用し、状態、種類、位置を表示しません。
利用者が専用語で取り出した種類文字列や位置整数は通常の文字列・整数であり、その後は既存の表示・
保存・トレース規則に従います。

結果返却操作が生成する失敗値、通常トレース、診断の専用fields、共通`dataStack`へ、元入力、
不正トークン、重複キー、入力プレビューを複写しません。捕捉不能診断時の入力スタックを原子的に
保つ場合でも、当該呼出しの入力文字列は診断用`dataStack`で`文字列:<redacted>`とします。
これは実行スタック上の値を変更する規則ではありません。

## 8. 資源と原子性

結果返却操作は既存JSON解析と同じ課金を行います。

1. 呼出し命令を既存命令予算へ課金する。
2. 入力UTF-8バイト数を測り、同数のJSON作業単位を一括予約する。
3. 厳密パーサーで入力を走査する。
4. 成功時だけ、値ノード数、配列要素数、オブジェクトメンバー数から既存JSON構築単位を予約する。
5. 入力1値を、成功または回復可能な失敗の結果1値へ置き換える。

`JSON解析失敗`と`結果`の包装、4取出し語には、JSON構築・作業、配列、正規表現の追加課金を
設けません。通常の命令数とスタック値数には含めます。

回復可能な入力不正では、手順2のJSON作業だけを消費し、JSON構築単位は消費しません。入力文字列を
失敗結果へ原子的に置き換え、stdout、stderr、保存値、外部能力を変更しません。

捕捉不能診断では、入力スタック、保存値、stdout、stderrを変更しません。手順2を受理した後の
解析中に判明した上限超過では、その入力走査作業を戻しません。JSON構築予約に失敗した場合も入力は
文字列のままですが、先行する入力走査作業は消費済みです。診断CLIがstderrへ出す文面はプログラムの
stderr副作用ではありません。

## 9. 静的説明と公開互換性

`explain --json`は公開版1を維持し、既存119語の後ろにRJSON機能グループの5語を仕様順で追加します。
各語の`featureGroup`は`"RJSON"`、`capabilities`と副作用集合は空、`returnsNormally`は`true`です。
結果返却操作と取出し4語は既存の`fixed`型規則を使います。

新しい型名と語名は予約名です。既存ソースがこれらを利用者名として定義していた場合は、外部公開版前の
意図的な予約名追加として`E_RESERVED_NAME`になります。`check --json`、`explain --json`の
`schemaVersion=1`に新しいメンバーは追加しません。

## 10. この機能グループに含めないもの

- 既存`E_*`診断を結果へ変換する汎用捕捉
- 資源上限、能力拒否、取消、実行時間上限、内部失敗の捕捉
- 結果の自動伝播、早期復帰演算子、汎用`map`
- `JSON解析失敗`の利用者構築、表示、等値比較、配列要素化
- 原入力、キー、期待トークン、人間向けメッセージの失敗値への保存
- JSON Schemaまたは業務上の形状検証
- HTTP応答本文の文字コード判定、バイト列、通信失敗

この機能グループの役割は、1本の純粋操作で「回復可能なドメイン失敗」と「捕捉不能な処理系診断」を分離し、
後続HTTPが同じ境界を再利用できることを実証するところまでです。
