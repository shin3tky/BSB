# NARRAY機能グループ: 二次元配列

> 本文は現行実装の規範契約です。

## 1. 目的と機能境界

NARRAY機能グループは、既存の同種・不変`配列<T>`を二次元まで拡張します。正規型は新しい別名や`表`ではなく、
既存の型構築子を入れ子にした`配列<配列<T>>`です。WST-TABLE機能グループのCSV/TSVは
`配列<配列<文字列>>`を使い、CSV専用の容器型を追加しません。

NARRAY機能グループで完成させる範囲は次です。

- 二次元配列型、入れ子配列リテラル、型付き空二次元配列
- raggedな行を含む不変値
- 既存5配列操作の外側・内側への適用
- 既存`各要素について`を入れ子にした行・要素反復
- 構造的等値比較、決定的表示、通常trace
- 1容器、1二次元値、1実行の資源上限と失敗原子性

次は含めません。

- 三次元以上の配列
- 配列要素としての`任意<T>`、`結果<T,E>`、失敗型、HTTP型、バイト列
- 矩形性、列数、列名、header、schema、セル型、null、欠損値
- 二次元専用の行・列・セル操作語、転置、行列演算
- CSV/TSV、ファイル、作業領域、streaming
- 可変配列、要素への破壊的代入、view、参照同一性

## 2. 次元と許可要素型

### 2.1 正規型

NARRAY機能グループの配列型文法は次です。

```text
arrayType        := "配列" "<" arrayElementType ">"
arrayElementType := allowedScalarType | oneDimensionalArrayType
oneDimensionalArrayType := "配列" "<" allowedScalarType ">"
allowedScalarType := "整数" | "真偽" | "文字" | "文字列" | "小数" | "JSON"
```

正規表記は空白なしの`配列<配列<文字列>>`です。入力では既存規則どおり型記号内の通常区切りを許し、
`format`は正規形へ統一します。

配列の次元は、最外の`配列`から許可スカラー葉型までに現れる`配列`型構築子の個数です。

- `配列<文字列>`は一次元
- `配列<配列<文字列>>`は二次元
- `配列<配列<配列<文字列>>>`は三次元で不許可

`任意`・`結果`の型構築子深さ上限256は維持しますが、配列要素型にはできません。
`配列<任意<文字列>>`、`配列<結果<文字列,文字列>>`、
`配列<配列<任意<文字列>>>`はいずれも不許可です。

### 2.2 型の一致

型は全階層で構造的に完全一致します。次はすべて異なる型です。

```text
配列<文字列>
配列<配列<文字列>>
配列<配列<整数>>
```

一次元から二次元、異なる葉型、raggedと矩形の間に暗黙変換はありません。raggedかどうかは値の形であり、
静的型の一部ではありません。

## 3. 値モデルと不変性

二次元配列値は、同じ一次元配列型を持つ0個以上の行を順序付きで保持する外側配列です。各行は既存の
一次元不変配列です。

```text
【【1、2】、【3】、空の整数配列】
```

この値の型は`配列<配列<整数>>`で、行長は2、1、0です。二次元配列はraggedを許し、全行が同じ長さで
あることを要求しません。同じ行値を複数位置から参照してもよく、共有の有無は観測できません。

外側の一部取得、行置換、行追加は新しい外側配列を返し、既存行を共有できます。内側の要素置換・追加は
新しい行を返し、元行と元二次元配列を変更しません。二次元配列の特定セルを書き換える暗黙操作は追加せず、
「行を取り出す、行を更新する、外側へ戻す」を明示します。

## 4. リテラルと型付き空値

### 4.1 入れ子配列リテラル

既存配列リテラルの要素式が、許可スカラー値または一次元配列値を正確に1個残せるようになります。

```text
【【「氏名」、「金額」】、【「佐藤」、「1200」】】
```

外側の全要素は同じ`配列<文字列>`でなければなりません。行長は型一致へ影響しません。
葉型が異なる次の値は既存`E_ARRAY_ELEMENT_TYPE_MISMATCH`です。

```text
【【「a」】、【1】】
```

入れ子要素式も、空の分離抽象スタックから検査して正確に1値を残します。副作用、利用者定義語、制御構文、
宣言、代入を要素式へ置けない既存規則は維持します。純粋な配列操作は、必要入力を同じ要素式内で作る場合に
使用できます。

三次元リテラルは既存`E_NESTED_ARRAY_NOT_AVAILABLE`です。診断の意味を「すべての入れ子禁止」から
「三次元以上は未対応」へNARRAY機能グループで狭めます。

### 4.2 空値

型を逆向き推論しない既存規則を維持するため、`【】`と`【【】】`だけでは型を決めません。

- `【】`は既存`E_EMPTY_ARRAY_TYPE_REQUIRED`
- `【【】】`は内側の`E_EMPTY_ARRAY_TYPE_REQUIRED`

外側が空の二次元配列には次の6組み込み値を追加します。

| 正規名 | 型 |
|---|---|
| `空の整数二次元配列` | `配列<配列<整数>>` |
| `空の真偽二次元配列` | `配列<配列<真偽>>` |
| `空の文字二次元配列` | `配列<配列<文字>>` |
| `空の文字列二次元配列` | `配列<配列<文字列>>` |
| `空の小数二次元配列` | `配列<配列<小数>>` |
| `空のJSON二次元配列` | `配列<配列<JSON>>` |

空行には既存の`空の整数配列`等を使います。

```text
【空の文字列配列、【「x」】】
```

この値は`配列<配列<文字列>>`です。外側空値は0行ですが、将来の列数を保持しません。

## 5. 既存配列操作の一般化

既存5語の型変数`T`は、許可スカラー型に加えて許可された一次元配列型にも具体化できます。

```text
配列の長さ                 (配列<T> -- 整数)
配列から取り出す           (配列<T> 整数 -- T)
配列の一部を取り出す       (配列<T> 整数 整数 -- 配列<T>)
配列の要素を置き換える     (配列<T> 整数 T -- 配列<T>)
配列の末尾へ追加する       (配列<T> T -- 配列<T>)
```

外側二次元配列では`T=配列<S>`です。したがって、取出しは行、置換と追加は同じ葉型の行を扱います。
取り出した行へ既存操作を使う場合は一次元配列として動作します。

セルを更新する場合は、利用者語の中で外側配列を保存し、対象行を取り出して内側の要素を置き換え、
保存した外側配列の同じ行位置へ新しい行を戻します。専用のcell更新語や暗黙lensは追加しません。

添字、半開区間、長さ上限、入力順、失敗原子性は一次元配列と同じです。行型が異なる置換・追加は静的な
`E_TYPE_MISMATCH`です。

## 6. 配列反復

`各要素について`は外側配列から行を順に1回ずつ渡します。反復本体の要素型が
`配列<T>`になる以外、入口・出口スタック、`打ち切る`、`続ける`、字句scopeの規則を変更しません。

```text
二次元配列を 各要素について
    各要素について
        表示する
    繰り返す
繰り返す
```

外側が空なら内側へ到達せず、空行では内側本体を0回実行します。入れ子制御状態は既存どおり外側から内側の
順で保持します。

## 7. 等価性、表示、trace

### 7.1 等価性

`等しい`は同じ二次元配列型どうしを比較できます。外側長、各位置の行長、各セルを順に比較し、すべて
等しい場合だけ`はい`です。raggedな形も値の一部です。異なる型どうしは既存の静的型不一致です。

要素型の表示・比較特性は配列階層を通して葉型から再帰的に導きます。NARRAY機能グループで許可する6葉型はすべて
既存の表示・等値比較対象です。

### 7.2 表示

表示は既存配列リテラルを再帰的に使います。

```text
【【1、2】、【3】、【】】
【【「a」、「b」】、【「c」】】
```

表示の64 MiB上限、原子的stdout書込み、文字列escapeを維持します。結果長と作業予算を通るまで一部を
出力しません。

### 7.3 trace

通常traceは各配列階層で先頭8要素まで、文字・文字列葉は既存の先頭16 Unicode code pointまでを使います。
9要素以上の省略数はその階層について表示します。JSON葉は既存の推移的非開示に従って値全体を伏せます。
NARRAY機能グループで新しい秘密性分類は追加しません。

trace用省略は配列構築・要素処理予算を消費せず、値全体を走査しません。traceの有無で診断、予算、結果を
変えません。

## 8. 資源上限

既存の1配列上限と1実行予算を維持し、二次元値の論理葉要素上限を追加します。

| 資源 | 上限 | 数え方 |
|---|---:|---|
| 1配列容器の直接要素 | 65,536 | 外側の行参照、各内側の葉要素を個別に適用 |
| 1二次元配列の論理葉要素 | 1,000,000 | 全行長の合計。共有行も出現位置ごとに数える |
| 1実行の配列構築単位 | 1,000,000 | 新しく作る各配列容器の直接要素参照数 |
| 1実行の配列要素処理単位 | 10,000,000 | 比較候補、表示候補、複製、反復等の直接要素参照 |
| 表示結果 | 67,108,864 UTF-8バイト | 既存表示上限 |

外側配列の値は各行の長さを合計した`logicalLeafCount`を有限幅で保持または計測します。加算overflow、負数、
上限超過値を実行値として構築できません。同じ65,536要素の行を複数回共有しても、論理上の各出現を数えます。

構築単位は構造共有した既存行の葉を再課金せず、新しい外側容器へ格納する行参照だけを課金します。
一方、1値の論理葉上限は共有に関係なく検査します。これにより、少ない物理参照で巨大な論理走査量を持つ値を
作れません。

外側の追加・置換は、元の合計から対象行長を引き、新行長を加える有限幅計算で1値上限を先に検査できます。
一部取得は対象行のcached長を合計します。等値比較と表示は、走査前に求めた比較・表示候補の外側行参照と
内側葉を既存要素処理単位へ一括予約します。早期不一致で実走査を止めても予約を戻しません。内側の既存
一次元操作は従来どおりです。

## 9. 原子性と判定順

二次元リテラルと外側操作は次の順で判定します。

1. 既存の命令数・能動実行時間
2. 静的に検査済みの次元、葉型、入力型に対応する実行値不変条件
3. 1容器65,536直接要素
4. 1二次元値1,000,000論理葉要素
5. 配列構築単位と要素処理単位を一括予約
6. 結果用データスタック上限
7. 新しい不変外側容器を構築し、入力を置換

拒否された予算予約は加算しません。既存行を共有しても、条件をすべて通るまで元配列、入力スタック、保存値、
stdout、stderrを変更しません。比較・表示の走査開始後に予算を逐次消費せず、cached metricsから安全に
一括予約できる場合は一括を優先します。

## 10. 型・IR・実行モデル

公開意味論を保つため、実装モデルを次のように一般化します。

- `ArrayType`の要素型を`ScalarType`から`ValueType`へ変更する
- `arrayElementType()`は`Optional<ValueType>`を返す
- `ArrayValue`の宣言要素型を`ValueType`にする
- `BuildArray`は検査済みの`ValueType`と直接要素数を保持する
- 型parserとconstructor depth計算は配列の内側も走査する
- analyzerの5配列型規則と配列loopは`T=配列<S>`を扱う
- runtime値の検証は各要素の完全な`ValueType`一致を要求する

許可方針は「任意の`ValueType`を配列へ入れる」ことではありません。構造を一般化した上で、公開型生成時に
「許可スカラー葉、配列次元2以下」を検査します。`任意`・`結果`等を誤って配列要素へ解禁しません。

合成した不正IR、要素型と値型の不一致、三次元値、壊れたcached metricsは利用者診断へ推測変換せず
内部エラー70です。

## 11. 組み込み辞書と公開説明

HTTPS機能グループまでの149項目の後ろへ、第4.2節の型付き空二次元配列6項目を仕様順で追加します。

- `featureGroup`: `"NARRAY"`
- `typeRule`: `fixed`
- 能力・副作用: なし
- `returnsNormally`: `true`

既存5配列操作の名前、機能グループ`"5"`、説明文、型変数表記を変更しません。型規則の具体化範囲だけを
二次元へ広げます。`explain --json`外側版1は維持し、組み込み辞書へ6項目を加算します。

`配列`、`T`の既存予約を維持し、新6項目名を予約します。`二次元配列`を型名や型構築子として予約しません。

## 12. 適合方針

NARRAY機能グループの中央適合では少なくとも次を独立期待として固定します。

- 6葉型の二次元型、空値、入れ子literal、ragged、空行
- formatの入れ子型・literal正規形と2回目冪等性
- 外側5操作、内側5操作、入れ子loop、保存、合流、任意・結果の内包型
- 葉型違い、一次元/二次元違い、三次元、型なし内外空literal
- 1容器、1値論理葉、構築、要素処理、表示、stackの丁度/1超過
- 共有行、空行多数、最大行、最大葉数での有限幅metrics
- 等価性、表示、trace省略、通常/trace同値
- 合成不正IRと壊れたruntime値の内部境界

本番実装から期待値を生成せず、型名、表示、予算、診断、traceを独立データとしてレビューしてから
Java実装へ進みます。

## 13. WST機能グループへの契約

WST-TABLE機能グループのCSV/TSVは次を使います。

```text
CSVを表として解析する
  (文字列 -- 結果<配列<配列<文字列>>,区切りテキスト解析失敗>)

表をCSVに変換する
  (配列<配列<文字列>> -- 文字列)
```

二次元配列自体はraggedと空行を許します。CSV/TSV解析は入力行の列数一致を検査し、直列化はraggedまたは
0セル行を専用診断で拒否します。CSV都合の矩形性を配列型の一般契約へ入れません。

WST-FILE機能グループの名前付き作業領域とファイル読書きは、二次元配列に依存せず`バイト列`までを扱います。
