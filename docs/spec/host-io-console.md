# IO-CONSOLE機能グループ: コンソール入出力と実行終了

> 本文は現行実装の規範契約です。

この文書は、IO-CONSOLE機能グループのコンソール入力、標準出力、標準エラー、入力終端、キャンセル、プログラム指定終了を定めます。CORE機能グループから存在する3個の標準出力語は互換に保ちます。

## 1. 値型と能力

`入力結果`を新しい具体型にします。値は不変で、次のいずれかです。

| 状態 | 保持内容 | 意味 |
|---|---|---|
| `行` | Unicodeスカラー値列1個 | 行終端を除いた入力行 |
| `終端` | なし | 完成した行を1つも残さず入力が終わった |
| `取消` | なし | 実行環境が現在の入力要求を取り消した |

`入力結果`は利用者定義単語のスタック効果に使用できますが、`表示可能`、`等しい`、配列要素型には含めません。BIND機能グループの初期値は副作用なしという規則を維持するため、ソース上の定数・変数を入力語で初期化することもできません。行、終端、取消を空文字列や特別な文字列で表しません。

実行環境は次の能力を独立して供給します。

| 能力名 | 用途 |
|---|---|
| `console.input` | 一行入力 |
| `console.output` | プログラム標準出力 |
| `console.error` | プログラム標準エラー |
| `process.exit` | プログラム指定終了結果の返却 |

能力の有無は`check`の成否を変えません。到達して呼び出した時点で不足していれば`E_CAPABILITY_UNAVAILABLE`です。辞書は単語ごとの能力と副作用先を決定的な順序で返します。

## 2. 一行入力

```text
一行を入力する          （-- 入力結果）
入力行である            （入力結果 -- 入力結果 真偽）
入力終端である          （入力結果 -- 入力結果 真偽）
入力キャンセルである    （入力結果 -- 入力結果 真偽）
入力行を取り出す        （入力結果 -- 文字列）
入力結果を捨てる        （入力結果 --）
```

3個の判定語は元の`入力結果`を残し、その上へ真偽値を積みます。したがって既存の`ならば`で状態を判定した後、行の取出しまたは結果の破棄ができます。`入力行を取り出す`へ終端または取消を渡すと`E_INPUT_RESULT_NOT_LINE`です。

```text
入力を処理するとは （入力結果 --）
    入力行である ならば
        入力行を取り出す を 一行表示する
    さもなければ
        入力終端である ならば
            入力結果を捨てる
            「入力終端」を 一行表示する
        さもなければ
            入力結果を捨てる
            「入力取消」を 一行表示する
        つぎに
    つぎに
こと。
```

### 2.1 行境界とUTF-8

- 実行環境の標準アダプタは厳密なUTF-8を読み、置換文字による修復をしません。
- LF、CRLF、CRを1個の行終端として受理し、返す文字列には含めません。
- 行終端だけなら空文字列の`行`です。
- 行終端前に入力が終わり、1バイト以上あれば、その内容を最後の`行`として返します。次の呼出しが`終端`です。
- 入力先頭のUTF-8 BOMを特別扱いせず、U+FEFFを通常の入力文字として保持します。
- 不正UTF-8は`E_INPUT_UTF8`、1行の値が16,777,216 UTF-8バイトを超える場合は`E_INPUT_LINE_LIMIT`です。
- 1実行で消費できる入力は、行終端を含む生バイトで67,108,864バイトです。超過は`E_INPUT_TOTAL_LIMIT`です。終端と取消は0バイトです。

入力待ち時間は30秒の能動実行時間へ数えません。待機中も命令数は増えず、入力語を表す`Call`自体は従来どおり1実行命令です。実行環境は完成した行、終端、取消、または失敗のいずれか1つを1回だけ返します。

標準ストリーム自体には移植可能な取消バイトを定義しません。埋込みホストとテスト用能力は取消を直接返せます。CLIがSIGINTを協調的に捕捉できた場合は取消へ対応できますが、OSがプロセスを先に終了した場合のシグナル終了はBSBプログラムの値ではありません。

## 3. 数値入力

数値専用の暗黙入力語は追加しません。入力行を取り出した後、TEXT機能グループの`文字列を整数に変換する`または`文字列を小数に変換する`を明示的に使います。空白除去も暗黙には行いません。構文、4,096桁上限、診断はTEXT機能グループと同じです。

```text
一行を入力する
入力行を取り出す
文字列を整数に変換する
```

## 4. 標準出力と標準エラー

既存語を維持し、対応する標準エラー語を追加します。

```text
表示する              （表示可能 --）
一行表示する          （表示可能 --）
改行する              （--）
エラー表示する        （表示可能 --）
エラー一行表示する    （表示可能 --）
エラー改行する        （--）
```

表示表現は既存の`表示可能`規則を共有します。改行は常にLFです。標準出力とプログラム標準エラーは別の64 MiB予算を持ちます。1呼出しの値とLFをまとめて事前検査し、上限超過では対象チャネルへ1バイトも委譲しません。過去に成功した出力と他方のチャネルは取り消しません。

能力境界は完全なUTF-8バイト列を1回で受け取ります。メモリ能力は成功か失敗を原子的に返さなければなりません。OSストリームが委譲後に部分書込みして失敗した物理バイトは一般には巻き戻せないため、BSBが保証する原子性は「上限・型・能力検査の完了前には委譲しない」ことと、失敗呼出しで言語スタックと保存値を変更しないことです。

プログラム標準エラーと処理系診断は実行環境内では別チャネルです。公開CLIは両方をプロセスのstderrへこの順で写します。実行時診断の直前にプログラムstderrがLFで終わっていなければ、CLIが区切りLFを1個挿入します。この区切りはプログラムstderr予算へ数えません。

## 5. プログラム指定終了

```text
終了する （整数 -- ⊥）
```

`終了する`は整数を1個消費し、プログラム全体を直ちに正常な制御移行として終了します。`⊥`は「通常出口がない」ことを表す仕様上の記号で、型名ではありません。0から255までを受理し、範囲外は`E_EXIT_CODE_RANGE`です。

- 0も明示的な正常終了として許可します。
- 1〜255はアプリケーションが選んだ終了コードで、処理系診断ではありません。
- 先に成功したstdoutとプログラムstderrは保持します。
- 終了地点のデータスタックに他の値があっても、終了後に利用されないため`メイン`残留値診断にしません。
- 到達可能な通常出口だけが宣言スタック効果と一致する必要があります。`終了する`後の同一連続範囲は既存の`W_UNREACHABLE_CODE`です。
- `check`と`format`はプログラムを実行しないため、指定終了コードを返しません。

公開CLIの`run`は指定値をプロセス終了コードとして返します。0〜255には処理系の既存コードと同じ数値も含まれ得るため、数値だけで終了原因を判別する外部契約は設けません。埋込みAPIは`completed`、`programExit`、`diagnosticFailure`を区別します。

## 6. 原子性と順序

1個の入出力または終了語について、能力確認、入力型・値域、資源上限を検査してから、外部能力へ1回だけ委譲し、成功後に入力スタックを確定変更します。入力は外部から行を受け取るため、失敗までに物理入力が消費される場合がありますが、部分的な`入力結果`は作りません。

通常実行とトレース実行で、能力呼出し回数と順序、入力結果、両出力、終了種別、終了コード、言語状態、既存予算が一致しなければなりません。

## 7. 対象外

端末制御、キー単位入力、エコー制御、パスワード入力、バイナリ入出力、パイプ判定、ファイル、ネットワーク、シグナル処理、任意の文字エンコーディングは8Aに含めません。
