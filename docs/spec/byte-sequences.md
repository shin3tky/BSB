# BYTES機能グループ: 不変`バイト列`とUTF-8・Base64変換

> 本文は現行実装の規範契約です。
>
> ここで明示する追加以外は、先行する実装済み機能グループの契約を維持します。
> [診断と資源境界](byte-sequences-diagnostics.md)および[適合性](byte-sequences-conformance.md)と一体です。

## 1. 目的と機能境界

HTTP要求・応答の本文を、Unicode文字列、JSON、`配列<整数>`のいずれとも混同しない不変な
`バイト列`値として保持します。任意の0〜255の並びを損失なく保持し、UTF-8とBase64へ変換する時だけ
文字列との境界を越えます。

この機能グループでは、HTTP、ファイル、乱数、圧縮、暗号、ハッシュ、文字コード自動判定、UTF-16・Shift_JIS等の
変換を追加しません。バイト列リテラル、バイト単位の整数取出し、置換、連結、追記、反復も追加しません。
固定バイナリは規範Base64文字列から復号でき、後続HTTPはホストから受け取った本文を同じ値型へ載せます。

## 2. 値と型

`バイト列`は、長さ`N`と0始まり位置`0`から`N - 1`までのバイト値で定まる、null非許容の不変な
組み込み具体型です。各要素は符号なし8ビット値0〜255ですが、要素をBSBの`整数`として公開しません。
Javaの符号付き`byte`、配列参照、`ByteBuffer`の可変位置、容量、バッキング領域は公開意味論に含めません。

値の生成後に内容は変わりません。一部取得は元値を変更せず、新しい論理値を返します。実装はこの意味を
守る限り、同じ不変ストレージの半開区間を共有できます。公開・埋込み境界で可変`byte[]`を受け渡す場合は、
入力時または境界内で防御コピーし、取得APIから内部配列を返しません。

`バイト列`は定数、変数、大域・局所保存、利用者定義語の入出力、分岐・ループの合流、
`任意<バイト列>`、`結果<バイト列,E>`、`結果<T,バイト列>`に使えます。型構築子の深さは既存256上限です。
一方、`配列<バイト列>`は既存の配列要素制約により`E_ARRAY_ELEMENT_TYPE_NOT_ALLOWED`です。
`配列<整数>`との暗黙変換、構造的同一視、共変関係はありません。

## 3. 公開語

既存125語の後ろへ次の11語を表の順で追加し、辞書は136語になります。すべて純粋で、能力・副作用は空、
`featureGroup="BYTES"`、`returnsNormally=true`です。新しい構文はありません。

| 正規語 | スタック効果 | 意味 |
|---|---|---|
| `空のバイト列` | `-- バイト列` | 長さ0の値 |
| `バイト列の長さ` | `バイト列 -- 整数` | バイト数 |
| `バイト列の一部を取り出す` | `バイト列 整数 整数 -- バイト列` | バイト半開区間 |
| `文字列をUTF8バイト列に変換する` | `文字列 -- バイト列` | BOMなしUTF-8符号化 |
| `バイト列をUTF8文字列に変換して結果を返す` | `バイト列 -- 結果<文字列,UTF8復号失敗>` | 厳密UTF-8復号 |
| `UTF8復号失敗の種類を取り出す` | `UTF8復号失敗 -- 文字列` | 安定ASCII種類 |
| `UTF8復号失敗のバイト位置を取り出す` | `UTF8復号失敗 -- 整数` | 0始まり位置 |
| `バイト列をBase64文字列に変換する` | `バイト列 -- 文字列` | 規範Base64符号化 |
| `Base64文字列をバイト列に変換して結果を返す` | `文字列 -- 結果<バイト列,Base64復号失敗>` | 厳密Base64復号 |
| `Base64復号失敗の種類を取り出す` | `Base64復号失敗 -- 文字列` | 安定ASCII種類 |
| `Base64復号失敗の文字位置を取り出す` | `Base64復号失敗 -- 整数` | 0始まりUnicodeスカラー位置 |

`空のバイト列`は組み込み値で、毎回同じ論理値です。共有の有無は観測できません。変換語の名前に現れる
`UTF8`と`Base64`はASCII表記を含む正規語名です。ソース語にハイフンを含む`UTF-8`別名、大小文字違い、
日本語別名は追加しません。`format`は既存の名前正規化だけを適用し、正規語名を出力します。

## 4. 長さ、一部取得、等価性

`バイト列の長さ`は0以上67,108,864以下のバイト数を`整数`で返します。

`バイト列の一部を取り出す`の入力順は値、開始、終了です。長さ`N`に対して
`0 <= 開始 <= 終了 <= N`を受理し、開始を含み終了を含まない`[開始, 終了)`を返します。
`[N,N)`は空、`[0,N)`は元と等しい値です。範囲外は`E_BYTE_SEQUENCE_RANGE_OUT_OF_BOUNDS`です。
成功結果が元ストレージを共有するか、空値・全体値を同一インスタンスとして返すかは観測できません。

`バイト列`を既存`等しい`の等値比較可能型へ追加します。同じ長さで、全位置の符号なしバイト値が同じ場合
だけ`はい`です。異なる長さは内容を比較せず`いいえ`です。Java配列同一性、ハッシュ値、Base64表現、
UTF-8としての文字列比較は使いません。`任意`・`結果`内の比較可能性は既存どおり全型引数から導きます。

## 5. UTF-8変換

### 5.1 文字列からバイト列

`文字列をUTF8バイト列に変換する`はBSB文字列のUnicodeスカラー値列をRFC 3629の最短UTF-8へ符号化します。
BOMを付加せず、U+FEFFが文字列値に含まれる場合だけ`EF BB BF`を通常の内容として出力します。
Unicode正規化、改行変換、終端NULの追加は行いません。BSB文字列は孤立サロゲートを保持しないため、
入力データ不正による失敗結果はありません。

### 5.2 バイト列から文字列

`バイト列をUTF8文字列に変換して結果を返す`は、ASCIIと2〜4バイトの最短形式だけを受理し、
U+D800〜U+DFFFとU+10FFFF超を拒否します。BOMは除去せずU+FEFFへ復号します。NUL、CR、LF、
非文字コードポイント、結合文字は有効なUnicodeスカラー値として保持し、正規化しません。

完全に有効なら`成功(文字列)`、最初の不正があれば`失敗(UTF8復号失敗)`を返します。置換文字U+FFFDで
修復せず、接頭辞だけを返しません。失敗値の種類と位置は次の順で決めます。

| 種類 | 条件 | 公開バイト位置 |
|---|---|---:|
| `invalidLeadingByte` | 先頭候補が`80`〜`BF`、`C0`〜`C1`、`ARRAY-F`〜`FF` | そのバイト |
| `invalidContinuationByte` | 有効な先頭の後、必要位置に`80`〜`BF`以外がある | その非継続バイト |
| `truncatedSequence` | 必要な継続位置が入力末尾を越える | シーケンス先頭 |
| `overlongEncoding` | 完成列がそのコードポイントの最短形式でない | シーケンス先頭 |
| `surrogateCodePoint` | 完成列がU+D800〜U+DFFFになる | シーケンス先頭 |
| `codePointOutOfRange` | 完成列がU+10FFFFを超える | シーケンス先頭 |

入力を左から走査し、有効な先頭の後は必要な継続位置を順に検査します。位置が入力内にあって非継続なら
`invalidContinuationByte`、入力外なら`truncatedSequence`です。必要数が揃ってから最短形式、サロゲート、
最大値を表順に判定します。これにより同じバイト列の種類と位置は実装APIに依存しません。

## 6. Base64変換

### 6.1 規範符号化

`バイト列をBase64文字列に変換する`はRFC 4648の基本Base64 alphabet
`A-Z a-z 0-9 + /`を使います。出力は改行・空白なしで、末尾量子が1バイトなら`==`、2バイトなら`=`を
必ず付けます。空バイト列は空文字列、3の倍数長ではpaddingなしです。URL-safe alphabet、MIME改行、
実装固有の別alphabetを出力しません。

出力長は入力長`N`に対して`N = 0`なら0、それ以外は`4 * ceil(N / 3)`です。文字列上限
16,777,216 UTF-8バイトを超える場合は、候補文字列を構築せず既存`E_STRING_UTF8_LIMIT`です。

### 6.2 厳密復号

`Base64文字列をバイト列に変換して結果を返す`は上記の規範形だけを受理します。空文字列は成功です。
空白、改行、全角文字、URL-safeの`-`・`_`、alphabet外文字、padding省略、途中padding、3個以上のpadding、
padding後のalphabet、非0の未使用pad bitを許しません。入力を除去・修復・正規化しません。

完全に有効なら`成功(バイト列)`、不正なら`失敗(Base64復号失敗)`を返します。失敗判定順は次です。

1. 左から最初の、基本alphabetにも`=`にも属さないUnicodeスカラー値を`invalidCharacter`とする。
2. Unicodeスカラー数が4の倍数でなければ`invalidLength`とし、位置は入力長、すなわちEOFとする。
3. `=`がない、末尾1個だけ、末尾2個だけ、の3形以外は`invalidPadding`とし、最初に形を壊す位置とする。
4. `xx==`の第2 sextetの下位4 bit、または`xxx=`の第3 sextetの下位2 bitが0でなければ
   `nonZeroPadBits`とし、そのsextetの文字位置とする。

手順3で受理する構造は、`A`を基本alphabetの1文字として、次の文法だけです。

```text
base64 := (A A A A)* ((A A "==") | (A A A "="))?
```

長さ検査後、この文法の同じ全長の語になり得ないことが初めて確定する最小の文字位置を
`invalidPadding`の位置にします。たとえば`=AAA`は0、`AA=A`は3、`A===`は1です。
`nonZeroPadBits`はこの構造検査に成功したpadding付き末尾量子だけを対象にします。

種類は`invalidCharacter`、`invalidLength`、`invalidPadding`、`nonZeroPadBits`の4値です。
文字位置は入力先頭から0始まりのUnicodeスカラー値位置で、JVMのUTF-16位置ではありません。
規範alphabet自体はASCIIなので、非ASCII入力は必ず`invalidCharacter`になります。

## 7. 失敗型

`UTF8復号失敗`と`Base64復号失敗`はnull非許容、不変、利用者構築不能の閉じた組み込み具体型です。
各値は第5・6節の安定種類と位置だけを保持します。元入力、入力の一部、復号済み接頭辞、期待バイト、
Java例外、自由文メッセージは保持しません。

両型は保存、合流、`任意`・`結果`の型引数に使えますが、表示、等値比較、配列要素には使えません。
観測は専用2語だけです。取出し語は入力失敗値を消費して1値へ置換し、再復号や専用予算消費をしません。

復号不正は外部データ由来の回復可能な失敗です。一方、型・スタック違い、サイズ・累積予算超過、
命令・実行時間上限、壊れた内部値は結果へ変換しません。詳細は診断仕様に従います。

## 8. 表示と非開示

`バイト列`は表示可能型に追加しません。stdout/stderrへ出すには、UTF-8復号の成功文字列またはBase64文字列へ
明示変換します。`バイト列`を含む`任意`・`結果`も、非選択側を含む型全体が表示不能です。

標準トレースは内容、長さ、接頭辞、ハッシュ、UTF-8妥当性にかかわらず常に次の形で伏せます。

```text
バイト列:<redacted>
UTF8復号失敗:<redacted>
Base64復号失敗:<redacted>
```

`任意`・`結果`に入れ子の場合も状態を含む外側全体を推移的に伏せます。失敗診断の共通`dataStack`、
Javaの`toString`、能力イベント、安全表現からも内容と長さを出しません。専用語で取り出した種類文字列・
位置整数と、明示変換後の文字列は通常の値であり、その後は既存の文字列・整数非開示方針に従います。

## 9. 資源

| 資源 | 上限 | 単位 |
|---|---:|---|
| 1個の`バイト列` | 67,108,864 | 論理バイト |
| 1実行のバイト列構築 | 134,217,728 | 新たに所有する論理バイト |
| 1実行のバイト列作業 | 268,435,456 | 走査・符号化・復号で処理するバイト |

一部取得は不変ストレージ共有を規範上許すため構築0、O(1)操作として作業1です。空値は両方0、長さは
作業1です。UTF-8符号化は出力バイト数を構築・作業へ、UTF-8復号は入力バイト数を作業へ数えます。
Base64符号化は入力バイト数と出力ASCIIバイト数の和を作業へ数えます。Base64復号は入力UTF-8バイト数を
最初の走査作業とし、成功時だけ復号結果バイト数を構築・追加作業へ数えます。

バイト列等価比較は長さ不一致なら作業0、同長なら左から実際に比較する各位置を作業1とします。同一実体を
比較しても規範上は全位置を数えます。`任意`・`結果`の状態不一致等、バイト列へ到達しない短絡は0です。
トレースの伏字化と失敗値の取出しはバイト列作業へ数えません。

構築・作業を同時に始める操作は、両方を受理できる場合だけ原子的に予約します。復号のように入力検査後だけ
結果長が確定する操作では、入力走査作業を先に予約し、成功形を確認後に結果構築と追加作業を原子的に予約します。
後半の予約失敗は先行走査作業を戻しません。1値上限と文字列結果上限は大きな候補配列・文字列を作る前に
有限幅で計算します。最大ヒープ512 MiBの全回帰条件を維持します。

## 10. 原子性と公開互換性

成功する変換と一部取得は、全検査と必要予約後に入力値を出力値へ1回で置き換えます。回復可能な復号不正も
正常終了であり、入力1値を失敗結果1値へ置き換えます。中間配列、接頭辞、空スタックは観測できません。

捕捉不能診断では入力スタック、保存値、プログラムstdout/stderr、能力イベントを変更しません。
先に受理した命令課金と入力走査作業だけは戻しません。拒否された構築・作業予約は累積値を変更しません。

`check --json`と`explain --json`は外側`schemaVersion=1`を維持します。成功説明の既存125語の後ろへ
11語を追加し、新しい3型名と固定効果を既存項目で表します。能力・副作用・
`parameterizedCapabilities`は変わりません。新しい公開JSONメンバーや構文は追加しません。

## 11. この機能グループに含めないもの

- HTTP要求・応答、論理接続の再解決、DNS、TLS、認証
- バイト列リテラル、16進文字列変換、バイト整数取出し、置換、連結、追記、反復
- `配列<整数>`・`配列<バイト列>`との変換、暗黙の文字列・JSON変換
- Base64 URL-safe・MIME・無padding入力、寛容な空白除去
- UTF-8以外の文字コード、BOM自動除去、文字コード推測、Unicode正規化
- ハッシュ、暗号、圧縮、ストリーミング、可変バッファ、ゼロコピーを保証する公開API
- 復号失敗の汎用エラー化、診断捕捉、自動伝播

この機能グループの完了後、最小HTTPSは応答本文を同じ`バイト列`で損失なく返し、Content-Type等を確認した
利用者コードだけがUTF-8またはJSONへ進めるようにします。
