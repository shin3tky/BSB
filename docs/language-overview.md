# 最小言語仕様の概説

この文書は、現在の Java 実装と適合性テストが提供する BSB 言語の範囲を概説します。
将来案ではなく、現在検査・整形・実行できる内容だけを対象にします。

## 言語モデル

BSB は静的型付きのスタック言語です。リテラルや単語呼出しは値をデータスタックへ積み、または
スタックから取り出します。単語定義は入力と出力をスタック効果として宣言し、処理系はすべての
到達可能な制御経路で型とスタック形状が一致することを実行前に検査します。

```text
二倍 とは （整数 -- 整数）
    2を 掛ける
こと。

メイン とは （ -- ）
    21を 二倍 一行表示する
こと。
```

文は空白で区切り、定義は `こと。` で閉じます。`#` から行末まではコメントです。助詞 `を`、`に`、
`と`、`から`、`で` は読みやすさのために置けますが、値そのものではありません。処理系は不自然な
位置の助詞を警告します。

ソースは UTF-8 とし、先頭の BOM は1個だけ受理して読み飛ばします。識別子は Unicode 正規化と紛らわしい文字の検査を受けます。
文字列は `「…」` または `"…"`、文字は `'…'`、配列は `【…】`、正規表現は `正規表現「…」` で表します。
整数と小数は符号付き十進表記を使い、小数では指数表記も利用できます。フォーマッタは意味を変えず、
空白・引用符・区切りを標準形へ整えます。本書では `format` の整形結果を「標準形」、regular expression を
「正規表現」と呼び分けます。

## 型

### 基本値

- `整数`: 任意精度の符号付き整数
- `小数`: 二進浮動小数へ変換しない正確な十進小数
- `真偽`: `はい` または `いいえ`
- `文字`: Unicode の拡張書記素クラスタ1個
- `文字列`: Unicode スカラー値列。利用者向けの長さは拡張書記素クラスタ数
- `丸め方法`: 最近接偶数、四捨五入、0方向、正方向、負方向
- `正規表現`: RE2 系の線形時間モデルでコンパイルされる正規表現
- `入力結果`: 一行入力の行、終端、取消を区別する値
- `日時`: エポックミリ秒と取得時 UTC オフセットを持つ値

### 構造化値

- `配列<T>`: 同じ葉型を持つ不変配列。一次元と二次元を利用可能
- `JSON`: null、真偽、整数、小数、文字列、配列、オブジェクトを内包する不変値
- `任意<T>`: 値あり `ある(T)` と値なし `ない` を区別する値
- `結果<T,E>`: 成功 `成功(T)` と失敗 `失敗(E)` を区別する値
- `バイト列`: 0〜255 の不変な列。文字列や整数配列とは別型
- `HTTP要求`、`HTTP応答`: ホスト能力を通して送受信する不変値
- `JSON形状`: JSONの種類と入れ子構造を表す不変値

回復可能失敗の型として、`JSON解析失敗`、`UTF8復号失敗`、`Base64復号失敗`、`HTTP送信失敗`、
`ファイル読取失敗`、`ファイル書込失敗`、`区切りテキスト解析失敗`、`JSON形状失敗`を提供します。各失敗値が公開するのは
種類や位置など仕様で定めた情報だけで、秘密、OS パス、内部例外は含みません。

## 単語、名前、保存領域

すべてのプログラムは入力・出力なしの `メイン` を入口にします。利用者定義語は前方参照と再帰呼出しができ、
同一名、予約名、未定義名、呼出し不能名を静的に拒否します。名前は字面と正規化後の同一性を区別して診断します。

`定数` と `変数` は大域または語本体の字句スコープへ置けます。定数は一度だけ初期化し、変数への代入は
宣言型と一致する必要があります。分岐・反復の局所スコープ、初期化順序、到達不能コード、戻り後の状態も
静的に検査します。

## 制御構文

- `ならば … さもなければ … つぎに`: 真偽条件による分岐
- `または … つぎに`、`かつ … つぎに`: 右辺ブロックを必要な場合だけ評価する短絡論理
- `回だけ … 繰り返す`: 非負回数の反復
- `ここから … 続く間 … 繰り返す`: 条件付き反復
- `各要素について … 繰り返す`: 配列要素の順次処理。二次元配列では入れ子にできる
- `打ち切る`、`続ける`、`戻る`: 対応する制御構造からの移行

分岐の合流点と反復の各境界ではスタック形状が一致しなければなりません。構文と型構築子の入れ子には
有限の深さ上限があります。

## 数値、文字列、配列

整数は加減乗算、比較、絶対値、最小・最大、床除算の商と剰余を提供します。小数は正確な加減乗算、
既定精度または精度・丸め方法を指定する除算、整数との明示変換を提供します。リテラルと文字列変換では
`1e3`、`1.25E-2`、`1e+2` の形を扱います。桁数、精度、スケールは構築前に上限検査されます。

文字列操作には、連結、比較、空白除去、長さ、取出し、slice、検索、置換、分割、反復、数値変換、
Unicode 16.0に固定したロケール非依存の完全大小文字変換と大小文字無視比較があります。書記素位置と
コードポイント位置を使う操作は明示的に分かれています。
正規表現は完全一致、部分一致、最初の一致、名前付き部分、置換、分割を提供し、パターン・入力・一致回数・
作業量を制限します。

配列は長さ、添字取出し、半開区間 slice、要素置換、末尾追加を不変操作として提供します。二次元配列は
ragged な行を保持でき、構造的等価性、決定的表示、二重反復に対応します。配列要素にできる葉型と次元は
制限されています。

## JSON、任意値、結果値

JSON は文字列全体を厳密に解析し、決定的なコンパクト JSON へ直列化します。数値は整数または正確な小数で
保持し、重複キーや文法不正を拒否します。型判定、スカラー変換、配列操作、オブジェクトのキー列挙・取得・
設定・削除を提供します。BSB ソースへ JSON リテラルを直接書く構文はありません。

入れ子値はRFC 6901 JSON Pointerで`任意<JSON>`として参照でき、オブジェクトはキー配列とJSON値配列から
順序を保って一括構築できます。JSONPathや動的な式評価は行いません。

キーが存在しない場合は `任意<JSON>` の `ない`、キーがあり値が JSON null の場合は `ある(JSONヌル)` です。
`結果<T,E>` は明示的な成功・失敗を通常値として保持します。JSON の回復可能解析は文法不正と重複キーを
`結果<JSON,JSON解析失敗>` にしますが、深さ・件数・入力サイズなどの資源超過は診断終了のままです。

外部JSONの構造検証には、葉、配列、object、nullableを組み合わせた第一級の`JSON形状`を使います。
`JSONの形状を検証する`は成功時に元のJSON、失敗時にJSON Pointer pathと閉じた種類情報だけを持つ
`配列<JSON形状失敗>`を返します。任意memberの欠落は許しますが、null許容とは区別します。

## バイト列と外部データ

文字列とバイト列の間は厳密 UTF-8 で変換し、Base64 は規範形だけを受理します。復号失敗は結果値で返し、
位置と閉じた失敗種類を取得できます。バイト列には長さ、slice、等値比較があり、通常の表示や trace では
内容を直接公開しません。

CSV/TSV は固定区切り、厳密な引用符、CR/LF/CRLF 入力、先頭 BOM 除去、BOM なし CRLF 出力を扱います。
解析結果は `配列<配列<文字列>>` です。文法失敗は回復可能失敗にし、行列数、セル数、入力、出力、作業量の
上限は診断として扱います。

## ホスト能力

コンソール入力・出力・標準エラー、指定終了、起動引数、プログラム名と場所、待機、単調時間、現在日時は、
差し替え可能な実行環境能力です。処理系を埋め込むホストは必要な能力だけを提供できます。

論理接続と作業領域はソース中で静的に宣言します。BSB 値へ URI、認証情報、OS パスを渡さず、論理名を
ホスト側の有限な設定へ解決します。標準 CLI は設定を暗黙探索せず、明示した TOML または `--file` 登録だけを
使用します。

HTTPS は GET、POST、PUT、PATCH、DELETE、HEAD の同期要求、規定ヘッダー、完全本文、status、応答ヘッダーを
扱います。接続設定版2では、最大8回の有限再試行、決定的backoff、`Retry-After`、接続単位の開始間隔を
ホスト方針として指定できます。変更系methodの複数送信には冪等性キーまたはAPI保証が必要です。
redirect、圧縮、streaming、非同期処理は含みません。通常の適合性テストは偽能力を使用し、実ネットワークへ
接続しません。

## CLI と診断

CLI は `check`、`run`、`format`、`explain --json` を提供します。`check --json` と `explain --json` は
BOM なし UTF-8 の1行 JSON を標準出力へ書き、正常に JSON を生成した場合は標準エラーを空にします。
成功、使用法、I/O、静的検査、字句・構文、内部失敗は異なる終了コードです。

診断は安定したコード、severity、処理フェーズ、ソース位置、構造化 field、expected/actual、関連位置、修正案、
資源上限を持ちます。`explain --json` は全組み込み語とその機能グループ、利用者語、スタック効果、スコープ、
束縛、到達性、能力、副作用、論理接続・作業領域の要求を返します。

## 資源と決定性

ソース、トークン、構文深さ、スタック、命令、文字列、数値、配列、JSON、正規表現、バイト列、HTTP、ファイル、
CSV/TSV、出力、実行時間には有限の上限があります。上限超過時は部分値や部分出力を公開しないことを原則とし、
外部書込みなど取り消せない操作の境界は個別契約で明示します。表示、整形、JSON直列化、静的説明、trace は
同じ入力と環境に対して決定的です。

## 非対応範囲

- 利用者定義型、利用者定義ジェネリック型、三次元以上または異種・可変の配列
- `任意`・`結果`を要素とする配列、単独の `ない` 構築、結果値の自動伝播、汎用診断捕捉
- ロケールを指定する大小文字変換、正規等価性を暗黙に含む比較、Unicode大小文字無視の正規表現
- 後方参照、先読み、後読み、再帰を含む正規表現
- JSON リテラル、JSONPath、JSON Schema文書の解釈
- 環境変数、外部コマンド、ディレクトリ列挙、任意 OS パス操作
- Basic/OAuth 認証、redirect、jitter、回路遮断、圧縮、streaming、非同期 HTTP
- 動的な接続・作業領域名、接続設定の自動探索やマージ、SQL クライアント
