# 局所単語

## 状態

検討保留。現在の BSB には導入しません。この文書は将来の設計開始点を残す非規範ノートであり、
構文、予約語、診断コード、整形結果、IR、実行動作、公開 JSON 契約を追加または変更しません。

## 想定する目的

大域の利用者定義単語へ切り出すほどではない小さな補助処理を、親となる単語の内部だけで定義できるように
することを想定します。将来導入する場合に最低限検討する性質は次です。

- 局所単語は、その定義を含む字句スコープからだけ呼び出せる
- 局所単語は、可視な親スコープの局所定数・変数を参照できる
- 親の局所変数への代入を許す場合、親の同じ呼出しフレームへ反映する
- 親単語の再帰呼出しごとに、捕捉する局所保存領域を分離する
- 同名の親単語が再帰中でも、動的な呼出元ではなく字句上の定義元を参照する

これは Mind の「局所処理単語」に着想を得られますが、Mind ソース互換性を目的にはしません。
構文、スタック効果、制約、診断は BSB の既存原則から独立に決定します。

## 現行仕様との境界

現在の BSB では、利用者定義単語はすべてトップレベルです。単語本体や制御ブロックの局所スコープには
定数・変数だけを宣言できます。内側の制御ブロックから外側の局所値は参照できますが、別の利用者定義単語は
呼出し元の局所保存領域へアクセスできません。

当面は補助処理をトップレベル単語として定義し、必要な値をデータスタックの入力・出力として明示的に
渡します。この代替は局所単語の隠蔽と捕捉を提供しません。

## 将来の意味論で決めること

導入を決定する前に、少なくとも次を規範仕様として確定する必要があります。

### 定義を置ける場所

- 単語本体の直下だけか、条件分岐・反復を含む任意の字句スコープか
- 局所単語の内部へさらに局所単語を定義できるか
- 宣言位置より前から呼べるか
- 親、自己、兄弟の局所単語を相互に呼び出せるか

実行経路によって単語の存在が変わる設計を避けるなら、局所単語定義は実行要素ではなく静的宣言として
扱う必要があります。

### 名前と可視性

- 局所値と局所単語が同じ名前空間を共有するか
- 現行の隠蔽禁止を局所単語にも適用するか
- 大域単語、組み込み単語、外側の局所単語との衝突をどう診断するか
- `explain --json` で局所単語をどの安定識別子と所有関係で表すか

表示名だけを内部識別子にすると、異なる親にある同名の局所単語を区別できません。IR と説明モデルでは
ソース上の表示名とは別の静的な単語 ID が必要です。

### スタック効果と捕捉

- 局所単語にも明示的なスタック効果を必須とするか
- 捕捉した値をスタック効果や副作用の説明へどう表すか
- 局所定数は値として、局所変数は同じ保存場所として共有するか
- 捕捉した変数の読取り・書込みを能力・副作用解析でどう示すか

局所値の捕捉を、暗黙のスタック入力へ読み替えてはなりません。呼出し時のデータスタック効果と、字句環境から
参照する保存領域は別の契約として検査・説明する必要があります。

### 寿命と呼出し

- 局所単語を第一級値にはせず、定義元の呼出し中だけ直接呼び出せる機能に限定するか
- 局所単語を値として返す場合、親フレーム終了後の捕捉値をどのように保持するか
- 呼出スタック上限へ親・局所単語のフレームを同じ1フレームとして数えるか
- 到達可能性、再帰判定、能力・副作用の推移閉包へ局所単語をどう含めるか

第一段階を非脱出の局所単語に限定すれば、一般的なヒープクロージャは不要です。局所単語の呼出しフレームから
字句上の親フレームへ静的リンクを持たせる方式を候補にできます。ただし、兄弟局所単語を経由する呼出しでも、
動的な呼出元ではなく正しい親フレームを選ぶ必要があります。

## 実装境界

将来の実装は次の層を横断します。一層だけを先行変更して、現在使われない汎用クロージャ機構を維持しません。

1. `frontend`: ネストした定義の字句解析、構文木、回復、構文深さ上限
2. `binding` / `analyzer`: 局所単語の字句スコープ、捕捉集合、呼出し解決、型・スタック効果検査
3. `explain`: 所有関係、可視性、捕捉、呼出しグラフ、能力・副作用
4. `format`: 定義位置と本体を区別した決定的な字下げ・終端表記
5. `ir`: 表示名と独立した単語 ID、捕捉先または静的リンクの情報
6. `runtime`: 呼出しごとの局所領域、字句上の親フレーム参照、再帰時の分離
7. `diagnostics` / `cli`: スコープ外呼出し、捕捉不正、資源上限、公開 JSON
8. 適合性テスト: 正常系、失敗系、上限、再帰、兄弟呼出し、同名局所単語、trace・説明の非漏えい

現在の `LoadLocal`、`StoreLocal` は実行中の単語フレームだけを対象にし、利用者単語の呼出しは独立した
局所保存領域を作ります。将来は、外側の局所スロットを示す字句深さを命令へ持たせる方法と、捕捉した保存場所を
子フレームへ明示的に渡す方法を比較します。どちらの場合も、実行時の名前検索は導入しません。

## 導入判断時の完了条件

実装開始前に次をそろえます。

- 構文、可視性、捕捉、再帰、兄弟呼出し、寿命の規範仕様
- 新しい診断コードと診断優先順位
- 標準整形と、二度整形して不変になる適合例
- 機能グループ ID と N/F/R 適合性ケース
- `explain --json` と trace の公開契約への影響
- 定義数、構文深さ、局所束縛数、呼出スタック、IR 命令数の数え方
- 捕捉した値を診断・説明・traceへ不用意に複写しないことの検査

これらを決めるまでは、局所単語用の予約語、構文トークン、診断コード、公開 JSON フィールドを予約しません。
